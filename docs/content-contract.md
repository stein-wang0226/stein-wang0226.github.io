# 内容、HTML 与资源协议

协议版本：1。与 `scripts/catalog.py` 的 v1 登记契约配套。
代码定义可执行规则，本文定义写作、保留和管理规则。

## 1. 登记与正文

| 字段 | 含义与规则 |
| --- | --- |
| `id` | 稳定的小写 slug，不随标题修订改变 |
| `source` | 仓库内权威正文；外部入口为 `null` |
| `url` | 公开地址，与源目录分离 |
| `kind` | `post / series / chapter / external` |
| `topic`、`type` | 取 `site.json` 的已定义值 |
| `tags` | 补充检索词，去重，不作为第二套分类 |
| `summary` | 描述实际覆盖与读者所得，不写模板占位 |
| `status` | `draft / published / archived` |
| `review_status` | `unreviewed / needs-review / reviewed`，与发布状态独立 |
| `updated` | 有依据的实质内容日期；未知为 `null` |
| `updated_source` | 自动追踪文从指定正文元素提取日期，不再手写第二份 |
| `series`、`order` | 子章的真实父系列与唯一正整数顺序 |
| `featured` | 是否在当前推荐入口呈现 |
| `related` | 有效且不重复的其他内容 ID，不自引用 |

正文需要迁移、拆分或改名时先列受影响的公开 URL、锚点和引用，再修改登记。
旧地址进入 `redirects.json`，默认保留查询参数和片段，避免多级跳转链。
HTML 锚点变更不能只靠 URL 跳转弥补，应保留旧锚点或证明已有引用得到更新。

## 2. 新增内容的最小完整度

普通文章使用 `make new` 创建草稿，系列使用入口和显式章节登记。
发布前移除 `TEMPLATE:EMPTY`，补齐以下与主题有关的内容：

1. 要解决的问题、读者先修和可得到的结论。
2. 核心机制或完整流程，解释关键术语和边界。
3. 一个能连接输入、中间状态与输出的具体例子。
4. 公式、伪代码或实现入口，只保留帮助理解的部分。
5. 数据/评测/成本口径，以及失败模式和不确定性。
6. 对应的原始来源、版本和进一步阅读。

不是每篇文章都需要六个机械小标题。实测、复现、方案和推断要分别标注，
没有执行的实验不能写成验证结果。题库缺答案就保留缺口，不用模板答案假装完稿。

## 3. Markdown 与 HTML

| 情况 | 建议 |
| --- | --- |
| 普通说明、指南、简短公式 | Markdown + 现有模板和阅读装配 |
| 密集科研图、复杂交互、现有完整文章 | HTML，保留有效原结构 |
| 同系列共用视觉/交互 | 系列自己的 CSS/JS，登记或确认现有复制规则 |
| 全站导航、页脚、目录 | 共享 renderer，不在每篇正文手写副本 |

Markdown front matter 与 catalog 中重复的标题等字段保持一致；
分类、关联和公开路径以登记为准。构建不从正文位置猜章节顺序。

完整 HTML 保留合法文档结构、语言、viewport、唯一 ID、可读标题和有效链接。
科研正文不得批量正则重写所有标签；局部改动核对邻接 DOM、公式和原交互。
原有导航兼容由 `reading.py` 装配处理，编辑时不手写生成的站点导航块。

静态资源按公开 URL 计算引用，使用现有 `ctx.rel` / `route_path`；
不能按 `content/` 源目录推导浏览器的相对地址。
原始正文 HTML 是源，外部 output 中经过装配的同名 HTML 才是产物，两者不可互换。

## 4. 原始报告、图表、数据与许可

| 资源 | 放置与管理 |
| --- | --- |
| 原始论文/PDF/官方报告 | `assets/research/<topic-or-date>/`，保留原始字节 |
| 图表、数值数据、生成说明 | 与专题相关的研究目录；保留 CSV/JSON 和口径 |
| 外部仓库源码参考 | 临时 checkout 在仓库外；只归档必要原件/摘录及许可 |
| 原始用户材料 | 按任务保留；可公开的资源才登记为公开 assets |
| 历史正文与 PDF | `content/archive/`、`assets/archive/`，保留既有兼容 |
| 字体和站点 CSS/JS | `assets/site/`，保留上游许可 |

引用至少记录题目、作者/组织、原始 URL、版本或 commit、章节/位置和事实口径。
原始报告归档记录长度、SHA-256、来源和许可；不把下载日当论文版本。
`sources.json` 与 `site.json` 职责不同：前者描述来源，后者决定资源公开路由。
当前研究报告的 `sources.json` 为对象，记录在 `sources` 列表下；
读取真实 schema，不把整个文件当作顶层列表。

资源发布必须匹配现有构建路径：

- `assets/site/` 中允许的 CSS、JS、字体由共享复制规则纳入。
- 普通 `post` 目录下允许的局部媒体由文章资源复制规则纳入。
- 系列与其他研究资源一般在 `site.json.assets` 明确登记。
- 只有下载链接或在正文出现文件名，不代表资源已进入公开产物。

不整仓库复制外部项目、不提交运行缓存、大模型权重、环境或下载中间产物。
引入大资源先报告体积、是否必要公开、许可和替代链接；
不要为达到体积阈值擅自重压原始 PDF 或删除内容。

图表轴、单位、分母、版本、误差范围和适用条件完整。
例如模型缓存比较需区分报告值与规格推导，明确是否包含 SWA、权重和临时显存。
评测需区分任务数量、成功率、pass@k、预算、环境和评测方版本。

## 5. 正文保留和事实审阅

`docs/content-migration-manifest.json` 是不可重建的迁移基线。
`docs/content-changes.json` 记录已核对的有意变化及当前 SHA。
修改基线覆盖文件时记录改前状态，核对实际正文差异，只更新本次受影响记录。
不要批量刷新 SHA 去消除检查错误。

`review_status` 的证据应能定位到该文的来源/验收记录。只检查格式与链接时，
不能声称论文事实已经复核。`reviewed` 也不等于每个实验都在本地复现。

履历、项目交付、作者顺序和会议接收状态来自作者材料或公开一手来源。
Project delivery、审阅轮次、代码公开和 benchmark 接收是不同事实。
精选展示应写具体方法与有依据的结果；单纯 fork、复制仓库或练习记录不作为研究成果。

## 6. 生命周期和验收

内容允许先草稿、后公开、再维护或归档；状态变化不是授权远端发布。
在归档或替换前查旧入口、资源、反向引用和读者路径，不把辅助资料默认视为冗余。

```bash
make governance       # 本地管理契约、skill 引用和 Profile 本地链接
make check            # 当前源构建并检查当前产物
make inventory        # JSON 规模报告，方便批量审计
```

按实际范围补浏览器、构建测试或迁移保留检查。
来源证据、格式验收和线上状态分别记录；检查不回写正文，不偷偷发布。
