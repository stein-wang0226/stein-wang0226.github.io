# Stein’s Notes 设计协议

协议版本：1。设计身份沿用用户选定的原 Stein’s Notes。
权威 CSS 是 `assets/site/` 的实际文件；这里说明选择理由与组件边界。

## 1. 视觉 token

| 角色 | 当前值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#f7f5f0` | 全站暖白背景 |
| 正文墨色 | `#1a1a2e` | 正文和导航 |
| 标题深色 | `#0a0a12` | 主要标题 |
| 青绿色 | `#0d9488` | Stein’s Notes 字标和强调 |
| 可读链接色 | `#0f766e` | 链接、选中态和交互 |
| 次要文字 | `#706b65` | 摘要和辅助说明 |
| 分隔边线 | `#d6d3cd` | 内容层级和控件边界 |
| 控件背景 | `#ffffff` | 搜索输入与主要卡片 |

局部原科学图解可保留既有配色。新增公共组件复用 token；
token 调整应同步 CSS 和本表，并检查实际对比度。
不把更换主题色、全站黑底或装饰渐变作为普通内容维护。

| 字体 | 角色 | 限制 |
| --- | --- | --- |
| Sora | 标题、导航、控件 | 从 `assets/site/` 本地加载 |
| Literata | 阅读正文 | 中文回退到系统字体 |
| JetBrains Mono | 必要的日期、代码或数据 | 不用来装饰所有说明文字 |
| PingFang SC / Microsoft YaHei | 中文回退 | 保持正常中文阅读行高 |

保留字体 OFL 许可。普通组件不额外引入字体/CDN。

## 2. 布局与组件

- 博客首屏保留两行 `Stein’s / Notes.` 字标，是品牌的主要视觉重点。
- 内容宽度复用现有 1040–1120px 容器；长正文控制行长，
  图解可以独立展开或提供放大查看，不强制塞进正文窄列。
- 桌面双列文章卡片，手机单列；精选系列用实际章节顺序，
  常规内容不拆成大量相同卡片。
- 搜索为紧凑一体式控件，桌面类型/排序相邻，手机自然换行。
  保留真实标签、提交、清除条件与空结果说明。
- 主要控件满足可点击面积，键盘焦点可见；按钮名字直接描述行为。
- 结构线和章节编号表示真实层级/顺序，不在无序信息前批量添加编号。
- 动效服务于用户操作；默认不加自动轮播、漂浮背景和反复进入动画。
  必要动画尊重 `prefers-reduced-motion`。

## 3. CSS 与 HTML 的职责

| 文件或层 | 可以负责 | 不应承担 |
| --- | --- | --- |
| `site.css` | 导航、首页、目录、页脚、公共 token | 覆盖整篇原文的所有 `h1/table/svg` |
| `profile.css` | 个人资料、项目、下载区 | 重写博客卡片 |
| `reading.css` | 导读、目录、系列、关联与宽内容适配 | 重画数学公式或科研图 |
| 专题 CSS | 同系列的图解、实验表和局部交互 | 为一个专题更换全站身份 |
| 正文局部样式 | 该文章特有的科学展示 | 复制导航、页脚和搜索逻辑 |

公共选择器限定在 `.site-page`、`.site-nav`、`.site-footer` 或阅读组件作用域。
新增专题用明确的专题根类。不要靠越来越宽的 `!important` 覆盖冲突；
历史手机目录的兼容覆盖有明确目标，不作为新代码的默认写法。

图像与科研 SVG 使用 `max-width:100%; height:auto`，保留 `viewBox`。
KaTeX / MathJax 内部 SVG 排除在科研图规则外。
宽表格、代码、长公式在自身容器滚动，页面整体不横向溢出。

## 4. 内容的视觉表达

文章先让读者知道问题、核心结论和阅读路径，再展开原理、实现和实验。
比较用表；机制用真实张量、流程或状态图；实验用有轴标签、单位和口径的图。
不使用无信息量的示意图填空，不把多个独立图表拉成同一长宽比。

标题书面、直接，正文避免“下钻”等生硬行话。状态、警告和限制说明只在有助于
理解结论时出现；实现细节留在对应研究段落，不进入普通导航文案。
有关新网页图片的生成/来源要求，遵循当前工具与用户的明确约束；不擅自取用外部图片。

## 5. GitHub Profile 的独立边界

GitHub 控制网页外壳、配色、字体和响应式布局，README 不支持任意 CSS 或 JavaScript。
GitHub Marketplace 的应用不会为所有访问者替换个人主页主题。

Profile 复用内容身份：研究对象、方法、成果和通往 Stein’s Notes 的路径。
使用原生标题、链接、表格和 `details`，让亮色/暗色模式自然适配。
不要在 README 中复制站点 CSS，也不安装只对个人浏览器生效的主题插件作为公开改版。

本次 Profile 的设计选择：

- GitHub 原生白/暗背景和链接蓝；本地预览只模拟平台排版。
- 人名与一句研究主线是首屏，资料链接保持一行或自然换行。
- 四项实际研究工作组成两列内容块，论文使用清晰的状态表。
- 次要论文和评测口径放可展开区；公开代码与精选阅读保持简洁。
- 不用技术栈徽章墙、贡献动画、访问计数或第三方统计图片填满首屏。

## 6. 修改后的验证

公共样式检查 390/768/1440px 的首页、博客、关于和代表科学长文；
检查搜索、Tab/Enter、可见焦点、菜单、目录、系列跳转、图表比例和无脚本阅读。

Profile 改动用 GitHub Markdown API 检查实际允许的标签和链接；
本地预览核对层级和尺寸，并明确它不是已发布的 GitHub 页面。
先看实际截图，再删去不能帮助读者的装饰。验收记录要标出本次范围，
不把正文事实或 GPU 实验算作样式验证通过。
