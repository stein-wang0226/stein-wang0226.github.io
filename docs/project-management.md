# 博客项目管理协议

协议版本：1。适用于统一主站、Stein’s Notes、CV、论文和 GitHub Profile 展示稿。
本协议定义稳定工作方法；当前内容清单、类别和 URL 由 JSON 登记，不在文档再维护一份。

## 1. 仓库边界

| 仓库或位置 | 职责 | 更新方式 |
| --- | --- | --- |
| `stein-wang0226.github.io`，本地 `site/` | 所有站点内容、组件、协议、维护 skill 的权威仓库 | 编辑源 → 检查 → 按授权提交和部署 |
| `stein-wang0226/stein-wang0226` | GitHub 个人主页 README 的展示仓库 | 从主仓库 `docs/github-profile/README.md` 同步 |
| `wyx0226.github.io` | 原学术站和历史提交 | 保留兼容；停用 Pages、归档和删除分别处理 |
| 工作区 `.trae/skills/` | IDE 的技能发现入口 | 管理 skill 链接到主仓库版本 |
| `/tmp/` 或用户指定的外部 work 目录 | checkout、测试、截图、预览、缓存 | 不进入正式内容目录 |

同名 Profile 仓库是 GitHub 平台的特殊入口，不能通过“合并到主站”取代。
新文和个人资料集中维护，展示仓库不独立增加事实。

## 2. 管理架构

```text
site/
├── AGENTS.md                         # 所有 Agent 的统一工作入口
├── .trae/skills/
│   ├── blog-project-manager/         # 分类、协议、批量整理与同步管理
│   └── blog-maintainer/              # 文章、个人页、组件的实际维护
├── content/
│   ├── site.json                     # 站点定义与公开资源
│   ├── catalog.json                  # 唯一文章/系列登记
│   ├── redirects.json                # 旧地址与资源副本
│   ├── posts/<id>/                   # 独立文章
│   ├── series/<series-id>/           # 入口和章节
│   ├── pages/                        # 关于和 CV
│   ├── publications/                 # 一文一记录
│   └── archive/                      # 保留的原件与历史正文
├── assets/
│   ├── site/                         # 全站字体、样式、目录脚本
│   ├── research/<topic-or-date>/     # 原始报告、数据、图表与来源
│   └── archive/                      # 历史 PDF
├── templates/                        # 页面结构与新文模板
├── scripts/                          # 登记、渲染、阅读装配与检查
├── docs/                             # 协议、研究依据、验收记录
│   └── github-profile/               # README、账号字段与同步协议
├── .automation/                      # 边界明确的前沿更新器
└── .github/workflows/pages.yml        # 构建、检查、导出、部署
```

构建链为 `catalog.load_content → BuildContext → pipeline → reading/views → check → export`。
继续使用锁定依赖的 Python + Markdown/HTML；正常扩充内容不引入数据库、CMS 或第二套框架。
若明确需求超出现有能力，先给出可核对的迁移收益、兼容方式和实际改动范围。

## 3. 内容组织与规模化

主题回答“研究什么”，类型回答“怎么讲”，`kind` 回答“内容怎样组织”：
三者分别维护。`origin`、`status` 和 `review_status` 不混进主题分类。

- 主题与类型从 `content/site.json` 选用；同义概念先用标签，不因一篇文章新增分类。
- 独立结论与阅读目标使用 `post`；连续学习路径使用 `series` + `chapter`。
- 前沿追踪记录增量，研究地图解释机制与证据，训练系列定义阶段与配方，
  题库检查掌握程度。通过 `related` 和锚点引用主讲页面，减少重复长文。
- 已有内容优先补缺口、例子、题解、来源和实验，不靠拆分同一篇长文增加数量。
- 新章有明确先修、输出和父系列顺序；搜索默认不把所有章节重复列为集合。
- `featured` 表示当前推荐，不等于科研质量评分。推荐应覆盖读者路径，
  并在内容规模增长时审阅首屏数量。
- 草稿使用 `draft`；完稿才进入 `published`。`archived` 内容保留可访问入口，
  归档不是默认删除源文件。

数量和关系随时用 `make governance` 或 `make inventory` 查看。
该检查不会写回 catalog 或刷新历史校验值。

## 4. 一次更新的协议

| 阶段 | 要做的事 | 可检查的产物 |
| --- | --- | --- |
| 定位 | 阅读状态、登记与目标正文，识别他人修改 | 本次范围和唯一源路径 |
| 内容 | 修订正文、例子、证据、限制，必要时更新摘要与关系 | 正文和登记差异 |
| 装配 | 检查父系列、前后章、关联、资源和旧 URL | 当前构建产物 |
| 验证 | 运行相应检查与真实浏览器操作 | 命令、日期、范围和结果 |
| 同步 | 按授权提交、推送，核对部署与目标页面 | commit、Actions、线上版本 |

正文要求见 [内容与资源协议](content-contract.md)，视觉要求见
[设计协议](design-system.md)，日常命令见 [维护流程](maintenance.md)。

不为每次小修改新建长期任务日志。来源复核和显著批量变更可以按主题/日期记录在 `docs/`；
同日同主题优先续写原记录。长远有效的规则回写协议，瞬态排查留在外部 work 目录。

## 5. 资料与 Profile 的一致性

| 事实或展示 | 权威来源 | 需要一起核对的入口 |
| --- | --- | --- |
| 任职、研究方向、项目范围 | 作者材料、`about.md`、`cv.md` | 首页、关于、CV、Profile |
| 论文题目、作者、状态 | 作者材料/原始论文、`publications/*.md` | 精选论文、详情、CV、Profile |
| 学习内容与推荐 | `catalog.json` | 博客、首页、Profile 精选链接 |
| 简历快照 | 作者提供的 PDF | 下载地址、在线说明和旧版副本 |
| GitHub 名称、bio、website | `docs/github-profile/settings.json` | 账号实际字段 |
| 置顶项目 | 当前可公开代码与研究价值 | GitHub pinned items |

主页简述方法和结果，CV 保存完整职责、评测口径与来源。
Profile 可以精选表达，但不能独立捏造或扩大事实。PDF 是快照，不自动等同于在线 CV。

置顶优先级：主站 → 原创研究代码 → 有实际独立内容的研究工具。
不默认展示普通 fork、Profile 空壳、课程练习或未公开的内部项目链接。
fork 有明确原创补丁、公开上游贡献或独立实验时，才描述具体贡献并链接证据。

## 6. 质量和发布边界

- 普通正文/登记更新：`make governance`、`make check`，并查看受影响页面和入口。
- 公共样式/导航：另查首页、博客、关于、代表长文的 390/768/1440px，
  焦点、手机菜单、科学图表和无脚本阅读。
- 构建/契约变化：运行已有 `scripts/test_pipeline.py`，核对隔离产物、失败保留、
  草稿排除、字节一致性和源不回写。
- 基线覆盖的正文/资源变化：逐项记录实际差异，再运行迁移保留检查。
- Profile：本地一致性检查、GitHub Markdown 渲染、链接、远端 README/字段/置顶状态。

`make governance` 检查 skill 引用、Profile 本地结构与链接和可管理的内容登记，
同时报告规模；`make check` 和 Pages 构建都会执行这项检查。
它不证明外部论文、个人事实或性能实验成立。

提交、推送、主站部署、README 同步、账号字段更新和置顶调整分别记录。
当前/此前明确授权内的动作直接推进，未获授权的远端写入保持为已准备的本地结果。
不要把“Git 工作树干净”“push 成功”或“README 已同步”替代所有对象的实际线上核对。

## 7. 当前审计与后续收益

2026-11-14 本次初始登记为 40 项：4 个系列、25 个章节、9 个独立文章
（含 1 个归档）、2 个外部入口；另有 6 篇论文。该计数是审计快照。
主仓库跟踪 147 个文件，`assets/` 实际约 54.7 MB，包含其他任务尚未提交的研究原件。

已经具备：显式登记、统一入口、隔离构建、URL 兼容、资源清单、Pages 校验和内容保留证据。
主要管理缺口及本次处理：

| 缺口 | 处理 |
| --- | --- |
| 规则分散，缺少 Agent 的统一入口 | `AGENTS.md` + 本协议 + 项目管理 skill |
| 样式身份只有历史设计记录 | 稳定设计 token、作用域和验收协议 |
| HTML、原件、数据的管理口径不集中 | 内容与资源协议 |
| 同步状态靠历史文字判断 | `profile.py status` 逐次读取真实远端 |
| Profile 存在仅描述 fork 来源的精选项 | 移除该项，按原创贡献筛选 |
| 左侧账号资料和置顶与主站定位不一致 | 保留可执行字段稿及明确的置顶顺序 |

内容继续扩充时，先依靠检查与索引改善管理；不要为规模增长提前制造复杂系统。
