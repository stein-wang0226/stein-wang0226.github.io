## 完整算例

Transformer 旧稿位于 `assets/archive/blog-before-learning-rework-20261115/posts/transformer-decoder-flow/index.html.txt`，72,136 bytes，原件不改。现稿在 `content/posts/transformer-decoder-flow/index.html`，装配为架构第2节。

恢复的训练链路包括查表、第一次 Norm、QKV、拆头、RoPE、打分、mask、softmax、value 加权、拼头与输出投影、第一条残差、第二次 Norm、SwiGLU、第二条残差、重复层、最终 Norm、head 和标签移位。推理链路包括 prefill、首token采样、逻辑位置、每层缓存、单token decode、再次采样与缓存状态。每一步有输入、中间对象、形状与输出。

数值教学模型单独声明关闭 RoPE、ε=0、单位投影矩阵等简化。第二位置输出分布为 `(0.179970, 0.659085, 0.160945)`；额外给定 EOS 标签时，该位置 NLL 为 `1.826695`。这些不是训练模型的质量结果。完整 PyTorch 代码保留 RoPE 和 ε，并用小型 CPU 模型运行一步训练。

同时补齐：

- GRPO：reward → 总体标准差与固定优势 → current/old ratio → 正负优势裁剪 → loss → logit 梯度；`J=0.11547005383792502`，有限差分最大误差 `1.84e-11` 以内。
- 投机解码：候选 `[B,B,C]` → 接受首B → 拒绝次B并补A → 丢弃后缀 → 提交 `[B,A]` → 恢复缓存。明确逻辑输出和已计算K/V的区别。
- Muon工业配方：接到训练主题的 polar 推导后，完整保留六项模型配方、参数分组、逻辑矩阵与分布式边界；架构页只保留机制关联入口。

旧稿中“Pre-Norm无需warmup”“推理无需mask”等绝对说法没有恢复为当前结论；当前解释明确条件。最终 Norm、标签来源、RoPE配对、SwiGLU参数预算与 repetition penalty 的正负logit处理分别说明。
