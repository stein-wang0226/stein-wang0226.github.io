<section id="scope"><h2><small>01 / READING GUIDE</small>主要结论与证据边界</h2><p>ProtAgent 研究紧凑模型能否学习使用真实生物信息工具：SFT 先学习工具调用和答案接口，在线 RL 再优化工具选择、停止和证据整合。论文主要研究变量是<strong>交互步骤级回报</strong>，不是全新基础模型。</p><div class="cards"><div class="card"><strong>61.00%</strong><span>闭环 OOD-1000：ProtAgent-8B 全样本成功率</span></div><div class="card"><strong>+19.40 pp</strong><span>相对 DeepSeek-V3.2-Thinking；95% 配对 CI [15.90, 23.00]</span></div><div class="card"><strong>60.15 / 41.62</strong><span>另一个 PFUA 模型的 ROUGE-1 / ROUGE-L recall，%</span></div></div><div class="warn"><b>不可混用：</b>闭环 61.00% 是参考注释 token 覆盖成功率，不直接衡量生物学正确性；PFUA 采用独立的数据、奖励、模型 checkpoint 和 ROUGE 指标。论文结果优先于历史实验表和配置摘要。</div><p>闭环主表本地 Qwen3 的温度为 1.0，而 API 行为 0，工具和提示相同不代表解码完全相同。61.00 与 GPT-5.5 的 60.80 差距很小，论文不据此主张优越或等价。</p><p class="source">来源：<a href="../../paper/arxiv2026/ProtAgent_arXiv.tex">论文 §3、§5</a>；<a href="../../paper/protagent_paper.pdf">论文 PDF</a>。</p></section>

<section id="sft"><h2><small>04 / SUPERVISED LEARNING</small>SFT：学习接口而非生成工具观察</h2><p>单步动作、观察到答案和完整多轮轨迹构成不同监督形态。系统消息、用户消息与工具观察是上下文，只有 assistant 动作和回答是预测目标。loss mask 用来避免将工具响应误当成模型需要生成的目标，label shifting 用于 next-token 对齐。</p><div class="eq">L<sub>SFT</sub> = − Σ<sub>u ∈ assistant tokens</sub> log πθ(yᵤ | context, y&lt;ᵤ)</div><div class="wrap"><table><tr><th>论文 SFT 参数</th><th>设置</th><th>解释</th></tr><tr><td>base / 数据</td><td>Qwen3-8B-Instruct；987 / 64；1 epoch</td><td>训练与验证轨迹规模</td></tr><tr><td>学习率 / 权重衰减</td><td>1×10⁻⁶，cosine / 0.01</td><td>优化日程和正则化</td></tr><tr><td>batch × 累积</td><td>1 × 1</td><td>论文给出局部 batch 与累积，不据此猜测全局 batch</td></tr><tr><td>长度 / 精度</td><td>8,192 / bfloat16</td><td>多轮轨迹上下文和数值格式</td></tr><tr><td>后端 / 并行</td><td>Megatron；TP2、PP2、CP2、sequence parallel</td><td>模型和输入切分方式</td></tr><tr><td>模板</td><td>Qwen2.5 chat template；label shifting enabled</td><td>模型基座和模板是不同配置项</td></tr></table></div><p class="source">来源：<a href="../../paper/arxiv2026/appendix.tex">论文附录 Training Configuration</a>；<a href="../../../supplementary/code_data/configs/closed_loop_main.yaml">补充配置摘要</a>。</p></section>
<section id="reward"><h2><small>05 / REINFORCEMENT LEARNING</small>动作奖励与步骤级信用分配</h2><p>RL 从 SFT 及已有 RL-warm checkpoint 继续。每个问题采样 K=4 条轨迹；中间工具调用获得动作奖励，终止答案获得组合奖励。该方法是 critic-free on-policy REINFORCE，未来奖励沿<strong>同一轨迹</strong>回传给之前步骤。</p><div class="eq">Gₜ,ₖ = rₜ,ₖ + γGₜ₊₁,ₖ，G<sub>H+1,k</sub> = 0；主设置 γ = 1<br>L = −E[Âₜ,ᵤ log πθ(yₜ,ᵤ | hₜ,ᵤ)] + βD<sub>KL</sub>(πθ || πref)</div><p>步骤回报赋给该 response 的 token。主方法使用 identity return normalization，随后对 advantage 做 whitening 与 clipping；identity 不代表整个优势处理链都没有归一化。论文中的 Step-Level GRPO 指按 prompt 组标准化逐步 return，目标仍是 vanilla policy gradient，不应等同于框架中的 episode GRPO。</p><div class="diagram"><svg viewBox="0 0 1000 155" role="img" aria-label="步骤回报和回合回报对照"><g font-family="sans-serif" font-size="16" fill="#174753"><text x="10" y="34">轨迹</text><text <section id="infra"><h2><small>06 / TRAINING & INFERENCE</small>代码、训练与工具框架</h2><div class="cols"><div><h3>训练与推理</h3><p>ProtAgent 负责蛋白任务、reward、工具、评测与配置；分布式训练由 ROLL 执行。论文 SFT 使用 Megatron；RL actor 使用 FSDP2，轨迹生成使用 vLLM。更新后需要将 actor 权重同步到推理侧，reference policy 提供 KL 约束。</p></div><div><h3>环境与工具</h3><p>registry 定义工具与后端，executor 处理输入和调用，native preflight 检查依赖。训练和论文评测需真实执行程序与数据库；启发式结果不能冒充论文 actual-tool 输出。</p></div></div><div class="wrap"><table><tr><th>类别</th><th>工具</th><th>依赖</th></tr><tr><td>序列与同源</td><td>seq_basic_props、MMseqs2 best hit</td><td>基础性质为 heuristic；MMseqs2 需 Swiss-Prot</td></tr><tr><td>结构域与定位</td><td>Pfam hmmscan、TMbed、SignalP</td><td>HMMER/Pfam-A、TMbed 和 SignalP 6.0 权重</td></tr><tr><td>无序与酶</td><td>IUPred3、CLEAN</td><td>对应程序、数据库或模型权重</td></tr><tr><td>skill API</td><td>STRING、QuickGO、Reactome</td><td>外部查询与返回快照</td></tr></table></div><p>可注册工具、启发式替代和占位能力不意味着都被论文主实验使用。预检应同时核验实际启用清单、二进制和数据库版本以及输出签名，不能只看模式名称或是否产生分数。</p><h3>Staging 与可复现单元</h3><pre>数据与 YAML → staging 副本 → 幂等 patcher → native preflight

<section id="limits"><h2><small>11 / INTERPRETATION</small>理论解释与后续决策</h2><p>episode return 把同一轨迹分数赋给所有动作；一条轨迹可能同时含有有用调用和重复调用。step return 保留位置与局部奖惩，使后发生的动作不继承之前的局部奖励，同时保留未来结果对先前动作的回传。这改善信号分辨率的解释与实验方向一致，但不是所有多轮任务都会提升的定理。</p><ul><li>注释 token overlap 不直接衡量生物学真值、工具证据蕴含或置信度校准。</li><li>训练池同源审计不能保证 runtime 数据库对测试蛋白不可检索；SignalP 版本差异没有匹配验证。</li><li>grounded citation、结构化 ID 密度、工具路由与 fidelity 为行为诊断，不是完整错误类别标注。</li><li>模型规模、数据分布与工具集合有限；更大范围结论需要跨 backbone、任务和数据源验证。</li></ul><div class="note"><b>下一步决策：</b>若目标是生物学可信度，应优先冻结预测，进行独立专家评审和证据蕴含标注；若目标是机制解释，应固定起点和预算，补充跨模型、跨工具及逐 reward 组件的匹配实验。两条路线回答不同问题。</div></section>
<section id="deep-dive"><h2><small>12 / ALGORITHM DEEP DIVE</small>算法选择：从假设、控制变量到代码路径</h2>
<p>这一节把算法比较拆成两个正交问题：一条轨迹的奖励如何分配给不同步骤，以及同一 prompt 生成的多条轨迹如何变换数值尺度。论文采用已有的 Monte Carlo return 和 REINFORCE，其贡献是在蛋白工具环境中对这两个因素进行控制比较，而不是提出新的通用策略梯度估计器。</p>
<h3>12.1 四臂设计与可解释的控制变量</h3>

<h3>12.2a 用一条轨迹计算回报</h3>
<p>下面是解释算法的人造算例，不是论文中的额外实验。假设三个步骤分别得到 +0.25、−0.30、+1.00，且 γ=1；逐步方法从末尾累加，episode 方法把总和赋给每个步骤。</p>
<div class="wrap"><table><thead><tr><th>步骤</th><th>示例动作 / rₜ</th><th>Step return Gₜ</th><th>Episode return</th></tr></thead><tbody><tr><td>1</td><td>首次相关调用 / +0.25</td><td>0.25 − 0.30 + 1.00 = 0.95</td><td>0.95</td></tr><tr><td>2</td><td>重复调用 / −0.30</td><td>−0.30 + 1.00 = 0.70</td><td>0.95</td></tr><tr><td>3</td><td>终止答案 / +1.00</td><td>1.00</td><td>0.95</td></tr></tbody></table></div>
<p>例如第 2 步不会继承第 1 步已取得的局部奖励，但仍收到第 3 步后续结果。数值只是 return；进入梯度前还须经过配置指定的 normalization、mask、whitening 和 clipping，不能把表中的 0.70 直接称作最终 advantage。</p>
<h3>12.3 为什么选 K=4、四步及分段重启</h3>
<div class="wrap"><table><tr><th>参数</th><th>论文值</th><th>机制与解释边界</th></tr><tr><td>采样组 K</td><td>4 条轨迹 / prompt</td><td>提供同一问题下的多个 on-policy 样本；不自动保证每组存在奖励差异，论文未在主表证明 K=4 最优</td></tr><tr><td>prompt instances / update</td><td>8</td><td>每次更新处理的问题实例数；与单条轨迹、token batch 和 GPU 数不同</td></tr><tr><td>H / response budget</td><td>4 步 / 1,024 tokens；总长 4,096</td><td>约束工具查询与答案生成；把停止策略和 token 截断纳入同一任务契约</td></tr><tr><td>γ</td><td>1.0</td><td>同轨迹后续奖励不因步骤距离折扣；不等于不同 reward 分量同权</td></tr><tr><td>β / policy epochs</td><td>0.001 / 1</td><td>参考策略约束强度及每批策略更新次数；不能推断对应的实测 KL 曲线</td></tr><tr><td>三阶段学习率</td><td>5e−7 → 5e−8 → 5e−8；各 50 updates</td><td>每阶段重新锚定 reference 并重置 optimizer；权重从前一 checkpoint 继承</td></tr><tr><td>advantage clip / grad norm</td><td>±0.2 / 1.0</td><td>前者约束优势信号，后者约束梯度范数；不是 PPO 概率比裁剪</td></tr></table></div>
<p>这些参数是论文选定配方，不是逐项参数搜索得出的全局最优值。尤其应分开原始 return、whiten 后的 advantage 和训练 reward：它们不共享可直接排名的数值含义。</p>
<h3>12.4 代码走读：轨迹 → return → response → token</h3>
<pre>compute_discounted_returns:
  group_by(traj_id) → 按 step 排序
  reversed: running = reward[t] + gamma * step_lambda * running
  step_rewards = running → 恢复原始样本顺序

step_reinforce:
  step_rewards → agentic_reward_norm(config) → response_level_rewards
  → token_level_rewards / response_mask → compute_reinforce_return
  → masked_whiten（配置启用时）→ advantage_clip</pre>
<p class="caption">代码展品｜摘自补充包 <a href="../../../supplementary/code_data/third_party/roll/roll/pipeline/agentic/utils.py">agentic/utils.py</a> 的处理顺序，展示结构而非完整调用栈。该函数同时支持 step_reinforce_lambda；论文主配方中的 step λ=1 才退化为普通折扣回报。</p>
<p>先按 traj_id 分组、按 step 排序，保证不会把不同轨迹的未来奖励串接；计算后恢复样本原序。step_reinforce 路由通过配置选择回报归一化，再进入 token 级 advantage、mask、whitening 和裁剪；因此同名参数必须连同调用位置阅读。该补充代码用于解释契约，并不单独证明某次远端 run 的每个配置值。</p>
<h3>12.5 OOD-100 局部消融：不显著不等于等价</h3>

<h3>12.7 评分代码与诊断分母</h3>
<p>补充包的 <code>analyze_ood100_eval.py</code> 对 domain_motif 在存在 <code>annots</code> 时用该字段作为 gold，使用 <code>kw_recall &gt; 0.5</code> 判成功，并分别报告匹配样本统计及以 episode 总数计算的 honest 指标。缺失答案或未匹配样本不进入 matched，但在 all-sample 分母中不获成功；要声称完整 benchmark 覆盖，还必须结合唯一 ID 和数量的完整性检查，不能只看这一个脚本输出。</p>
<p>论文附录的 grounded-citation rate 和 identifier 数量以已回答样本为分母；表中的首次/任意步骤相关工具 aggregate 专指三个数据库任务，而非五任务宏平均。正文中这两种诊断分母与主指标的全部 episode 分母不同，不能直接相减。</p>
