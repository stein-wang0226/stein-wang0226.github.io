<section id="peft">
<h2>LoRA 与 QLoRA：冻结底座，仍需要反向传播</h2>
<section id="citation-sources-2" aria-label="章节来源" data-citation-audit="20261114"><p class="citation-source-links" style="font-size:0.88em;line-height:1.8"><strong>相关原论文 / 官方资料：</strong><a href="https://arxiv.org/abs/2002.05202" title="GLU Variants Improve Transformer · Shazeer, Noam · 2020/02/12 · 2002.05202">SwiGLU</a>；<a href="https://arxiv.org/abs/2305.13245" title="GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints · Ainslie, Joshua, Lee-Thorp, James, de Jong, Michiel 等 · 2023/05/22 · 2305.13245">GQA</a>；<a href="https://arxiv.org/abs/2106.09685" title="LoRA: Low-Rank Adaptation of Large Language Models · Hu, Edward J., Shen, Yelong, Wallis, Phillip 等 · 2021/06/17 · 2106.09685">LoRA</a>；<a href="https://arxiv.org/abs/2305.14314" title="QLoRA: Efficient Finetuning of Quantized LLMs · Dettmers, Tim, Pagnoni, Artidoro, Holtzman, Ari 等 · 2023/05/23 · 2305.14314">QLoRA</a>。</p></section>

<div class="equation" role="math" aria-label="LoRA更新与参数量">W₀ ∈ R^(dout × din)，A ∈ R^(r × din)，B ∈ R^(dout × r)
y = W₀x + (α/r)BAx；可训练参数 = r(din + dout)
完整矩阵参数 = din × dout；底座 W₀ 冻结</div>
<p>低秩限制施加在增量 ΔW，底座可以是满秩。LoRA 省去冻结参数的梯度和优化器状态；上游 adapter 要获得梯度，仍可能需要穿过后续冻结层反传和保存 / 重算激活。因此“只训练少量参数”不能直接换算为相同比例的训练计算下降。<a href="#ref-lora">[1]</a></p>
<p>例如一个8192×8192矩阵，本文选 r=64，可训练量为1,048,576，约为原矩阵的1.56%；这是单矩阵规格推导，不代表全模型比例。若扩展到 Q/K/V/O、SwiGLU 三矩阵、router 或专家，必须分别统计真实形状与是否共享。GQA 的 K/V 矩阵通常更小。</p>

<section id="optimizers">
<h2>AdamW、Muon 与精度：更新规则不等于权重约束</h2>
<section id="citation-sources-3" aria-label="章节来源" data-citation-audit="20261114"><p class="citation-source-links" style="font-size:0.88em;line-height:1.8"><strong>相关原论文 / 官方资料：</strong><a href="https://arxiv.org/abs/2304.11277" title="PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel · Zhao, Yanli, Gu, Andrew, Varma, Rohan 等 · 2023/04/21 · 2304.11277">FSDP</a>；<a href="https://docs.pytorch.org/docs/stable/fsdp.html" title="PyTorch FSDP API · 官方文档 / 原始出版页">PyTorch FSDP API</a>。</p></section>

<div class="equation" role="math" aria-label="AdamW与Muon的概念更新">AdamW：W ← (1−ηλ)W − η m̂/(sqrt(v̂)+ε)
Muon（概念）：M ← momentum(G)；U ≈ polar(M)；W ← W − η·scale(U)
梯度裁剪：G ← G·min(1, c/(||G||₂+ε))</div>
<p>AdamW 把 weight decay 从自适应梯度分母中解耦，不能简单等同于给 Adam loss 加 L2。Muon 近似正交化的是二维更新矩阵，不要求更新后 W 正交；embedding、输出头和一维参数的分工，以及矩形缩放、动量 / Nesterov、Newton–Schulz实现都影响结果。<a href="#ref-adamw">[3]</a> <a href="../llm-research-map-2026/s07_architecture_training.html#muon">前沿配方与原论文</a>。</p>
<p>矩阵被 TP/FSDP 切片后，独立对每块做 polar 一般不等于整矩阵更新再切片。研究方案应冻结 optimizer 的逻辑矩阵、通信、参数分组和精度，再比较 AdamW / Muon；否则“优化器收益”混入了重计算、并行和更新预算差异。</p>
<div class="callout"><strong>优化器阅读路线：</strong><a href="#adamw-derivation">SGD → Momentum → Adam → AdamW</a> → <a href="#adamw-example">两步数值例子</a> → <a href="#optimizer-landscape">方法与适用条件</a> → <a href="#optimizer-cost">显存与 FLOPs 账本</a> → <a href="#optimizer-evidence">原论文效率对照</a> → <a href="#optimizer-recipe">训练框架中的落地检查</a>。原理、规格推导与作者实验分别注明；没有统一条件下的实测排名。</div>

<h3 id="adamw-derivation">从 SGD 到 AdamW：方向、尺度与衰减逐步分开</h3>
<p>设待训练参数为 θ，当前 minibatch 的平均损失为 L<sub>t</sub>，g<sub>t</sub> = ∇L<sub>t</sub>(θ<sub>t−1</sub>)。以下向量乘除与平方均逐坐标进行；一次 t 指一次真正的 optimizer update。梯度累积的多个 microbatch 共同形成这次 g<sub>t</sub>，不各自推进动量和偏差修正。来源：<a href="https://arxiv.org/abs/1412.6980v9">Adam 原论文</a>、<a href="#ref-adamw">AdamW 原论文 [3]</a>与<a href="https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html">PyTorch AdamW 算法与 API</a>。</p>
<figure><div class="flow" aria-label="SGD到AdamW的方法关系">
<div class="stage"><b>SGD</b><small>用当前梯度<br>同一学习率作用于各坐标</small></div>
<div class="stage"><b>Momentum</b><small>积累历史方向<br>减少方向反复变化</small></div>
<div class="stage"><b>Adam</b><small>方向均值 + 平方均值<br>按坐标调整更新尺度</small></div>
<div class="stage"><b>AdamW</b><small>保留 Adam 更新<br>单独施加权重衰减</small></div>
</div><figcaption>教学关系图：Adam 还吸收了自适应缩放思想，并不是从 Momentum 唯一推导出的算法。</figcaption></figure>
<h4>1. SGD：当前梯度决定下一步</h4>
<div class="equation" role="math" aria-label="SGD更新">L(θ + Δθ) ≈ L(θ) + gᵀΔθ
min_Δθ [gᵀΔθ + ||Δθ||₂²/(2η)]  ⇒  Δθ = −ηg
θ_t = θ_(t−1) − η_t g_t</div>
<p>这个局部线性化加二次步长惩罚解释了梯度下降方向；minibatch 梯度将它变成 SGD。它不保存梯度历史。不同坐标的梯度尺度差异或 batch 噪声可能让同一个 η 很难兼顾所有方向，但不能据此断言 SGD 在所有任务都差。</p>
<h4>2. Momentum：对历史方向做平滑</h4>
<div class="equation" role="math" aria-label="Momentum和指数平均">u_t = μu_(t−1) + g_t；θ_t = θ_(t−1) − η_t u_t
u_t = Σ_(k=1..t) μ^(t−k) g_k，u_0 = 0
EMA约定：m_t = β₁m_(t−1) + (1−β₁)g_t
若μ=β₁且初值均为0：m_t = (1−μ)u_t</div>
<p>持续同向的梯度会累积，交替方向会部分抵消。sum-buffer 与 EMA 两种写法存在 (1−μ) 的尺度差，学习率要相应换算；不能直接拿相同数值的 η 比更新幅度。Nesterov 又改变取方向的位置，需核对具体实现。定义可对照<a href="https://docs.pytorch.org/docs/stable/generated/torch.optim.SGD.html">PyTorch SGD / momentum 文档</a>。</p>
<h4>3. Adam：一阶矩给方向，二阶原点矩给尺度</h4>
<div class="equation" role="math" aria-label="Adam一阶矩二阶矩和偏差修正">m_t = β₁m_(t−1) + (1−β₁)g_t
v_t = β₂v_(t−1) + (1−β₂)(g_t ⊙ g_t)
m̂_t = m_t/(1−β₁^t)；v̂_t = v_t/(1−β₂^t)
θ_t = θ_(t−1) − η_t m̂_t/(sqrt(v̂_t)+ε)</div>
<p><strong>m 是梯度的指数加权均值；v 是梯度平方的指数加权均值。</strong>v 不是中心化方差，也不是完整 Hessian：方差还需要减去均值平方，Hessian 则描述损失的二阶导数。sqrt(v̂) 大的坐标会缩小更新；较小的坐标相对放大。β₁ 控制方向记忆，β₂ 控制尺度记忆；Adam 保存两份与参数同形状的状态。</p>
<div class="equation" role="math" aria-label="偏差修正的推导">m_t = (1−β₁) Σ_(k=1..t) β₁^(t−k)g_k
若 E[g_k]=a 不随k变化，则 E[m_t]=(1−β₁^t)a
若 E[g_k²]=b 不随k变化，则 E[v_t]=(1−β₂^t)b
除以1−β^t，消除由零初始化带来的权重总和不足。</div>
<p>偏差修正针对零初始化，不代表能消除非平稳数据、策略变化或梯度估计的所有偏差；比值 m̂/sqrt(v̂) 本身也不是某个“真实更新”的无偏估计。学习率 warmup 和偏差修正作用不同，不能互相替代。<a href="https://arxiv.org/abs/1412.6980v9">Adam §2–3</a>。</p>
<h4>4. AdamW：为什么 Adam 加 L2 不等于解耦衰减</h4>
<div class="equation" role="math" aria-label="L2与weight decay区别">L2目标：L̃(θ)=L(θ)+(λ/2)||θ||₂² ⇒ g̃=g+λθ
SGD + L2：θ_t=(1−η_tλ)θ_(t−1)−η_tg_t
Adam + L2：用g̃更新m、v；λθ进入历史和自适应分母
AdamW：m、v只接收g；θ_t=(1−η_tλ)θ_(t−1)
                                −η_t m̂_t/(sqrt(v̂_t)+ε)</div>
<p>无动量的标准 SGD 中，上述 L2 和乘法衰减可等价；Adam 的坐标缩放与历史状态破坏了这个等价关系。AdamW 把衰减直接施加于参数，因此衰减项不会进入 m、v。固定学习率下，只有衰减的参数经过 T 步变为 (1−ηλ)<sup>T</sup>θ₀；变动学习率则为 ∏<sub>t</sub>(1−η<sub>t</sub>λ)θ₀。所以“解耦”不意味着最终收缩量与学习率、更新步数无关。<a href="https://arxiv.org/abs/1711.05101v3">Decoupled Weight Decay Regularization</a>。</p>

<h3 id="adamw-example">可复算的两步例子：偏差修正与权重衰减</h3>
<p>以下为<strong>本文构造的教学算例，非训练实验</strong>：θ₀=1，依次输入 g₁=2、g₂=−1，η=0.1，β₁=0.9，β₂=0.999，ε=10⁻⁸，λ=0.1，m₀=v₀=0。梯度由例子给定，不随各算法参数重新计算，故不能用最终 θ 比较收敛优劣。</p>
<div class="reading-table" style="overflow-x:auto"><table>
<thead><tr><th>t / g</th><th>m</th><th>v</th><th>m̂</th><th>v̂</th><th>m̂/(√v̂+ε)</th><th>Adam θ</th><th>AdamW θ</th></tr></thead><tbody>
<tr><td>1 / 2</td><td>0.2</td><td>0.004</td><td>2</td><td>4</td><td>≈1</td><td>0.900000</td><td>0.890000</td></tr>
<tr><td>2 / −1</td><td>0.08</td><td>0.004996</td><td>0.421053</td><td>2.499250</td><td>0.266337</td><td>0.873366</td><td>0.854466</td></tr>
</tbody></table></div>
<p>第一步未经偏差修正的方向是 0.2/√0.004≈3.1623，修正后约为1。第二步虽然 g₂ 为负，m₂ 仍为正，历史方向尚未反转。AdamW第二步为 0.99×0.89−0.1×0.266337≈0.854466。相同梯度序列下，SGD是1→0.8→0.9；sum-buffer Momentum（μ=0.9）是u:0→2→0.8，θ:1→0.8→0.72。</p>
<details><summary>展开：用 Python 标准库复算 Adam / AdamW</summary>
<pre><code>from math import sqrt
m = v = 0.0
adam = adamw = 1.0
for t, g in enumerate((2.0, -1.0), start=1):
    m = 0.9 * m + 0.1 * g
    v = 0.999 * v + 0.001 * g * g
    mh = m / (1.0 - 0.9 ** t)
    vh = v / (1.0 - 0.999 ** t)
    direction = mh / (sqrt(vh) + 1e-8)
    adam -= 0.1 * direction
    adamw = (1.0 - 0.1 * 0.1) * adamw - 0.1 * direction
    print(t, mh, vh, direction, adam, adamw)</code></pre>
<p class="note">这是公式复算代码，不含 autograd、参数分组、混合精度或分布式逻辑。</p>
</details>

<h3 id="optimizer-landscape">业界与研究路线：优化方向、减少状态、改善矩阵几何</h3>
<p>以下区分<strong>已有工业实现</strong>与<strong>研究候选</strong>。参数状态中的二阶矩不是二阶导数；Shampoo/SOAP也通过梯度统计构造预条件器，不直接保存完整模型 Hessian。Muon 的核心机制和工业变体继续见<a href="../llm-research-map-2026/s07_architecture_training.html#muon">研究地图07</a>。</p>

<thead><tr><th>方法 / 来源</th><th>怎样更新或节省</th><th>适用方向与代价</th></tr></thead><tbody>
<tr><td>AdamW<br><a href="#ref-adamw">原论文 [3]</a></td><td>逐坐标m、v，自适应缩放；解耦衰减</td><td>成熟基线，常用于预训练与后训练；全尺寸状态和内存带宽是主要成本。</td></tr>
<tr><td>Muon / MuonClip<br><a href="https://arxiv.org/abs/2502.16982v1">Moonlight</a>、<a href="https://arxiv.org/abs/2507.20534">Kimi K2</a></td><td>矩阵动量经过近似polar；隐藏层矩阵Muon，其他组AdamW。MuonClip额外控制QK幅度。</td><td>已有LLM工业报告；多次矩阵乘法、逻辑矩阵分组与分布式聚合需计成本。不能默认所有参数或所有RL阶段都更优。</td></tr>

<tr><td>8-bit Adam(W)<br><a href="https://arxiv.org/abs/2110.02861v2">原论文</a>、<a href="https://huggingface.co/docs/bitsandbytes/optimizers">bitsandbytes</a></td><td>将状态做block-wise量化，目标是压缩既有优化规则的存储；小张量可保持32-bit</td><td>工具生态较成熟；量化元数据与解码kernel有成本。状态8-bit不意味着权重、梯度、master也8-bit，或总显存下降75%。</td></tr>

<p><a href="https://arxiv.org/abs/2607.19058v2">SkewAdam（2026-08-13，v2）</a>按MoE骨干、专家、router分配不同状态；作者6.78B MoE、82M token短程实验报告状态50.6→1.29GB、峰值81.4→31.3GB。v2消融明确：分层主要买到显存收益，不能把全部困惑度改进归因于分层。<strong>两项为作者报告、尚未在本文复现，也不作为成熟万亿token工业配方。</strong></p>

<h3 id="optimizer-cost">成本账本：显存、FLOPs、带宽与通信分别计算</h3>
<p>下面是<strong>根据状态形状推导的逻辑容量</strong>，不是实测峰值。令一个矩阵W∈R<sup>p×q</sup>、n=pq，持久浮点状态统一按FP32计，每元素4 bytes；不含权重、梯度、master、激活、临时buffer和分片。小张量例外、dtype、blocking与具体实现会改变容量。</p>

<thead><tr><th>方法</th><th>主要持久状态 / 矩阵</th><th>FP32状态容量</th><th>每次更新的主要工作</th></tr></thead><tbody>
<tr><td>SGD / Momentum</td><td>0 / n个动量元素</td><td>0 / 4n bytes</td><td>O(n)逐元素读写；Momentum多一份状态</td></tr>

<tr><td>GaLore / APOLLO，单侧rank r投影</td><td>两个rq状态 + pr的basis，示意方向p→r</td><td>约4(2rq+pr) bytes；具体momentum/额外buffer按实现</td><td>投影矩阵乘法、basis刷新；GaLore可能有SVD，APOLLO用随机投影</td></tr>
<tr><td>SOAP，未分块的双侧版本</td><td>m、旋转v、左右统计矩阵与特征基</td><td>典型约4[2pq+2(p²+q²)] bytes</td><td>旋转/Gram乘法O(p²q+pq²)，分解O(p³+q³)每f步刷新；临时区另计</td></tr>
</tbody></table></div>
<p>SOAP公式按同时保存左右统计矩阵与其特征基的版本计；<a href="https://arxiv.org/html/2409.11321v2#S7.SS2">原论文 §7.2</a>讨论空间和优化，blocking/one-sided会改结果。APOLLO的辅助缩放与GaLore的投影更新规则不同，表中只合并说明一侧压缩空间的容量，不能视为两个算法相同。</p>
<div class="equation" role="math" aria-label="单矩阵状态与全模型训练内存">8192×8192矩阵，n=67,108,864：
AdamW m+v：8n = 512 MiB；Muon/Lion动量：4n = 256 MiB
Adafactor行列状态：4(8192+8192) = 64 KiB（不含完整动量）
8-bit两个状态：2n = 128 MiB（不含scale/例外）
全参模型：BF16权重+BF16梯度+FP32 master = 8N bytes
加FP32 AdamW状态 ⇒ 16N；所有组均一份FP32动量 ⇒ 12N
后一种是状态减半、总静态容量减少25%，不是总显存减半。
若Muon只覆盖ρ比例参数，其余AdamW：state=(8−4ρ)N bytes。</div>
<p>MiB按2<sup>20</sup>bytes；上述理想式尚未做ZeRO/FSDP分片。MoE按可训练的总参数计状态，前向计算则取决于实际路由；不能用“每token激活参数量”替代全部优化器状态量。原集群<a href="#cluster">16N静态账本</a>可按真实分组替换state项。</p>
<h4>Muon的矩阵乘法，怎样换算为FLOPs？</h4>
<div class="equation" role="math" aria-label="Newton Schulz计算量规格推导">乘加按2 FLOPs计，X∈R^(a×b)，转置使a=min(p,q)、b=max(p,q)
一种五次多项式实现：A=XXᵀ；B=b₀A+c₀A²；X←a₀X+BX
每轮主矩阵乘法 ≈ 4a²b + 2a³ FLOPs
k轮 ≈ k(4a²b+2a³)；不含归一化、逐元素、通信与补充参数组
对8192×8192、k=5：≈1.649×10¹³ FLOPs = 16.49 TFLOPs/次更新
该数是运算量，不是TFLOP/s吞吐率，也不是GPU占用率。</div>
<p>推导依据<a href="https://arxiv.org/html/2502.16982v1#S2.SS1">Muon论文的Newton–Schulz多项式</a>；实际实现可能采用不同乘法安排、迭代数、精度或分块。TFLOPs高不一定墙钟更慢，因为GEMM可利用Tensor Core；AdamW运算少也可能被状态读写拖慢。要测 optimizer step 时间、显存峰值、通信字节、整步时间与有效训练吞吐，不能从公式推出固定耗时倍率。</p>
<p>对单个dense线性层，B个输入token的前向加两次反向主GEMM约6Bpq FLOPs，便于与这层的optimizer开销对比；这不是整个Transformer的精确6ND公式，Attention、激活重计算、MoE路由和其他算子需另计。梯度累积让同一次更新处理更多token，optimizer占比可能下降；缩小microbatch引发的重计算和通信则可能让真实开销上升。</p>
<p class="note">同一规格算例：8192方阵、5轮时，NS主GEMM与该层前向/反向主GEMM之比约为5×8192/B。B=65,536时约62.5%，B=524,288时约7.81%。B指这次逻辑更新实际用于该矩阵的token总量，而非microbatch大小；这两个比例为运算量推导，不是实测训练时间占比。</p>

<h3 id="optimizer-recipe">接入训练框架：保持相同目标，记录真实成本</h3>
<ol>
<li><strong>固定实验：</strong>模型/数据/tokenizer、有效token batch、loss mask、精度、并行与评测协议；分别比较等token、等总算力、等GPU-hours三种预算。各优化器独立调合理学习率与scale，计入调参成本。</li>
<li><strong>登记分组：</strong>以逻辑参数名与形状区分attention投影、MLP、expert、embedding、head、router、Norm；保存optimizer种类、decay、lr和共享/拆分规则。Muon用完整逻辑矩阵的更新接口；TP/FSDP切片不能静默改变数学对象。</li>
<li><strong>记录质量：</strong>held-out loss/perplexity和目标任务质量、遗忘、失稳/重试；至少报告重复种子的离散程度。pretrain结论不能直接当GRPO/PPO收益；RL另计rollout和环境预算。</li>
<li><strong>记录成本：</strong>forward/backward/optimizer/collective各段时间、有效tokens/s、allocated与reserved峰值、state常驻容量、峰值临时buffer、估算/实测FLOPs口径、GPU-hours与checkpoint I/O。重叠段不能重复相加。</li>
<li><strong>验证恢复：</strong>保存m/v或动量、块尺度、投影basis、量化scale、scheduler、global update与RNG；从AdamW换Muon通常是新阶段状态初始化，不能把同形状张量直接当兼容状态加载。</li>
</ol>
<p>PyTorch当前文档提供<a href="https://docs.pytorch.org/docs/stable/generated/torch.optim.Muon.html">Muon参数与两种学习率缩放</a>及<a href="https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html">AdamW的fused/foreach选项</a>；本文没有验证现有Megatron/verl固定版本已支持所有候选。框架集成要核对版本、分片语义和checkpoint格式，再做小规模运行。原有<a href="#parallel">进程组</a>与<a href="#stability">恢复检查</a>继续适用。</p>

<p>本文分析：新架构的稳定性应分解为残差传播、QK尺度、路由负载、数值范围和参数更新五个对象。loss下降只能说明当前目标被优化；通用能力回放与 held-out 任务必须独立评测。</p>

<section id="stability">
<h2>训练诊断与恢复：保存能解释异常的状态</h2>
<p>每步至少按任务桶保存目标 token 数、loss、梯度范数、裁剪比例、学习率、溢出 / 跳步、序列长度、专家负载、零方差组比例及policy lag。一次尖峰要能对应到数据版本和样本，避免把数据污染、非法工具输出、FP溢出或路由失衡统称为“训练不稳定”。</p>
<div class="reading-table"><table><thead><tr><th>现象</th><th>先区分的解释</th><th>本文建议的待执行对照</th></tr></thead><tbody>
<tr><td>某一批 loss / gradient spike</td><td>异常文本、长序列、数值溢出、更新过大</td><td>冻结样本与起点，比较精度 / 裁剪 / step；保留失败 checkpoint</td></tr>
<tr><td>训练指标升、通用能力跌</td><td>分布偏移、目标重加权、遗忘、污染</td><td>同预算比较 replay 比率与数据切分，不用训练集验收</td></tr>
<tr><td>MoE 一部分专家过载</td><td>router漂移、token异质性、容量和dispatch</td><td>分任务 / 专家看token、drop、梯度和通信；不能只看均值</td></tr>
<tr><td>恢复后行为不同</td><td>遗漏 optimizer、RNG、sampler、rollout版本</td><td>checkpoint同时保存数据游标、随机态、scheduler、adapter与环境镜像</td></tr>
</tbody></table></div>
<p>恢复范围分两层：模型训练状态能够续训；长程工具环境是否能够恢复要另外定义。只恢复权重并重新采样，不等于恢复一条中断中的科学分析轨迹。对应<a href="../agent-harness-guide.html">Harness状态管理</a>。</p>
</section>
<section id="parallel">
<h2>并行维度先分清逻辑对象</h2>
<section id="citation-sources-5" aria-label="章节来源" data-citation-audit="20261114"><p class="citation-source-links" style="font-size:0.88em;line-height:1.8"><strong>相关原论文 / 官方资料：</strong><a href="https://arxiv.org/abs/1910.02054" title="ZeRO: Memory Optimizations Toward Training Trillion Parameter Models · Rajbhandari, Samyam, Rasley, Jeff, Ruwase, Olatunji 等 · 2019/10/04 · 1910.02054">ZeRO</a>；<a href="https://arxiv.org/abs/2304.11277" title="PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel · Zhao, Yanli, Gu, Andrew, Varma, Rohan 等 · 2023/04/21 · 2304.11277">FSDP</a>；<a href="https://docs.pytorch.org/docs/stable/fsdp.html" title="PyTorch FSDP API · 官方文档 / 原始出版页">PyTorch FSDP API</a>；<a href="https://www.deepspeed.ai/docs/config-json/" title="DeepSpeed official docs · 官方文档 / 原始出版页">DeepSpeed official docs</a>。</p></section>

<div class="reading-table"><table><thead><tr><th>维度</th><th>主要切分</th><th>代价与约束</th></tr></thead><tbody>
<tr><td>TP</td><td>矩阵 / head / FFN 通道</td><td>层内collective；head及矩阵可分性、KV复制</td></tr>
<tr><td>PP</td><td>层与阶段</td><td>microbatch、pipeline bubble、层 / 专家负载不均</td></tr>
<tr><td>CP</td><td>同一长序列的上下文</td><td>Attention历史交换；不是多条独立样本</td></tr>
<tr><td>DP + optimizer sharding</td><td>样本；冗余训练状态</td><td>梯度归约 / 状态聚合；有效batch按独立样本维度算</td></tr>
<tr><td>EP / ETP</td><td>专家分配 / 单专家矩阵</td><td>dispatch/combine；专家DP与普通层DP可不同</td></tr>
<tr><td>FSDP / ZeRO</td><td>参数、梯度、optimizer状态的冗余</td><td>all-gather / reduce-scatter；不是新增的模型层轴</td></tr>
</tbody></table></div>
<p>ZeRO-1/2/3分别进一步分片optimizer、gradient、parameter；具体常驻buffer与临时聚合取决于实现。CP减少序列激活 / Attention工作量，不应假定它独立缩小每rank权重。<a href="#ref-zero">[4]</a>；原通信说明见<a href="../distributed-training-guide.html">分布式指南</a>。</p>
<details><summary>Megatron Core v0.14.0：同一 world size 的两种进程组</summary>
<pre><code># parallel_state.py L647–728；简化，BSD-3-Clause
DP = world_size // (TP * PP * CP)
ETP = TP if expert_tensor_parallel_size is None else ETP
expert_DP = world_size // (ETP * EP * PP)
# 普通层 RankGenerator：tp=TP, cp=CP, dp=DP, ep=1
# 专家层 RankGenerator：tp=ETP, cp=1, dp=expert_DP, ep=EP
# 两种视角共享 pipeline groups；不额外分配 EP 倍的 GPU。</code></pre>
<p>固定提交<a href="https://github.com/NVIDIA/Megatron-LM/blob/23e00ed0963c35382dfe8a5a94fb3cda4d21e133/megatron/core/parallel_state.py#L647-L728">23e00ed</a>。当 ETP=TP，专家层使用普通层DP×CP域重组，<code>expert_DP = DP×CP/EP</code>。这比“EP永远嵌在DP内”更精确；新版本或独立ETP需重新核对。</p>
</details>
</section>
<section id="cluster">
<h2>两套工业规模后训练规划</h2>
<section id="citation-sources-6" aria-label="章节来源" data-citation-audit="20261114"><p class="citation-source-links" style="font-size:0.88em;line-height:1.8"><strong>相关原论文 / 官方资料：</strong><a href="https://arxiv.org/abs/1910.02054" title="ZeRO: Memory Optimizations Toward Training Trillion Parameter Models · Rajbhandari, Samyam, Rasley, Jeff, Ruwase, Olatunji 等 · 2019/10/04 · 1910.02054">ZeRO</a>；<a href="https://docs.pytorch.org/docs/stable/fsdp.html" title="PyTorch FSDP API · 官方文档 / 原始出版页">PyTorch FSDP API</a>；<a href="https://www.deepspeed.ai/docs/config-json/" title="DeepSpeed official docs · 官方文档 / 原始出版页">DeepSpeed official docs</a>。</p></section>

<p>目标是讨论大模型系统约束，不为单个airway研究制造足量训练数据。Dense参考公开Qwen2.5-72B；MoE参考Qwen3-235B-A22B。它们是可固定规格的基线，最新型号案例见研究地图。H100 80GB、8卡/节点和池比例由本文选择，配置尚未运行、端到端兼容尚未验证。<a href="#ref-models">[7]</a></p>
<div class="reading-table"><table><thead><tr><th>规划</th><th>硬件与训练 actor</th><th>rollout 池</th><th>关键约束</th></tr></thead><tbody>
<tr><td>Dense 约70B</td><td>128卡 / 16节点；64训练卡<br>TP4×PP2×CP2×DP4=64</td><td>64卡；规划16个TP4副本</td><td>TP4×CP2尽量放8卡节点内；PP跨节点。reference共置须另计权重与临时区</td></tr>
<tr><td>大型MoE</td><td>1024卡 / 128节点；512训练卡<br>TP2×PP4×CP2×DP32=512</td><td>512卡；TP8为初始比较路线，EP服务为另一个消融</td><td>ETP2×PP4×EP8×专家DP8=512；128专家可分8组。94层不能四等分，规划24/23/23/24层</td></tr>
</tbody></table></div>
<p>MoE 的 TP8 rollout 可能复制4个KV heads；EP方案也不能再将同一并行域乘一次。节点放置、服务kernel、权重转换、94层stage负载与CP支持需要未来联合检查。不能从进程数乘积成立推断方案可直接投产。</p>
<div class="equation" role="math" aria-label="Dense静态训练状态估算">本文选定 N=70×10⁹，BF16权重/梯度、FP32 master+m+v：
无分片逻辑状态 = (2+2+4+4+4)N = 16N bytes
示意：TP4×PP2切权重；gradient/master/m/v在DP×CP=8域分片
每rank静态 ≈ 2N/8 + 14N/64 = 32.8125 GB（十进制）
同形状BF16 reference另加 ≈ 2N/8 = 17.5 GB/rank</div>
<p class="note">这是理想均匀切片的规格推导，N=70B也不是精确checkpoint参数量。排除激活、重计算、通信bucket、未分片参数、临时聚合、allocator、KV及碎片；FP32梯度、不同optimizer或ZeRO/FSDP策略会改公式。不能将32.8GB称为实测峰值。</p>
<p>GRPO可不训练critic；PPO的critic需要权重、梯度、optimizer和推理前向，不能塞进剩余显存时就应减少并行actor资源或扩容。reference可共置 / CPU offload，但CPU内存、传输与重载成本必须计入；独立神经reward / 教师也要独立列资源。</p>
<p>CPU环境worker负责RNA-seq脚本与verifier，另列CPU-hours、内存、并发和超时；对象存储保存不可变fixture、checkpoint、trace及artifact。未测量前CPU worker数量和墙钟时长保持空值，不能声称与GPU池免费重叠。</p>
<p><a href="../assets/research/scientific-agent-design-20261114/cluster-plan.json" download>下载完整规划JSON</a>；对照、分层长度预算和成本见<a href="../agent-data-benchmarks/s04_cluster_training_evaluation.html">科学任务集群方案</a>。</p>
</section>
<section id="rollout">
<div class="integration-overview"><h2>资源重叠与数据过期的交接</h2><p>本章主讲更新对象、优化器、诊断和训练进程组；异步rollout应把资源计划交接给<a href="../llm-posttraining/s05_frameworks_async.html#three-policy">后训练概率对齐</a>。记录行为/训练版本、丢弃策略和环境耗时，再比较有效更新吞吐；128/1024 H100规划保留在上节。</p></div>
<!-- READING:HISTORY:START --><details data-reading-history><summary>整合前异步rollout概览 · 2026-11-14</summary>
<h2>异步 rollout：提升重叠，控制数据过期</h2>
<p>同步方案等待一批中最慢轨迹，再更新actor；异步方案让环境 / 生成继续运行，trainer有足量数据就更新。其代价是行为策略与当前策略不同。必须保留采样时的logprob和策略版本，区分概率校正、裁剪、过滤及有限lag。重新用新权重计算“旧logprob”不能还原行为策略。</p>
<p>固定 verl v0.6.0 的<a href="https://github.com/volcengine/verl/blob/ddd86f527a4af75095e4677b02b5aa272913a088/recipe/one_step_off_policy/README.md">one-step-off-policy recipe</a>提供生成 / 训练资源隔离与权重同步的实现路线；AReaL v5描述完全异步、staleness控制与PPO改动。两者不是相同算法，论文数学 / coding结果也不是本科学任务的收益证明。<a href="#ref-areal">[6]</a></p>
<details><summary>本文建议的接入顺序与配置边界</summary>
<p>先以同步、相同精度 / 模板 / 动作mask建立概率一致性，再比较one-step overlap；完全异步单独消融。记录样本完成、权重同步、排队与更新时刻，区分更新次数lag和实际时间lag。长工具调用期间是否换策略须明确，最好将整条轨迹绑定同一版本或逐动作保存版本。</p>
<p>所选 verl 配置文件<a href="https://github.com/volcengine/verl/blob/ddd86f527a4af75095e4677b02b5aa272913a088/verl/trainer/config/engine/megatron.yaml">engine/megatron.yaml</a>确有TP、PP、CP、EP、ETP与distributed optimizer字段。本文下载文件是独立方案schema，不是该框架启动YAML；容器依赖、MCore adapter和全部组合未实测，不混写两个版本的启动参数。</p>

<h2>理解检查与下一步</h2>
<details><summary>LoRA参数少，为什么长上下文仍会OOM？</summary><p>冻结底座仍参与前向；adapter梯度可能穿过冻结层反传，激活、Attention中间状态、logits和临时buffer不随可训练参数同比减少。</p></details>
<details><summary>512卡、CP2、EP8时，为什么专家DP不是4？</summary><p>本版本普通层DP=32，但专家视角cp=1，重组DP×CP域；ETP=TP时专家DP=32×2/8=8。世界规模始终512。</p></details>
<details><summary>异步吞吐更高，就证明训练更好吗？</summary><p>还需同资源质量曲线、同推理预算终评、过期样本比例、训练 / 环境成本和失败记录。更多过期或不可验证轨迹可能增加token吞吐却降低有效更新。</p></details>
