架构、训练和服务共同约束

训练小 batch/长序列与服务高并发/decode 的瓶颈不同。MoE 的小专家在训练大 token 数时利用率较好，decode 的小 GEMM 和跨节点派发可能更难；递归状态减小持久历史，但树搜索要快照和分支；稀疏 indexer 减少读取，训练与服务的选择差异又可能影响 RL ratio。

Muon、mHC 或 FP4 都不独立定义整套方案。optimizer 分组、训练精度、checkpoint、rollout backend 和环境协议需要版本化。工业规模资源分配见训练集群设计；科学任务对照见SFT/RL 方案。

MTP、投机与 diffusion drafter 的收益边界

MTP 可以增加辅助预测/训练信号，投机服务则需要候选与目标验证；多预测头不自动让所有生成并行且无损。扩散 drafter 提出候选块，目标模型按规定验证，其质量和接受率影响实际收益。方法详细证据在DFlash → DSpark → AdaFlash维护。

精确采样需要对应 proposal/target 和接受/修正规则；greedy 一致性与随机采样分布一致性是不同条件。模型 forward 更少不一定减小请求延迟，drafter、验证、KV 和调度的成本都要计入。并发下 drafter 还可能占用原本可以服务目标模型的资源。

这些是基于机制的设计判断，不是新性能结论。公开 RNA-seq 子集只承担科学合同示例；足量训练数据要经过多研究来源审计、独立切分和验证，不能把一个小数据包当成大模型训练规模。

可解释的比较协议

把问题分成三层：机制消融固定主干、数据和参数/算力预算；同 checkpoint 服务比较固定精度、长度、并发与输出策略；端到端 Agent 比较固定任务、工具权限、verifier 和总执行预算。任何一层改多个因素，都需另列联合方案，避免声称单机制因果。
