历史保存、历史选择与计算实现分别优化什么

Attention 的查询仍是“当前位置读哪些历史表示”。MHA/MQA/GQA 改变 query 与 KV 的共享关系；MLA 压缩历史表示；SWA/稀疏检索限制读取集合；FlashAttention 改变精确计算的 IO；PagedAttention 改变状态分配。这些可以组合，但不产生同一种复杂度或质量保证。

先修：QKV 与 causal mask。本文 B 为并发序列数、T 为保存的历史 token 数、L 为采用该机制的层数、Hq/Hkv 为 query/KV heads、dh 为每个 K/V head 的宽度。K/V 宽度相同只是本节基础假设。

MHA、MQA、GQA：写入头和读取头可以不同

机制共享关系KV 存储/投影边界
MHAHkv=Hq，每个 query 对应一组 KV独立 KV 较多表达容量与内存都较大
MQAHkv=1，所有 query 共享一组 KVKV 存储显著减少query 仍多头；质量影响取决于训练
GQA1<Hkv<Hq，每组 query 共享 KV在 MHA/MQA 之间折中checkpoint 转换通常需 uptraining
MLA保存 latent KV 与位置相关分量，再恢复/吸收投影依 latent、RoPE 与实现算字节不能套用单一 Hkv 缩减比

MQA 和 GQA 原论文讨论了内存带宽与质量取舍，GQA 包含从 MHA checkpoint uptraining 的配方；它们没有证明任意模型减少 head 都无损。固定 Llama 源码中 Q 投影到 Hq·dh、K/V 投影到 Hkv·dh；eager 路径的 repeat_kv 为计算展开 head，不意味着持久缓存也必须保存展开后的副本。[2][8] L159–220

从形状推导缓存字节

M_KV = B × T × L × Hkv × (dK + dV) × bytes/value 若 dK=dV=dh：M_KV = 2 B T L Hkv dh b bytes/token/request = 2 L Hkv dh b 本文规划例：L=80，Hkv=8，dh=128，BF16 b=2 每 token = 327,680 B = 320 KiB；T=32,768 时每请求 = 10 GiB

上述数值由选定的形状算出，是容量例子，不是某个服务的峰值实测。它排除分页余量、allocator、workspace、临时激活、权重和跨设备复制。TP 理想分片可减少每 rank 的份额，但 Hkv 小于 TP 时可能复制 KV head；必须检查后端布局。

长上下文不同机制要逐层加总：full KV 随 T 增长，SWA 可按实现截到 window，recursive state 按 state shape 算；训练 SWA 并不保证服务只分配 window 大小。量化还要加 scale、零点、对齐和高精度例外。容量表和完整预算见部署第03章。

MLA 的关键是保存比完整多头 KV 更窄的 latent；RoPE 的位置相关部分常需单独处理，以免破坏投影吸收。DeepSeek V4.1 又使用 CED、CSA2 与缓存共享，其报告的 890 B/token 属于特定压缩/组共享口径，不是所有 MLA 的常数。V4.1 分项推导与排除项保留为具体案例。

RoPE 让内积包含相对位移

二维分量：R(pθ)[x₁,x₂]ᵀ = [cos(pθ)x₁ − sin(pθ)x₂, sin(pθ)x₁ + cos(pθ)x₂]ᵀ q'_i = R(i)q_i，k'_j = R(j)k_j (q'_i)ᵀk'_j = q_iᵀ R(j−i) k_j

旋转本身编码绝对位置，QK 内积中的相对旋转取决于 j−i。多频率二维对子让模型处理不同距离；通常作用于 Q/K，不能笼统说把位置向量加到所有输入。不同实现的 interleaving、partial rotary、频率与 scaling 必须与 checkpoint 一致。[3]

把最大位置调大只允许计算更长位置；未见过的频率/距离仍会产生分布变化。插值、频率缩放与长上下文训练解决不同问题。长上下文验收应包含位置敏感检索、多针冲突、依赖链和真实任务，不能只用一个 needle 成功率证明普遍能力。

Cache position 与逻辑 position 为什么要分开？

cache_position 决定状态写到哪里，position_ids 决定位置编码。padding、prefix 复用、分页、截断和 SWA 可能使物理槽位与逻辑位置不同。复用相同 token prefix 还要求 position、mask、adapter、权重和精度兼容。

局部窗口与稀疏检索改变可见历史

路线每步主要读取保留什么需验证的能力
Full attention所有允许历史通常完整 KV精确多项召回与 O(T) decode 访问
SWA附近 window局部 KV；可能另有全局层/sink远程信息能否通过混合层传递
稀疏 indexer选出的 top-k 历史/压缩块候选索引与被查询表示indexer 漏召回、选择成本与梯度
压缩历史摘要/latent/压缩块压缩 state 或 KV不可逆信息损失与恢复机制

少读历史不等于少存历史；索引仍可能依赖完整候选状态。局部层与全局层交替也不能简单按局部比例推算端到端速度。新架构的 indexer、压缩组与层计划应回到固定模型配置，分别核算。

FlashAttention 和 PagedAttention 的优化对象

FlashAttention 通过分块和 online softmax 在 SRAM 中累积输出，避免将大规模 score/概率矩阵反复写入 HBM；原算法保留 dense softmax attention 的数学计算。它没有把 full attention 变成线性计算，也不能自动缩小所有 KV。不同融合顺序与浮点格式仍可能导致数值差异。[4]

PagedAttention 把逻辑 KV 映射到非连续物理块，改善变长请求的碎片与共享；prefix cache 再复用兼容前缀的计算。存储分页不改变 causal mask，命中前缀也没有降低从零 prefill 的内在计算。具体 vLLM/SGLang 调度和源码在部署第01章维护。

判断一个“提速”：先写清它改变的是算术次数、HBM IO、持久状态、物理碎片、共享命中、网络传输还是调度等待，再比较相同模型、精度、长度和负载。

对照方案与自测

本文建议：固定 checkpoint 时先比较 full forward/KV 解码的一致性，再测同长度同并发的 TTFT、ITL 和峰值内存。改变 MHA/GQA 或窗口属于结构变更，应单独训练或使用有依据的转换配方；不可把未适配模型的质量下降当成机制本身上限。所有这些对照尚未执行。

自测：为什么 GQA 省 KV，却不把全部 Attention 计算同比减少？

query head 仍有 Hq 个，每个仍要与允许的历史计算 score 并聚合 value。K/V 投影与保存量减少，读取可以共享，但 softmax/query 计算、输出投影与 FFN 仍存在；最终收益还受 kernel 和带宽限制。
