固定大小状态怎样保留不断增长的历史

完整 Attention 为历史保留可逐项访问的 KV；递归模型不断更新一个固定形状的状态，用它概括历史。后者可降低长序列 decode 的状态增长，但压缩与覆盖会影响精确召回。混合架构让不同层承担递推、局部访问与全局读取。

先修：Attention 与缓存。本章公式采用 S ∈ R^(dv×dk)、列向量 q/k/v；与第01章的行向量约定转置等价，不能混用乘法方向。GDN 原论文 §2–3 明确讨论更新和硬件并行。[7]

外积状态把历史聚合为关联矩阵

设 \(S_0=0\)，\(S\in\mathbb R^{d_v\times d_k}\)，q/k为 \(d_k\) 维列向量，v/o为 \(d_v\) 维。每步向状态加入value与key的外积，展开递推，再右乘当前query：

\[ S_t=S_{t-1}+v_tk_t^\top =\sum_{i=1}^t v_i k_i^\top,\qquad o_t=S_tq_t=\sum_{i=1}^t v_i(k_i^\top q_t). \]

这条式子省略feature map与归一，不等于softmax Attention。它用一个关联矩阵累积历史，查询时获得key匹配加权的value。

两条关联例：\(d_k=2,d_v=1\)，写入 \(k_1=(1,0)^\top,v_1=2\)，再写入 \(k_2=(0,1)^\top,v_2=3\)，状态成为[2,3]。query为 \((1,0)^\top\) 时读出2；query为 \((1,1)^\top\) 时读出5，权重没有softmax归一。

状态是多次外积的和；读 query 时通过 kᵀq 的匹配得到 value 组合。因为固定维度要承载越来越多关联，相似/非正交 key 会干扰。它没有保留每个 token 的原始 KV 列表，也不能无条件恢复所有细节。

\[ M_{\rm state}=\sum_{\ell}H_{{\rm state},\ell}d_{v,\ell}d_{k,\ell}b_\ell,\qquad M_{\rm KV}=\sum_{\ell}T H_{{\rm kv},\ell}(d_{K,\ell}+d_{V,\ell})b_\ell. \]

本例一个state只有2个值；若每值4B，则8B，与已处理token数无关。混合模型的卷积状态、Attention KV及其他缓存另计。

容量式对一条序列计：\(\ell\) 索引对应类型的层，\(H_{{\rm state},\ell}\) / \(H_{{\rm kv},\ell}\) 是状态头 / KV 头数，\(b_\ell\) 是每个元素的字节数，\(T\) 是保留的历史长度。\(d_{v,\ell},d_{k,\ell}\) 是状态两轴宽度，\(d_{V,\ell},d_{K,\ell}\) 是显式 KV 的宽度；两类层分别求和。

“状态不随 T 增长”指特定递归状态的持久大小；训练仍有按序列的激活/重计算，prefill 仍要处理每个 token。它不能推出无限上下文、训练 O(1) 显存或无损记忆。

遗忘控制与定向更新解决不同问题

符号：\(\alpha_t\) 是旧状态保留系数，\(\beta_t\) 是沿当前 key 方向的修正幅度；\(I\) 是 \(d_k\times d_k\) 单位矩阵。\(v_t-S_{t-1}k_t\) 是新值与旧预测的误差，\(\|k_t\|_2\) 是欧氏长度；下式 \(\prod\) 表示连续多步保留系数相乘。

\[ \begin{aligned} \text{遗忘外积：}\quad S_t&=\alpha_tS_{t-1}+v_tk_t^\top,\\ \text{delta：}\quad S_t&=S_{t-1}+\beta_t(v_t-S_{t-1}k_t)k_t^\top,\\ \text{gated delta：}\quad S_t&=\alpha_tS_{t-1} +\beta_t(v_t-\alpha_tS_{t-1}k_t)k_t^\top\\ &=\alpha_tS_{t-1}(I-\beta_tk_tk_t^\top)+\beta_tv_tk_t^\top. \end{aligned} \]

delta先读旧预测 \(S_{t-1}k_t\)，得到写入误差，再沿key方向修正。若 \(\|k_t\|=1,\beta_t=1\)，右乘同key可得 \(S_tk_t=v_t\)，即该关联被精确覆盖；key未归一时这条结论不直接成立。

覆盖例：沿用状态[2,3]，将第一个key的新值改为5。外积累加变成[7,3]；delta取 \(\beta=1\) 得[5,3]。gated delta再取 \(\alpha=0.5\)，先衰减为[1,1.5]，定向修正后得[5,1.5]：覆盖目标关联，同时遗忘另一关联。

\[ S_t=\alpha_tS_{t-1}+v_tk_t^\top \quad\Longrightarrow\quad S_t=\sum_{i=1}^t\left(\prod_{j=i+1}^t\alpha_j\right)v_i k_i^\top \quad(S_0=0). \]

展开后的乘积说明旧关联如何累计衰减；空乘积为1。真实模型的alpha/beta范围、key归一与向量gate以实现为准。

α 对旧状态整体衰减，便于快速清除；delta 先读取当前 key 关联的旧值，再朝新值修正，实现定向覆盖。GDN 把两者组合，原论文讨论了快速遗忘、精确修改与检索的互补。它们的报告实验是该模型规模/配方下的结果，不是所有工业任务上的普适排序。[7] GDN §2–4

KDA 等进一步细化 decay 的方向/粒度，需要检查 gate 是标量、向量还是其它结构；不能把所有“K”或“delta”变体写成同一递推。具体 Kimi/Qwen 配置与披露边界放在型号证据页。

Mamba 与 SSD 把状态更新组织成高效计算

在一般单步 SSM 中，设输入 \(x_t\in\mathbb R^{d_x}\)、状态 \(h_t\in\mathbb R^{n}\)、输出 \(y_t\in\mathbb R^{d_y}\)；\(\bar A_t\) 为 \(n\times n\) 状态转移，\(\bar B_t\) 为 \(n\times d_x\) 输入映射，\(C_t\) 为 \(d_y\times n\) 读出，\(D\) 为 \(d_y\times d_x\) 直连。横线表示离散化后的参数；工业实现可按通道组织结构化状态。

\[ h_t=\bar A_t h_{t-1}+\bar B_t x_t,\qquad y_t=C_t h_t+Dx_t. \]

一般离散SSM的状态由前态与当前输入共同更新；Mamba使部分参数依赖输入，选择保留与遗忘；Mamba-2/SSD联系递归与分块并行。标量教学例 \(h_0=0,\bar A=0.5,\bar B=C=1,D=0,x=[2,4]\) 得 \(h=[2,5]\)，第二步保留前一步一半。

Mamba 不只是普通 RNN 换名字：选择性参数和硬件算法让它适应语言等离散输入；Mamba-2 又以 SSD 提供结构化并行。原报告中的 kernel/层速度不是任意混合 LLM 的端到端收益。[7] Mamba、SSD

递推式有时间依赖，但训练并非只能 Python for-loop：chunkwise 算法以 chunk 的入状态、局部块计算和出状态组织 tensor-core 运算。GDN 还利用 WY 表示处理 delta 的依赖。更快 kernel 要连同 chunk 大小、状态读写、backward 和精度测量。

Agent 分支和换窗需要不同的恢复协议

树搜索/多采样要从同一 prefix 创建分支。Full KV 可在相容条件下共享前缀页，递归模型则要保存分支起点的状态快照，局部卷积状态也要一致。发生截断或摘要换窗后，重新 prefill 摘要得到的状态与继续完整历史的状态不同；两者不能声称无损等价。

完整恢复算例：同一前缀怎样生成两个独立分支

输入与简化：沿用标量SSM，\(h_t=0.5h_{t-1}+x_t,\ y_t=h_t\)，\(h_0=0\)，前缀输入[2,4]。先算 \(h_1=2,h_2=5\)，冻结分支起点 \(h_{\rm prefix}=5\)。A续写输入6，B续写输入−2；这里的输入是教学数值，输出是该SSM的读出，不是完整LLM的词表预测。

执行路径恢复的入状态更新与当前输出
A：从前缀快照开始5\(0.5\times5+6=8.5\)
B：从同一快照独立开始5\(0.5\times5-2=0.5\)
错误：B接着A的可变状态运行8.5\(0.5\times8.5-2=2.25\)
B：重放完整前缀再继续重算得到50.5，与快照恢复一致

换窗：若从零只重放最后一个输入4，状态为4；再接A的6，读出8，与完整历史的8.5不同。摘要是新的输入，也没有天然的状态等价保证；KV和递归状态都必须对应实际输入历史。

换参数：将状态转移系数改为0.25，完整重放[2,4]应得到4.5，再接6读出7.125；直接复用旧状态5会得到7.25。即便保存了原token，也需要重算或一个明确的跨版本状态算法。单个标量快照只含一个数，真实混合block还需各层KV、卷积状态、位置与门控相关状态。

RL 权重更新使旧状态通常过期。每一生成段都应固定权重、router、mask、位置、adapter、精度与 kernel；跨版本恢复需有明确协议。恢复机制与 policy lag 连接Partial rollout 的分段交接。

自测：固定状态为什么不等于无限无损上下文？

固定维度要压缩无限增长的关联，非正交 key、覆盖和有限精度会损失信息；也没有逐项保留原文。能处理更长输入是计算能力，能可靠读取任意历史细节是另一个质量问题。
