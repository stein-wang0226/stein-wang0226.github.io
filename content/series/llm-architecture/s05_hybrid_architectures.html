固定大小状态怎样保留不断增长的历史

完整 Attention 为历史保留可逐项访问的 KV；递归模型不断更新一个固定形状的状态，用它概括历史。后者可降低长序列 decode 的状态增长，但压缩与覆盖会影响精确召回。混合架构让不同层承担递推、局部访问与全局读取。

先修：Attention 与缓存。本章公式采用 S ∈ R^(dv×dk)、列向量 q/k/v；与第01章的行向量约定转置等价，不能混用乘法方向。GDN 原论文 §2–3 明确讨论更新和硬件并行。[7]

外积状态把历史聚合为关联矩阵

S_t = S_(t−1) + v_t k_tᵀ o_t = S_t q_t = Σ_(i≤t) v_i (k_iᵀq_t) S ∈ R^(dv×dk)；k/q ∈ R^dk；v/o ∈ R^dv 此式省略 feature map、归一化及模型特定 gate，不等于 softmax Attention

状态是多次外积的和；读 query 时通过 kᵀq 的匹配得到 value 组合。因为固定维度要承载越来越多关联，相似/非正交 key 会干扰。它没有保留每个 token 的原始 KV 列表，也不能无条件恢复所有细节。

固定状态预算（单请求、仅该部分）： M_state = Σ_layers H_state × dv × dk × bytes/value Full KV 预算 = Σ_layers T × Hkv × (dK+dV) × bytes/value 递归模型还可能有 convolution state、Norm/gate、中间缓存和混合 Attention KV

“状态不随 T 增长”指特定递归状态的持久大小；训练仍有按序列的激活/重计算，prefill 仍要处理每个 token。它不能推出无限上下文、训练 O(1) 显存或无损记忆。

遗忘控制与定向更新解决不同问题

带遗忘外积：S_t = α_t S_(t−1) + v_t k_tᵀ Delta：S_t = S_(t−1) + β_t (v_t−S_(t−1)k_t)k_tᵀ Gated delta：S_t = α_t S_(t−1) + β_t (v_t−α_t S_(t−1)k_t)k_tᵀ 等价：α_t S_(t−1)(I−β_t k_t k_tᵀ) + β_t v_t k_tᵀ α/β 的范围、key 归一化与 gate 参数化由模型规定

α 对旧状态整体衰减，便于快速清除；delta 先读取当前 key 关联的旧值，再朝新值修正，实现定向覆盖。GDN 把两者组合，原论文讨论了快速遗忘、精确修改与检索的互补。它们的报告实验是该模型规模/配方下的结果，不是所有工业任务上的普适排序。[7] GDN §2–4

KDA 等进一步细化 decay 的方向/粒度，需要检查 gate 是标量、向量还是其它结构；不能把所有“K”或“delta”变体写成同一递推。具体 Kimi/Qwen 配置与披露边界放在型号证据页。

Mamba 与 SSD 把状态更新组织成高效计算

一般离散状态空间：h_t = Ā_t h_(t−1) + B̄_t x_t y_t = C_t h_t + D x_t Mamba 使部分参数依赖输入，实现选择性传播/遗忘 Mamba-2 / SSD 利用结构化半可分矩阵联系递归与分块并行

Mamba 不只是普通 RNN 换名字：选择性参数和硬件算法让它适应语言等离散输入；Mamba-2 又以 SSD 提供结构化并行。原报告中的 kernel/层速度不是任意混合 LLM 的端到端收益。[7] Mamba、SSD

递推式有时间依赖，但训练并非只能 Python for-loop：chunkwise 算法以 chunk 的入状态、局部块计算和出状态组织 tensor-core 运算。GDN 还利用 WY 表示处理 delta 的依赖。更快 kernel 要连同 chunk 大小、状态读写、backward 和精度测量。

这些机制的“memory”对象不同。Engram 的模型内部查表/条件记忆不能直接当成会话文件；RAG 在外部检索知识再输入模型，长期 memory 还涉及筛选/巩固/权限。完整边界连接Codex memory与RAG。

Qwen、Kimi、Nemotron、MiniMax 等公开家族的 layer pattern、state 和专家路径由型号表维护。配置里的 pattern、共享层与真实 block 数可能不同，计算预算按实际层执行，不按宣传比例独立推算。

Agent 分支和换窗需要不同的恢复协议

树搜索/多采样要从同一 prefix 创建分支。Full KV 可在相容条件下共享前缀页，递归模型则要保存分支起点的状态快照，局部卷积状态也要一致。发生截断或摘要换窗后，重新 prefill 摘要得到的状态与继续完整历史的状态不同；两者不能声称无损等价。

RL 权重更新还使旧状态过期。rollout 版本、router、mask、位置、adapter、精度与 kernel 要冻结到 episode，跨版本恢复需有明确协议。恢复机制与 policy lag 连接异步 RL。

沿信息损失和真实预算设计对照

本文建议分开测试：单针/多针与关联冲突、长依赖、多跳组合、顺序重排、分支恢复、上下文超出训练长度。先固定参数/数据对比历史机制，再在等训练算力与同服务预算下比较混合层计划。记录 state+KV 总量、prefill/decode、任务质量和每个成功任务成本。

没有实测时不画模拟性能曲线。GDN、Mamba 报告展示特定实验中的效率与质量，跨家族 token/s 和 benchmark 分数不能直接归因给一个 state 机制。

自测：固定状态为什么不等于无限无损上下文？

固定维度要压缩无限增长的关联，非正交 key、覆盖和有限精度会损失信息；也没有逐项保留原文。能处理更长输入是计算能力，能可靠读取任意历史细节是另一个质量问题。
