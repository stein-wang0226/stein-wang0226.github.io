读式约定：单 token 的 \(x\) 是 \(d\) 维行向量，右乘投影矩阵；\(f\) 是 FFN 中间宽度，\(b_1,b_2\) 为偏置，\(\phi\) 为非线性激活，\(\sigma\) 为 sigmoid，\(\odot\) 为逐元素乘法。路由式中 \(e\) 索引专家，\(I\) 是选中专家的集合，\(g_e\) 是权重，\(E_e\) 是专家函数；\(E\) 表示专家总数，\(k\) 是每 token 选中数，shared 项为共享专家输出。

通道容量怎样变成稀疏计算

相关原论文 / 官方资料：Transformer。

FFN 在每个 token 的表示上执行非线性变换。MoE 把一组 FFN 换成多个专家，再由 router 选择少数参与当前 token 的计算。它扩大可存储的参数容量，同时控制激活计算；代价是路由、专家负载、派发通信和训练稳定性。

先修：block 与矩阵形状。基础 FFN 来源于 Transformer；门控变体见 GLU 原论文，稀疏训练工程用 Switch 作明确案例。[1][5]

两矩阵 FFN 与三矩阵 SwiGLU

相关原论文 / 官方资料：SwiGLU。

普通 FFN 的 \(W_1,W_2\) 是 \(d\times f,f\times d\) 权重，\(b_1,b_2\) 是 \(f,d\) 维偏置。SwiGLU 的 \(W_{\rm gate},W_{\rm up}\) 都为 \(d\times f\)，\(W_{\rm down}\) 为 \(f\times d\)；\(g(x),u(x)\) 是两个 \(f\) 维中间行向量。SiLU 式中 \(z\) 是激活输入，sigmoid 为 \(\sigma(z)=1/(1+e^{-z})\)，对向量逐元素应用。

\[ \begin{aligned} \operatorname{FFN}(x)&=\phi(xW_1+b_1)W_2+b_2,\\ W_1&\in\mathbb R^{d\times f},\quad W_2\in\mathbb R^{f\times d},\\ g(x)&=\operatorname{SiLU}(xW_{\rm gate}),\\ u(x)&=xW_{\rm up},\\ \operatorname{SwiGLU}(x)&=(g(x)\odot u(x))W_{\rm down},\\ \operatorname{SiLU}(z)&=z\sigma(z). \end{aligned} \]

忽略bias，普通FFN两矩阵各 \(df\) 个参数，总 \(2df\)；SwiGLU三矩阵总 \(3df\)。普通宽度取 \(4d\) 时为 \(8d^2\)，解 \(3df=8d^2\) 得等参数SwiGLU宽度 \(f=8d/3\)，实际还需硬件取整。

两个小例：\(d=6\) 时，普通 \(f=24\) 与SwiGLU \(f=16\) 都有288个矩阵参数。若gate投影为[0,1]，up投影为[2,3]，SiLU后逐项相乘得到[0,2.1932]，然后才由down投影回主干。它在通道上门控，不是在token之间交换信息。

gate 分支和 up 分支分别投影，元素乘积产生输入依赖的通道选择，再回到 hidden 维度。这里的 gate 是每 token 的通道门控，和 MoE router 的专家选择不同。固定 Llama 实现的 LlamaMLP.forward 正是 act(gate_proj(x))*up_proj(x) 后经 down_proj。[8] L143–156

如果只换非线性而保持 f 不变，参数和 GEMM 也变多；所谓“公平激活函数比较”需明确是否等参数、等 FLOPs 或等训练算力。现代专家宽度可能更细，还叠加共享专家与 latent 投影。

Router 决定 token 走向哪些专家

\(s\in\mathbb R^E\) 是 router 给当前 token 的专家分数向量，TopK 返回最高 \(k\) 个分数的专家索引集合 \(I\)。\(y\in\mathbb R^d\) 是恢复到主干的输出，\(E_e(x)\) 和 \(E_{\rm shared}(x)\) 都是同维专家输出；\(g_e(x)\) 是选中路径的标量权重。此抽象式尚未限定权重归一方法，下面的算例才固定为沿专家轴 softmax、选中后再归一。

\[ s=\operatorname{Router}(x),\quad I=\operatorname{TopK}(s),\qquad y=\sum_{e\in I}g_e(x)E_e(x)+E_{\rm shared}(x). \]

\(E_e\)为路由专家；共享路径是否存在、gate的softmax/sigmoid、top-k后归一以及选择bias是否参与输出，均由实现定义。下面固定这些选择，把路由、输出、容量与通信接成同一批算例。

token-choice 路由让每个 token 选择专家，容易造成专家收到的 token 数不均。专家数量 E、top-k、宽度 f、共享专家、层计划共同决定容量；“总参数 1T、激活 30B”并未描述 KV、router、通信、输出头或投机模块。

top-k 是可微的吗？

离散选择本身通常不对所有候选传播普通连续梯度；选中路径的 gate 和专家参与训练，router 还可从辅助目标获得梯度。不同 straight-through、soft routing、loss-free balancing 的处理不相同。不能因为选择离散就说 router 完全不学习。

完整路由算例：四个 token 怎样派发并恢复输出

输入与简化：四个二维行向量 \(x_A=(1,0),x_B=(0,1),x_C=(1,1),x_D=(2,0)\)，A–D 是 token 身份标签，不是矩阵或维度；三个专家、top-2，专家编号为1–3。\(W_r\in\mathbb R^{2\times3}\) 是本例路由权重，log 是自然对数；router 先沿三个专家做 softmax，再将选中权重重新归一化。为看清派发与加权，专家简化为 \(E_1(x)=x,E_2(x)=2x,E_3(x)=3x\)，共享输出取0；真实专家的 SwiGLU 已在上一节展开。本例先执行 dropless 路径，不是任何模型的训练配置。

\[ W_r=\begin{pmatrix}\log4&\log2&0\\0&\log4&\log2\end{pmatrix}, \qquad s=xW_r. \]

\(W_r\) 是 \(2\times3\) 路由矩阵，log 为自然对数。对A，\(\exp(s)=(4,2,1)\)，softmax 得 \((4/7,2/7,1/7)\)；选择专家1、2后除以 \(6/7\)，得到权重 \(2/3,1/3\)。表中其余行按同一规则计算，选中顺序按分数从大到小。

路由计算 → 专家 assignment → 恢复 token 顺序
输入\(\exp(s)\)路由分数的指数 exp(s)选中专家 / 权重加权输出 \(y\)
A：(1,0)(4,2,1)1：2/3；2：1/3\((2/3)x_A+(1/3)2x_A=(4/3,0)\)
B：(0,1)(1,4,2)2：2/3；3：1/3\((2/3)2x_B+(1/3)3x_B=(0,7/3)\)
C：(1,1)(4,8,2)2：2/3；1：1/3\((2/3)2x_C+(1/3)x_C=(5/3,5/3)\)
D：(2,0)(16,4,1)1：4/5；2：1/5\((4/5)x_D+(1/5)2x_D=(12/5,0)\)

容量检查：四个 token 产生八条 assignment，专家负载为[3,4,1]。这里 \(N=4\) 是本批 token 数、\(k=2\) 是每 token 的选中数、\(E=3\) 是专家数，\(c\) 是无单位容量系数，\(C_{\rm slot}\) 是每专家 assignment 槽位数，\(\lceil\cdot\rceil\) 表示向上取整。若另采用 \(c=1\)，则 \(C_{\rm slot}=\lceil cNk/E\rceil=\lceil8/3\rceil=3\)，专家2溢出一条。假设按A→D顺序丢掉D到专家2的路径且不重新归一，D输出变成 \((4/5)x_D=(8/5,0)\)，与 dropless 的 \((12/5,0)\) 不同。若重新归一或转路由，又是另一种结果。空闲专家的槽位不会自动补给忙碌专家。

通信检查：设rank 0持有token A,C和专家1、2，rank 1持有token B,D和专家3。dropless时，B→专家2、D→专家1、D→专家2三条路径跨rank；每条发送二维BF16向量，纯dispatch payload为 \(3\times2\times2=12\) B，combine同形状另12 B。24 B仅为两个方向的表示数据，排除gate/索引元数据、对齐、协议与反向通信；本地assignment不计网络传输。这也说明通信量取决于token和专家的放置。

负载与容量既影响效率，也影响学习机会

机制主要目的需记录的副作用
Auxiliary balance loss鼓励分派数量与概率均衡权重可能与任务 loss 冲突，局部/batch/全局口径不同
Capacity factor限制每专家接收量，规划 bufferoverflow/drop/pad 策略可能改变哪些 token 真正学习
Dropless dispatch尽量不丢 token assignment不均衡仍造成显存和时间长尾
路由 bias / loss-free balancing通过选择偏置调节分派bias 更新速度、统计窗口、训练/服务一致性

Switch 的 top-1、capacity 与 selective precision 是特定训练方案；现代 top-k、多共享专家和动态派发不能照搬全部参数。[5] Switch 若模型按领域过度集中到少数专家，短期质量与长期利用率可能呈现不同关系；只看平均 token 数会漏掉峰值和不活跃专家。

上面的完整算例已显示：均匀平均负载不能保证峰值不溢出，丢弃一条路径还会改变对应token的输出。容量公式中的分子要计入top-k产生的assignment数；具体取整和跨rank统计口径仍由实现定义。

  • 学习：按层/域查看assignment、gate entropy、梯度和overflow。
  • 效率：看最忙专家、GEMM利用率和通信P95；平均均衡可能掩盖峰值。
  • 一致性：训练与rollout的router、精度和选择偏置需兼容。

总参数、激活参数与通信分别算账

\(P_{\rm expert}\) 是所有路由专家的矩阵参数元素数，\(P_{\rm active,routed}\) 是单 token 选中专家的参数元素数；均假设每专家是宽 \(f\)、输入输出宽 \(d\) 的三矩阵 SwiGLU，排除 bias。\(D_{\rm dispatch}\) 是一次派发的单向 payload 字节，\(N_{\rm remote\ assignments}\) 计跨设备路径数，\(d_{\rm sent}\) 是每路径发送的表示元素数，\(b\) 是 byte/元素。

\[ P_{\rm expert}=3Edf,\qquad P_{\rm active,routed}=3kdf,\qquad D_{\rm dispatch}\approx N_{\rm remote\ assignments}\,d_{\rm sent}\,b. \]

总模型还要加shared、router、Attention和输出头；激活参数只是本token参与的矩阵。派发式表示单向payload，combine另计；远端分派数、表示宽度 \(d_{\rm sent}\)、元数据和布局决定通信量。

所有专家权重仍需存储并分布到设备；top-k 小不意味着整个模型能装入单卡。专家训练状态可按专家 DP 分片，非专家参数按普通 DP 管理。dispatch/combine 要传表示和元数据，网络拓扑、负载偏斜与 overlap 决定实际时间。

若固定总参数增加 E 并缩小单专家，激活 FLOPs 可能下降，但更小的 GEMM 未必更快；若固定激活计算增大 E，权重容量和 checkpoint IO 增加。两类设计要分开对照。

LatentMoE 把专家工作空间缩窄

此处 \(r\) 是 latent 宽度，\(z\) 是 \(r\) 维行向量；可训练 \(P_{\rm down},P_{\rm up}\) 的形状分别为 \(d\times r,r\times d\)。\(E_e(z)\) 改为在 latent 空间输入输出 \(r\) 维，\(y_{\rm routed}\) 是还原到 \(d\) 维的路由支路输出；\(\sum_e\) 仅累加选中专家（或等价地令未选中的 \(g_e=0\)）。\(P_{\rm projection}\) 是两组投影的参数元素数，这里的 \(P\) 前缀不表示概率。

\[ z=xP_{\rm down}\in\mathbb R^r,\quad r<d,\qquad y_{\rm routed}=\left[\sum_e g_eE_e(z)\right]P_{\rm up},\quad P_{\rm projection}\approx2dr. \]

共享/Norm路径另按模型相加；若实际派发latent，通信表示宽度才从 \(d\) 变为 \(r\)。投影省下的专家维度同时带来信息压缩，不能只按 \(r/d\) 宣称整体提速。

可把节省的维度用于更多专家或新宽度，但投影、共享路径和 router 仍有成本。router 读 hidden 还是 latent、投影后 Norm 和 gate 的顺序，必须看对应实现。Nemotron 与 Kimi 的不同规格及稳定化证据集中在LatentMoE 案例，不把维度缩减率改写成整体吞吐收益。

EP 与其它并行维度的组合

相关原论文 / 官方资料：Megatron-LM；Megatron Core。

TP 拆矩阵，EP 分布专家，DP 复制并同步参数，PP 分配层，CP 分担长序列；进程组可以重叠/重新组织。Megatron 的 expert DP 与普通 DP 关系有明确实现约束，EP 不总是再乘一次 world size。大型 MoE 的工业配置在训练方法章与集群对照章统一解释。

服务 decode 每步 token 少，专家负载和小 GEMM 可能更敏感；prefill token 多、CP/TP 与派发策略又不同。训练快的 EP 配置不能直接认定是低延迟服务的最优方案。

消融与常见失败

问题本文建议的对照不可省略
更多专家是否有效固定激活 FLOPs，再改变 E；另做固定总参数实验loss、各域质量、总算力、实际 wall time
Latent 是否损失信息先固定 E/k，仅改 r；再评估容量再分配投影、payload、梯度与长尾质量
训练/rollout 概率偏差固定权重与输入，比 routing、logprob 和精度版本、随机性、mask、router replay

这些是待执行研究设计。失败包括专家塌缩、overflow 丢学习目标、跨节点通信主导、小 batch GEMM 低效和低精度 router 选择不稳定。对 Agent RL，选择偏差可累积在长轨迹的重要性比率中，见后训练主题的Agentic RL对照。

自测：为什么“激活参数少”不能独立预测延迟？

它只近似一部分矩阵计算；权重读写、专家派发、负载尾部、KV、kernel 利用率、共享路径和请求调度都影响时间。不同层和阶段的瓶颈也不相同。
