模型架构之外，还要理解信息传递和更新方式

从上一章的模型家族里抽出可复用机制：残差怎样传信息、专家在哪个空间计算、矩阵怎样更新、哪些对象可以低精度、推理深度怎样增加。它们与Attention、数据和后训练协作，各自有不同的消融与成本。

阅读原则：沿张量对象辨别机制。AttnRes选择深度上的表示，mHC混合并约束残差流，LatentMoE下投影专家工作空间，Muon近似正交化更新矩阵，FP4改变特定数值对象，recurrent depth重复执行共享权重。一个名字不能代替完整训练配方。

截止2026-11-14，公式用于解释原论文机制，数值为来源规格或明确推导；本站未训练、复现或执行本章实验。完整模型与版本表见第06章，引用见统一索引。

从固定残差累加，到选择深度与混合残差流

普通pre-norm残差可简写为x_(l+1)=x_l+F_l(Norm(x_l))。它为信号提供短路径，但更深模型中的表示会沿固定累加路径混合。AttnRes、mHC和GR分别改变“怎样读取过去层”和“怎样在多路流之间传递”，不能都称为同一种residual attention。

Attention Residuals：Attention轴在深度上

AttnRes为当前层设置可学习query，从前面层的表示得到归一化key，再用softmax权重读取这些表示。对同一token位置，概念式如下；它选择的是前层表示，没有替代序列中的token Attention。[60]

a_(l,i) = softmax over i < l [ q_lᵀ RMSNorm(h_i) ] input_l = Σ_(i<l) a_(l,i) h_i F_l reads input_l; h_i denotes the available previous representations attention axis = depth / previous blocks, not token position

Full AttnRes需要管理更多历史层表示。Block AttnRes把层分组，读取完成block的summary与当前block的局部累积，减少状态与访问压力；Kimi K3采用该方向。理论的信息选择收益必须连同activation保存、重算、融合kernel和pipeline通信评估。[60] [5] §2.2

mHC：约束多路残差的混合矩阵

令X_l ∈ R^(n×d)表示n路残差。Hyper-Connections用pre映射汇入当前模块，再将模块输出分发回多路流，同时用res映射混合已有流。mHC把res矩阵约束到Birkhoff多面体，近似通过Sinkhorn行列归一化得到。[61] §3

X_(l+1) = H_l^res X_l + H_l^post F_l(H_l^pre X_l) Birkhoff constraint: H_ij ≥ 0, H 1 = 1, Hᵀ 1 = 1 ideal residual mixing: ||H||₂ ≤ 1; products remain doubly stochastic implemented Sinkhorn iterations approximate this constraint

理想双随机矩阵是置换矩阵的凸组合，其谱范数不超过1，乘积仍双随机；这是residual mixing部分的性质。实际20轮Sinkhorn是近似，带非线性F及pre / post更新的整个网络没有因此获得无条件稳定证明。应监控约束残差、gradient norm及失稳频率，不能把数学性质扩大成全训练保证。

DeepSeek V4.1使用n=4的Single-Pass mHC，复用上一block的A，将报告定义的activation traffic从20d降到10d；这是该映射流量减少50%，不是完整训练时间减半。GLM-5.3配置也采用mHC，但不能直接继承DeepSeek的kernel数值。[1] §2.4.1 [53]

Qwen GR：读4路流的元素门控

Qwen3.8的Gated Residual把残差流扩为4路，通过elementwise gate读取；gate沿通道工作。它与mHC的行列约束、AttnRes的跨深度softmax具有不同参数化、状态和数值路径。应依据原报告的融合与消融比较，不凭“四路”认定三者相同。[45]

LatentMoE：减少专家工作维度，容纳更细的专家

传统MoE在hidden空间dispatch token并执行多个FFN。LatentMoE先将表示下投影到较窄latent，再完成路由专家计算并上投影回来。节约的维度可重新用于更多专家或不同宽度；因此需要同时说明hidden、latent、expert intermediate、top-k与共享专家。[51]

z = P_down x y = P_up [ Σ_(e∈TopK(router(x))) g_e E_e(z) ] + shared_path(x) x ∈ R^d, z ∈ R^r, r < d conceptual routed path; normalization, gates and shared paths depend on model

这里将router表示为读取x；具体实现的router输入、归一化顺序和shared路径必须查对应模型，不能用此概念式替代源码。缩小dispatch表示能减少一部分通信，但上下投影、gather、负载平衡和专家内部GEMM也加入成本。

不同家族的top-k和专家数同时变化，不能把上述维度比直接用于跨模型速度排名。EP跨设备带宽、token偏斜与尾部等待也可能改变瓶颈。与已有分布式训练指南连接时，应分开记录TP、EP、DP、dispatch和combine。

Muon：近似正交化的是更新矩阵

Muon先对矩阵梯度累积动量，再用polar / semi-orthogonal近似获得更新方向。理想SVD表达是M=UΣVᵀ → UVᵀ；实际大规模实现常用Newton–Schulz或其他近似迭代，避免完整SVD。[62]

M_t = μ M_(t−1) + G_t ideal: M_t = U Σ Vᵀ → O_t = U Vᵀ W_(t+1) = W_t − η_t · scale(shape, recipe) · O_t semi-orthogonal O_t: OᵀO = I or OOᵀ = I for a full-rank rectangular matrix actual implementations use approximate iterations, often with Nesterov / decay variants

Muon改变更新的奇异值结构；模型权重W没有被永久约束为正交矩阵。矩形尺寸、近似阶数、scale、学习率、weight decay和Nesterov细节各有版本，不能拿这行概念公式冒充所有训练代码。

按head或逻辑投影拆开有明确目的：不同功能、尺度与形状不应因物理存储融合而被当作同一个更新对象。embedding、output head、router、bias与Norm也具有不同形状和统计；要保存参数分组及优化器状态，才能解释切换配方的效果。

分布式训练：本地切片不一定等于全矩阵更新

polar近似依赖矩阵乘积。对完整梯度矩阵应用Muon，通常不等于对各TP / FSDP切片分别应用后再拼接。实现需要明确gather / shard边界、动量所有权、orthogonalization计算位置和通信量。checkpoint恢复时优化器状态与矩阵分组也必须一致。[62]

有意义的对照应报告等token和等算力两种预算、validation loss、任务质量、optimizer step时间、额外通信及失稳恢复成本。只比较固定step数，会混入吞吐差异；只比较loss下降，也会漏掉执行预算。

FP4格式不仅是4bit value，还包括scale、block分组和高精度例外。以DeepSeek主KV为例，512channels的E2M1值占256B，16值一个8bit scale再加32B；indexer的128channels另为64+4B。第03章的890B/token还叠加跨层缓存组与压缩比，不能从“4bit”独立推导总预算。逐项推导与排除项。

同样，NVFP4和OCP MXFP4的scale层级与格式不同；权重、激活、梯度、KV和optimizer迭代分别登记。低精度验证应包含loss与真实任务、重尾样本、长上下文、router / gate稳定性、峰值内存及训练恢复。

Recurrent depth：推理预算也可以放进潜在计算

Huginn的公开研究采用共享权重的recurrent depth：先得到token表示，再让同一个核心模块在潜在状态上迭代，最后输出token分布。推理时改变迭代次数，把更多算力用于token内部计算。[64]

h^(0) = Pre(input) h^(j+1) = Core_θ(h^(j), input), j = 0 … K−1 logits = Post(h^(K)) K controls executed depth; θ is shared across recurrent iterations conceptual form; exact state injection / normalization follow the model
增加算力的方式重复的对象可观察的代价
更长Chain-of-Thought生成更多可见token输出长度、KV、decode时间和语义步骤
Recurrent depth共享权重core对潜在状态多次执行每token执行深度、state / cache设计、收敛与停止规则
多采样 / 投机多个候选轨迹或drafter + verifier样本预算、并行资源、接受率和验证成本
Harness重试 / 换窗工具调用、模型请求与上下文装配环境时间、摘要损失、checkpoint与任务恢复

这是一条可分析的公开研究路线，不能凭闭源Agent的换窗或memory行为推断GPT采用这种模型结构。递归深度也不自动带来单调增益：训练时的迭代分布、测试时外推、潜在状态稳定性和停止条件都需测量。

连接Agentic RL：架构改变的是哪些训练条件

模型更新、rollout服务和工具环境一起决定Agentic RL吞吐。混合递归状态影响prefix复用和多分支快照；稀疏indexer、量化kernel和MoE routing可能让rollout与trainer存在实现差异；Muon改变参数分组和更新成本。它们需要接入已经讨论的异步RL与版本对齐，而不是把服务tokens/s直接当学习效率。
