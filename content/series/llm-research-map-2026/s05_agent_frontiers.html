从工具调用走向可验证的场景能力

GUI和科学Agent值得成为正式研究专题：两者都有长程状态、可恢复执行和多层验收，直接连接本站作者的GUI研究、Harbor科学任务合成与ProtAgent。Skills、memory、参数更新则提供三种不同的适配层，不能用一个“自我改进”概念代替实验。

GUI：从单次点击准确率到长程恢复

OSWorld 2.0项目合作方介绍108个长程任务、31个自托管网站及150 / 300 / 500 step budgets。Binary success与partial score应在同一版本、同一步数预算下比较；评价最终状态，不能强制所有策略复刻唯一点击序列。以上是合作方公开口径，本地未复现。[42]

研究问题具体机制应保留的证据
Observation / grounding屏幕、可访问性树、坐标、窗口焦点和延迟；不同工具提供不同信息观察时间、动作前后状态、权限和可见范围
长程规划任务分解、里程碑、状态压缩与预算分配各步骤真实进展、遗忘 / 循环、上下文压缩后的状态缺失
恢复与回退误点击、弹窗、登录状态、焦点错误和部分提交后的恢复错误类型、可重试性、恢复成功率、额外步数与风险
验收与复现重置环境、固定网站、终态检查与部分完成标准环境 / grader版本、预算、终态产物、基础设施失败

与CUA-Recovery公开项目相连时，可讲清失败分类和恢复流程；内部环境、未公开规模和未授权结果不放进文章。固定任务与scaffold后比较恢复模块，不能把工具权限或步数增加的收益归因于算法。

科学Agent：能运行、能提交、能支持结论是三层能力

AIRS-Bench采用20个research tasks，以problem / dataset / metric定义任务，报告valid submission、normalized performance与不同scaffold。ProgramGym强调程序复现环境；两者共同提醒：文件存在、脚本退出码为0、报告流畅都不是完整科研验收。[27] [10]

层检查典型失败
执行正确依赖、seed、资源、输入版本、脚本和产物未读真实数据、硬编码、GPU / 网络故障、无法重跑
提交有效schema、指标实现、split、数值有限性与复现路径测试泄漏、错指标、错误join或未按要求提交
科学支持假设、对照、统计不确定性、方法适用条件与证据来源把相关性说成因果、重复样本泄漏、只有成功实验、解释超出数据

科学任务的verifier通常是组合：确定性结构 / 数值检查 + 方法约束 + 专家或经校准的判断。自动judge应保留不确定 / 需人工复核状态，而不是强迫所有回答二元化。跨dataset、论文和任务族划分，避免同一生物样本或同源实验同时进入训练与评测。

作者方向可形成的公开长文：ProtAgent连接工具使用与step-level RL；Harbor科学任务合成连接环境与验证合同。文章应区分annotation coverage、任务reward和生物学正确性，指标含义以公开论文为准，不把coverage提高解释为所有预测已被证实。

一个具体GEO / SRA任务的公开案例应交付数据来源、版本、许可、预处理、任务指令、独立verifier、oracle、负对照和失败报告；合成流程与迁移一致性先看第01章。

Skills：把流程文件变成可测的干预

SkillsBench初版 2602.12670v1是86 tasks / 11 domains / 7 configurations；1.1官方发布是87 / 8 / 18 paired paper configurations。不要将初版任务数、新版分组和动态leaderboard拼成同一结果。[29] [41]

Curated skills在论文设置中的正效应，不意味着self-generated skills必然有效。Skill内容可能通过任务分解、代码模板、工具约束、默认检查改变行为；同时增加token、错误指令和版本依赖。应做paired no-skill / curated / self-generated比较，保留工具与预算一致。

Skill资产应记录评测问题
来源、版本、适用条件、依赖与权限任务变化后是否仍适用；是否意外调用更强工具
文本、代码、资源、校验流程与token开销收益来自更好步骤、预置解法还是更大上下文
训练 / 测试隔离、相似任务与人工整理过程是否泄漏答案、过拟合某题或把测试反馈写回skill
触发与未触发记录、失败与回退无关skill是否干扰；需要时是否真正读到 / 执行

Memory、harness、LoRA：持续学习应分层验收

Macaron-V1讨论冻结base、per-turn LoRA routing、模型–harness版本链以及memory / context / parameters的不同更新层。它报告的自改进设置提供方法路线，但长期compounding continual learning与collective intelligence仍是open question，不能写成已经证实的长期复利。[28]

更新层改变什么最少验收
Context / memory经验记录、状态摘要、检索与任务历史来源与时效、写入污染、相关性、删除 / 回退、token成本
Skills / harness工作流、工具、路由、观察和恢复策略固定模型的paired比较；冻结版本，排除权限扩大与测试泄漏
LoRA / model专家参数与routing；真正改变策略分布旧能力回归、专家冲突、版本与行为log-prob、任务时间顺序留出

持续学习实验需要时间线：在第t阶段只使用当时可获得的训练反馈，评估后续新任务与旧任务保留，并保存可回退版本。反复使用同一测试集优化memory / skill会失去独立评测含义；短期重复题收益不能代表长期新任务泛化。

Engram是模型内部条件参数记忆，KV是计算状态；两者与跨任务memory的边界见第03章。模型–harness同时更新时应留出单独和组合对照，否则无法知道收益来自哪里。

并行Agent与多教师：一个减少关键路径，一个整合能力

Kimi K2.5的PARL / Agent Swarm研究orchestrator与subagent分解。比较并行策略要同时报告critical-path wall time与总tokens / GPU / 工具成本，不能只数subagent数量；并行不消除依赖、重复工作与协调失败。[30]

MOPD在学生rollout状态上整合多教师能力；Nemotron Ultra和DeepSeek公开专家训练与OPD配方。这与推理时同时运行多个Agent不同：前者把教师行为整合进学生参数，后者用运行时协作换取能力或延迟。不同教师、logits范围与mask的结果不能合并成通用蒸馏结论。[25] [33] [1]

路线适合的问题应检查的代价
并行子Agent可分解、相对独立的搜索 / 执行 / 验证子任务关键路径、总成本、协调与重复、工具争用、失败恢复
专家路由 / LoRA不同任务分布需要不同策略，但共享base路由误差、切换状态、专家覆盖、部署与版本复杂度
多教师OPD希望统一学生保留多个专家能力教师冲突、学生状态覆盖、训练成本与通用能力回归
