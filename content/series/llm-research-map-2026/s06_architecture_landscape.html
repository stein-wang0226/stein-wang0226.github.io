06 · Architecture landscape · 2026-11-14

从单个模型案例，扩展到不同团队的架构选择

DeepSeek V4.1是一个具体案例，不能覆盖整个基模方向。本章把Qwen、Kimi、Nemotron、GLM、MiniMax、MiMo、Step及Gemma接到同一组问题：历史保存成什么、哪些层访问全局、专家在哪个维度计算、多模态如何进入主干，以及这些选择怎样影响真实任务成本。

先读三点：线性状态、压缩KV、稀疏检索、滑动窗口解决的是不同问题；“混合架构”必须展开到实际层计划；模型能力还取决于数据、训练和执行系统，不能从参数量或Attention名称推导榜单排名。

截止2026-11-14。公开规格以团队报告和固定模型配置为依据；没有同硬件、同精度、同工作负载的本站复现。第03章保留DeepSeek详细拆解，第07章解释残差、LatentMoE和优化器。七章引用共用71项来源索引。

先理解四条历史访问路径

稠密global Attention通常保存随长度N增长的KV；MLA改变每token的保存维度。GDN / KDA维护有限矩阵状态，递归decode状态大小不随N逐token增长，但训练仍要处理整条序列，混合global层仍有KV。DSA / QSA / MSA保留可检索历史，只让query读取候选；indexer、选block和gather本身仍有成本。SWA只直接读取窗口，跨层传播和global层决定远距离信息怎样进入结果。

GDN → KDA：从整体遗忘到按通道控制

采用Kimi Linear的张量方向，S ∈ R^(d_k×d_v)，输出为Sᵀq。普通线性累积把kvᵀ加入状态；delta rule用当前key所预测的value误差定向更新。GDN加入标量遗忘α；KDA把它扩展为按key通道的对角门控。[49] [48] §2–3

GDN: S_t = α_t (I − β_t k_t k_tᵀ) S_(t−1) + β_t k_t v_tᵀ KDA: S_t = (I − β_t k_t k_tᵀ) Diag(α_t) S_(t−1) + β_t k_t v_tᵀ read: o_t = S_tᵀ q_t state shape per head: d_k × d_v; gate and rank-one update are ordered

对角门控与rank-one矩阵一般不能交换顺序。有限状态也不能无损保留任意历史；论文与工业模型保留global层以加强直接检索。Kimi K3另把log-decay下界设为−5，并改进输出gate，使chunkwise计算更适合Tensor Core；这是特定数值范围设计，不意味着KDA变成softmax Attention。[5] §2.1

实际层数量：不要用一个“3:1”替代全部型号

Qwen：混合状态、稀疏global与主干外的容量

Qwen3.5-397B-A17B固定模型卡已经采用Gated DeltaNet与global Attention混合。Qwen3.8-Flash-Next进一步把问题拆成三部分：36个GDN层处理递归状态，12个global槽保留检索；CPT阶段把原full Attention替换为Qwen Sparse Attention（QSA）；用4路Gated Residual和另51B n-gram embedding表增加信息传递与条件容量。[71] [44–46]

机制来源描述理解时的边界
GDN + global48层：36 GDN、12 global槽递归层没有逐token global KV，不代表整个模型没有全局缓存
QSA压缩比4；indexer budget 2048；在CPT引入预算和压缩比不能直接换算成4倍端到端速度
Gated Residual残差扩为4路，elementwise gate读取与mHC双随机混合、AttnRes深度选择不是相同操作
N-gram表125B主模型之外51B，放在accelerator外容量与访问带宽分别计；不能只按125B估总参数存储

固定config仍用full_attention字符串标记global槽。读源码时必须继续追到实际模块与kernel，不能据此认定发布模型执行稠密Attention。完整报告还强调训练稳定性与效率消融；指标属于其设定的模型、预算和负载，不能移到别的家族。官方固定PDF封面日期2026-08-26，arXiv v1提交2026-08-31，两者分别登记。[45] [46]

适合学习的连接：先用Decoder张量流标出global KV，再替换一部分层为GDN；最后考虑GR和查表容量如何影响activation traffic、通信与参数放置。

Kimi：KDA、深度选择与Stable LatentMoE共同扩展

Kimi K3报告公开2.8T总参数、104B active、原生视觉及1M上下文。它并非只换Attention：KDA负责高效序列混合，周期Gated MLA提供global访问，Attention Residuals选择前层表示，Stable LatentMoE把专家计算放进更窄的latent空间。[5]

K3.1 Pro固定配置列出93层，即69 KDA + 24 Gated DSA；模型卡说明从K3的full-attention Gated MLA层改为Gated DSA。因此K3完整报告能解释基础机制，但K3.1当前global路径应引用新card/config。不能把K3实验表直接重命名为K3.1结果。[47]

结构具体公开设计要追问什么
KDA通道遗忘、lower-bounded log-decay、输出gate；与chunk算法共同设计状态恢复、多分支rollout、长历史检索怎样管理？
AttnRes沿深度选择此前表示，而非固定累加全部残差保存哪些block summary？选择与跨pipeline访问成本是多少？
Stable LatentMoEhidden 7168 → latent 3584；896 routed、top16、2 shared；RMSNorm、SiTU-GLU、Quantile Balancing通信维度和专家数同时变化，质量与负载是否匹配？
训练优化K3 Per-head Muon；K2使用MuonClip按head拆矩阵与QK clipping是不同措施，不能合并成一个名称

论文中“scaling efficiency”包含架构和配方的综合作用；不能称为KDA单模块的速度倍数。进一步推导见LatentMoE和Muon。

Nemotron：混合子模块、LatentMoE与训练稳定性

Nemotron 3 Ultra的550B / 55B主干混合Mamba、Attention和MoE。报告/配置中的108是这几类子模块的总计，不是108个与Kimi相同的Transformer block。LatentMoE把8192维表示下投影到2048，512个routed experts中选择22个，从专家内部计算与dispatch宽度两个方向调整成本。[33] §2 [50] [51]

报告的NVFP4应用于fprop / dgrad / wgrad中的大矩阵乘，保留部分高精度对象。更值得记录的反例是§2.7披露的后期训练不稳定：切换BF16并没有解决问题。因此“低精度训练成功”需要连同失败阶段、保护项和恢复策略阅读，不能推导全模型FP4或认为切回高精度总能恢复。[33] §2.7

MTP也要分训练与发布：预训练使用两个共享权重MTP头，released config为一个共享模块。支持1M与默认启用1M同样不同；固定config默认262144，模型卡提供更长上下文的额外设置。部署对照必须记录实际启用值。[50]

下载完整报告。架构之外，专家后训练与OPD怎样整合能力，可接到SFT / RFT章节；不能把后训练增益全归因于Mamba。

GLM：旧报告、新配置与独立服务测量分层阅读

GLM-5的技术报告以Agentic Engineering为目标，公开DSA、训练与长程Agent系统。GLM-5.3-Flash进一步采用KDA与DSA / MLA混合：320B / 18B，45层中34 KDA、11 global层；FFN侧是3 dense + 42 MoE，288 routed、top8、1 shared，并使用IndexPool4和mHC。[52] [53] [66]

Attention类型与FFN类型是两张层表。原GLM-5报告不能证明5.3每个新增结构；新模型卡/config负责当前规格，旧论文负责技术前序。

MiniMax：按GQA group选block的MSA

MiniMax Sparse Attention把长历史划分成block，让不同GQA group分别选择相关block再执行Attention。它保留可被query检索的历史；不是KDA那种有限递归状态，也不等同MLA的latent KV表示。[54] v2

M3.1-Flash公开428B / 23B、1M context，并将前三个full Attention层改为MSA；其MoE层分布仍保留前三个dense FFN。因此“前三层已经稀疏”需说明是在Attention侧，不能写成这三层FFN也变成MoE。[55]

加速数字的对象：MSA论文的109B、3T训练对照，以及H800上1M长度kernel的14.2× / 7.6×，不是428B M3.1完整Agent任务的端到端加速。论文的kernel、模型实验和新发布模型要分别标明。

值得展开的研究问题是group-specific候选是否减少共享检索的损失、选择器能否找到远距离关键信息，以及block gather是否适合实际硬件。比较时同时测候选召回、长上下文质量、indexer和Attention时间；没有这些量，单个稀疏率难以解释成本。

MiMo：局部 / 全局主干与扩散drafter共同设计

MiMo-V2.6 Pro为1.02T / 42B、70层（60 SWA + 10 GA），Flash为310B / 15B、48层（39 SWA + 9 GA）；两者窗口128、无shared experts。小窗口降低局部历史访问，global层补充远距离访问，但Pro / Flash的完整层表不同。[56]

其diffusion drafter有5层，在anchor之后预测7个token、窗口1024。这里的drafter是主模型之外的投机组件，不能把“7个token并行预测”写成主模型不再自回归，也不能省略验证成本。它与本站DFlash / DSpark / AdaFlash综述形成直接连接。第04章：投机验证与任务成本

训练阶段同样分工：预训练AdamW；mid-training将hidden矩阵切到Muown，embedding、head、router继续AdamW；MXFP4 QAT在mid-training引入。权重、激活、梯度及KV的精度是不同对象。公开蒸馏模型与RL代码也不等于Pro / Flash所有权重全部开放。[56]

这一家族特别适合研究同一主模型固定时，drafter、QAT与服务并发怎样改变接受长度和总成功成本；如果同时更换主干和后训练checkpoint，就只能评估系统整体。

Step：局部Attention、MTP与矩阵更新的数值细节

Step 3.5 Flash报告196B总量、11B active，SWA / Full为3:1、窗口512，并使用3个MTP模块。Step 3.7 Flash固定模型卡则给出约198B，包含196B文本与1.8B视觉、45层、256K上下文。[57] [58]

应同时保留“3.5训练报告”和“3.7当前配置”，不能用前者冒充后者单独完整报告。视觉分支还增加输入编码和token成本，仅比较文本active不足以解释GUI任务效率。

3.5报告给出实用的数值反例：Polar Express迭代在BF16中出现罕见outlier，把该迭代改到FP16后不再出现。范围应限定到这一正交化近似及其测试，不推广成所有模型矩阵采用FP16。Muon相关更新如何拆矩阵、选精度和分布式执行，见第07章。

Gemma 4：端侧、多模态和KV复用也是架构前沿

架构研究不能只围绕数百B或万亿参数。Gemma 4把E2B / E4B、12B、26B-A4B、31B放在不同部署目标下，采用Local / Global混合、KV sharing等设计，但型号例外很多，有效参数、总参数和MoE active也不能混作一个数。[59]

设计报告说明学习与比较问题
Local / Global4:1或5:1取决于型号局部窗口、global层数和目标上下文必须一起记录
KV sharing / global K=V减少部分重复状态；并非全部型号完全相同哪些层生成、哪些层复用？是否改变projection或质量？
12B encoder-free48×48×3图像patch、40ms音频块通过projection进入LLM省掉独立encoder后，主干承担什么输入建模成本？
端侧部署家族包含不同有效容量与结构显存、延迟、能耗、离线可用性与质量共同决定选择

“Gemma 4都没有encoder”是错误概括；encoder-free具体指12B路线。对GUI或移动Agent，截图与音频输入频率、token预算及恢复能力，可能比单次文本吞吐更影响使用体验。下载技术报告。

阅读和实验怎样形成可复用的结论

先按具体机制读原论文，再按完整模型读配方，最后按执行系统看工作负载。推荐顺序：GDN / Kimi Linear → Qwen与Kimi → LatentMoE / AttnRes / mHC → Nemotron与GLM → MSA、MiMo、Step、Gemma → DeepSeek专章回看缓存所有权。

待执行对照固定条件应交付的结果
历史访问同规模 / 数据 / token预算；改变局部、递归与global层计划检索与真实任务质量、state / KV内存、prefill / decode时间
多轮Agent服务同任务、harness、工具、checkpoint和生成预算；冷 / 热prefix、低 / 高并发成功率、P50/P95、prefix命中、state恢复、工具与队列时间、成功成本
MoE部署同权重 / 精度 / 服务实现；改变TP / EP / DP及token分布dispatch通信、专家负载、尾部延迟、显存与实际任务分数
