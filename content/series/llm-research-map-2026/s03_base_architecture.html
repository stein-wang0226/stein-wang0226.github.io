CED：长prompt主计算放在哪里

CED是Causal Encoder–Decoder。Encoder处理因果历史；Decoder的global KV由encoder末层hidden state经过projection得到，因此不必为每个长prompt位置完成传统上半模型的全部全局KV计算。Decode时新token仍通过encoder和decoder。[1] §2.2

学习时应把它接到已有Decoder张量流：普通decoder通常逐层保存自己的KV；CED先改变global KV来源，再通过跨层复用减少存储与重复计算。具体Q、KV、SWA和indexer的所有权要分开画。

张量来源：global C / Z 与本层 Q / SWA

Hidden维度为5120。Decoder的Full层从末层encoder表示 H₂₀生成global latent Cₗ = H₂₀ Wₗᴷⱽ 与压缩权重 Zₗ = H₂₀ Wₗᶻ；本层query和SWA KV仍由本层hidden产生。C / Z是压缩表示及其权重，不能画成传统独立K和V两份等长缓存。主Attention有64个query heads、512 channels，query compression维度1280；indexer有32个query heads、128 channels。[1] §2.2–2.3

CSA2：共享KV、重算索引和复用候选是三件事

层模式Global KV / indexer KTop-k候选仍由每层保留
Full产生本组共享的KV与indexer K执行索引与top-k选择本层Q与SWA KV
Reindex复用前面层的KV / indexer K重新计算top-k，按本层查询选择本层Q与SWA KV
Reuse复用KV / indexer K同时复用已有top-k本层Q与SWA KV

CSA2减少跨层冗余，但共享KV不等于所有层做相同Attention：各层仍有自己的query和局部SWA。Decoder的hierarchical indexing让后续索引在首层候选池内扫描，第一层仍需扫描全文，不能宣称所有indexing成本变成O(1)。[1] §2.3

分析算力时至少区分KV projection、候选检索、选中位置的Attention和SWA四部分；“稀疏Attention”一个标签不能说明总复杂度。实现性能还取决于候选大小、跨层计划、内存访问与kernel，而不只取决于理论乘加次数。

40层的实际计划

Hierarchical indexer：先选block，再在池内重排

在decode中的decoder，首个Full仍对全局历史扫描，把位置按8个一组组成block，按block内最高indexer score筛出最多2048组，得到最多16384位置的候选池。后续4个Reindex按各层query在该池内选top-512；Reuse沿用所选位置。SWA独立处理最近128位置。首扫描仍随历史N增长；后层扫描受候选池上限约束，不能把整体写成O(1)。这一decode优化在post-training引入，报告强调训练与推理采用一致流程。[1] §2.3.2

first global scan: O(N) candidate pool ≤ 2048 blocks × 8 positions = 16384 later Reindex: select 512 from this pool; Reuse: no new index selection

890 bytes/token究竟包括什么

存储 / 成本对象V4.1报告口径阅读边界
HBM中的global KV摘要约890 bytes/token，约V4-Flash的1/4；§2.4含FP4主KV不是模型权重，不是总显存，也不包含全部SWA和临时计算
Persistent cacheSSD / host缓存约前序的1/8；结合局部状态重建不同存储层口径，不能和HBM 1/4相乘成“总显存1/32”
SWA局部KV各层自己的窗口状态，decoder需尾部replay窗口与层数成本仍存在；小global KV不代表局部缓存消失
Weights / Engram / workspace独立的参数、放置、通信和临时内存不能从KV字节推算模型完整部署容量

以上固定到报告摘要、§2.4、§3.2。FP4是精度 / 存储设计的一环；压缩后的KV访问与反量化也有计算和带宽成本，需要实际profile。[1]

FP4格式：主KV与indexer用不同scale

对象数值 / scale规格每entry规格字节量化与使用
Main KV，512 channelsE2M1 4-bit；每16值一个E4M3 8-bit scale512÷2 + 512÷16 = 288 BRoPE后量化；post-training QAT；读出反量化。省略标准NVFP4的第二级全局scale
Indexer K，128 channelsOCP MXFP4：E2M1；每32值一个E8M0 8-bit scale128÷2 + 128÷32 = 68 B格式与主KV不同，不能一律按16值scale计费
SWA局部KVFP8另计，未加入890 B/token窗口128，仍有各层state及重建成本

本节讲KV存储。不能据此声称全模型权重、GEMM或所有激活已变成FP4。NVIDIA标准NVFP4还使用per-tensor FP32 scale；DeepSeek省略该级，布局并非完全相同。格式补充来源：OCP MX v1.0规范、NVIDIA NVFP4格式说明（2025-06-24）。

890 B/token的逐项推导

main + indexer = 288 + 68 = 356 B/entry encoder: 3 cache groups × (1 entry / 2 tokens) = 1.5 entries/token decoder: 1 shared cache × (1 entry / token) = 1 entry/token global total = (1.5 + 1) × 356 = 890 B/token

Bounded replay：用计算换存储

持久缓存可以保留更紧凑的global表示，恢复时重跑尾部以近似重建decoder局部状态。§3.2.2报告其质量影响小，但这是bounded replay的近似storage–compute trade-off，不能称为bit-exact重建。

重放对象触发与输入写入 / 保留状态恢复边界
Encoder SWAglobal cache命中、SWA未命中；重放cached prefix最后128 tokens只补SWA，不覆盖已缓存global；uncached suffix产生global及SWA。短TTL host池仍使用约10% host DRAM保留encoder SWA逐层exact恢复的依赖范围理论上L×W；实际只重放W
Decoder SWA每次prefill，取最后128位置encoder outputs过decoder得到decode用SWA；从不作为prefix cache长期保存理论依赖L_dec×W；实际bounded replay为W，同样是近似状态

对多轮Agent，缓存命中后往往只有短工具返回，却仍要恢复局部状态；长输入、短输出与大量轮次下，replay、host / SSD IO和排队可能成为显著成本。长prompt的单次prefill加速不能直接替代端到端Agent实验。

T_episode ≈ Σ_turn (T_prefill_new + T_cache_IO + T_replay + T_decode + T_tool + T_queue)

这是观测项的概念分解；实际系统可能重叠计算、IO和工具等待，不能把重叠span直接累加。计费去重见第01章。

Engram和Agent memory分别更新什么

Engram采用N-gram hashing与context-aware gating，把条件查表记忆引入参数稀疏性。它并非自动记录过去任务的episodic memory，也不是外部RAG系统。V4.1单列196B Engram，让参数总量和每token活跃计算进一步分离。[3] [1]

“记忆”形式所在层与内容典型更新 / 失效方式
Engram条件参数模型内部的可学习查表与门控训练更新；部署成本包含参数存储与访问
KV / prefix cache特定权重、token历史和实现下的中间状态生成时写入；版本或计算条件变化可能使缓存不适用
RAG / episodic memory外部资料、事件、经验与检索索引文档 / 事件写入；需来源、时效和隐私控制
Skills流程说明、代码、资源和工具约束维护文件与版本；是否有效通过paired任务评测

这些层可以协作，但不能相互替代：参数记忆不自动保证事实可追溯，长KV不自动实现跨任务持续学习，skill文件增长不等于参数能力增长。场景验收见第05章。
