数据研究的增量：生成空间与学习反馈

有更多任务，未必有更多能力覆盖。DeepSeek V4.1 §5.1把任务定义为 problem / environment / verification system；本节比较不同工作怎样扩大这个空间，以及怎样证明扩展对独立任务有效。[1]

  • 固定资产角色：材料、可重采样任务和轨迹分开管理；机制已在任务主讲展开。
  • 隔离同源内容：仓库、时间、任务族与生成模板可能共享答案；随机切分轨迹不足以保证独立。
  • 先验收再谈难度：全失败可能来自环境或grader；通过oracle后仍需负对照和指令审计。

四条数据合成路线，分别补什么

路线 / 相关工作机制与适用问题需要额外检查

SWE-smith；V4.1 coding pipeline		从可构建仓库、起始commit和代码变化构造任务；fail-to-pass证明修复有效，pass-to-pass保护已有功能。V4.1另有隔离构建、去泄漏、多Agent试解和独立审计测试覆盖不足、oracle修复是否绕过规格、隐藏测试泄漏；SWE-smith是2025基础工作

路线来源：SWE-smith [23]、V4.1 §5.1.1 [1]、NexForge [8]、EvoSyn §4–5 [9]、ProgramGym [10]。不同团队共同支持“环境与验证是数据生产的一部分”，但没有给出通用最优合成配方。

与 Harbor 合成工作的直接连接：先把任务包作为主要交付，再产出示范轨迹；把正确性与难度作为两张报告。当前模型全失败的题只有在环境、oracle、指令和grader经过审计后，才能进入困难任务池。

独立验证环境带来的迁移问题

任务格式、数值容差和负对照在任务合同展开。这里关注把原benchmark迁入Harbor后，哪些状态会丢失。[35]

独立 verifier sandbox把验证过程移到单独环境，只接收显式声明的 artifacts。运行中的进程、未复制的数据库状态和临时目录不会自动转移。官方参数包括 artifacts 与 verifier.environment_mode；不能自行造字段或默认整台环境已经复制。奖励写入 /logs/verifier/reward.txt 或对应JSON输出。[36] [35]

迁移算例：Agent把规范CSV写入声明产物路径，却把SQLite修改留在临时目录。独立verifier能读CSV，不能自动看到数据库变更；原环境“通过”、迁移后“失败”此时属于交接差异。应声明数据库快照或验证可重放导出，不能直接降低grader要求。此例是教学设计，未运行任务。

迁移一致性：统一格式之后仍要重放

Adapter parity：统一入口后仍要保留初始状态、动作语义、超时、工具与grader；否则分数变化可能来自迁移。[26]

困难切片：Harbor-Index v1从54个benchmark、6,627候选筛出82题，最终涉及29个benchmark；它测困难前沿，不能替代通用能力量尺。[34]

  • 先在原环境与adapter环境重放同一组已知行为，核对观察、动作、终态和reward；oracle与已知失败路径都要比较。
  • 对不可重放的随机用户 / 外部网页，冻结可控状态或使用重复试验，把随机性与adapter差异分开报告。
  • 记录环境重置、资源上限、工具错误和是否真正进入grader；超时与基础设施失败不静默归为策略失败。
  • 固定scaffold、工具权限、尝试次数和预算再比较模型；原论文外部baseline只作为参考，不充当严格受控消融。

Terminal-Bench 4.0是breaking major release：官方说明资源校准、移除8个任务，并在正文写19项修复；合作方页面写20 revised、66 tasks。保留19/20来源分歧，以逐项release清单再复核；旧版本分数不能直接搬进4.0表格。[37] [38]

榜单审计要检查什么

Silent Instrument Errors报告HAL/τ归档中的双重计费、未进入grader、gold replay混入动作日志和evaluator重评分。这些是作者审计，本地未重放，可据此设检查项，不能推论所有榜单无效。[11]

AgentProofBench研究verifier的reuse/rebuild与deployment-state panels；结论限该任务族，不能替代所有场景的验证器验收。[12]

  • 请求去重：父span已含两个请求费用0.03与0.02时，总费用是0.05；再加父span的0.05会误报0.10。这是计费教学例。
  • 缓存单列：缓存输入与未缓存输入分开统计，按实际请求标识核对账单。
  • 失败保留：区分policy、environment、tool、grader、预算耗尽与unknown，记录是否进入grader。

待执行：从任务验收到合成闭环消融

展开四阶段研究方案
阶段固定条件与改变项验收产物
A · 任务验收固定环境与verifier；运行oracle、负对照、不同策略试解和重置重跑可构建率、oracle一致性、负对照误通过、失败归因、版本清单；阈值由任务风险预先定义
B · Adapter parity同状态 / 动作重放；仅改变原环境与适配环境逐项观察、reward、资源与成本差异；每项修复后重跑
C · 合成路线固定base、训练器、目标token和生成预算；比较静态任务、空间内重分配、空间扩展有效新任务率、去重后覆盖、grader分歧、逐域留出成绩与单位成本
D · 训练闭环冻结独立留出题；训练失败反馈只能用于训练池合成泛化、遗忘、有效组 / token、成功成本和各随机seed；保存完整原始日志

这是建议方案，全部待执行；不提供预测增益或伪造benchmark结果。训练阶段与固定SFT对照见CPT / Midtraining；把reward转成策略更新见后训练主题的Agentic RL。

合成流水线的定量证据

EvoSyn 的反馈与设计消融连接分类与最终 SFT 能力；相同候选预算不代表相同有效任务费用。本地科学实验仍待执行。

面试短答：反馈驱动合成要区分“在既有空间重分配预算”和“增加新的交互因素”；收益需要在冻结留出集、同训练与生成预算下验证。环境错误和grader投机必须先排除。
