先分清：轨迹、任务、环境和 benchmark

Agent 的训练瓶颈往往不在于“有没有更多文本”，而在于能否持续生产可运行、可验证、难度合适且不污染评测的交互任务。DeepSeek V4.1 §5.1 将任务定义为 problem / environment / verification system，并明确沿用 SFT → RL → OPD；它把主要投入放在任务与环境生产。[1]

资产包含什么训练 / 评测用途最容易混淆的点
领域材料文档、代码、issue–PR、日志、科学资料CPT / midtraining 的上下文和知识有代码不等于有可执行任务
任务包指令、初始状态、依赖、预算、验证标准RL 可重新采样；也能生成示范题目描述不能替代环境与grader
轨迹观察、动作、工具结果、版本、reward、产物SFT、拒绝采样、离线分析或在线策略更新成功轨迹仍可能泄漏答案或包含错误奖励
训练环境族可变化的参数、状态、用户、工具、程序版本扩大策略遇到的分布；在线合成课程改变seed不必然增加语义覆盖
Benchmark快照固定题集、版本、scaffold、预算、grader、聚合规则冻结后衡量泛化与可比较能力benchmark转成训练任务后，原题不能继续充当独立留出

从同一仓库提取多个任务，要按仓库 / 时间 / 任务族隔离数据划分，并检查共享测试、答案、PR 和生成模板。简单地随机切分轨迹可能把近重复题分到训练和评测两侧。

与 Harbor 合成工作的直接连接：先把任务包作为主要交付，再产出示范轨迹；把正确性与难度作为两张报告。当前模型全失败的题只有在环境、oracle、指令和grader经过审计后，才能进入困难任务池。

Harbor：把输出合同做成可执行验收

官方任务格式把 instruction、environment、tests、solution组织成一个任务目录。下面仅展示目录角色，具体字段以固定版本的官方文档为准。[35]

task/
├── instruction.md        # Agent能看到的要求与输出合同
├── task.toml             # 元数据、资源和环境 / verifier配置
├── environment/          # 可构建、可重置的起始环境
├── tests/                # verifier与隐藏验收逻辑
└── solution/             # oracle方案；不暴露给待测Agent

独立 verifier sandbox把验证过程移到单独环境，只接收显式声明的 artifacts。运行中的进程、未复制的数据库状态和临时目录不会自动转移。官方参数包括 artifacts 与 verifier.environment_mode；不能自行造字段或默认整台环境已经复制。奖励写入 /logs/verifier/reward.txt 或对应JSON输出。[36] [35]

一个科学数据整理任务怎样定义合同

以表达矩阵与样本表为例：指令明确ID匹配、重复项规则、允许缺失值、输出路径及统计口径；verifier分别检查结构、内容、不变量和报告的一致性。只检查CSV存在，会奖励空表、硬编码或错误join。

合同层检查对象建议负对照
产物与schema指定文件、列名、类型、主键唯一性空文件、缺列、错分隔符、重复ID
数据语义样本集合、矩阵方向、join匹配、预定缺失策略行列转置、漏样本、错组标签、无条件填零
数值与不变量容差、行数、总量、排序无关比较和边界输入同形但数值错误、随机矩阵、仅适配公开例子的输出
证据与报告报告统计与原始数据一致；保留命令和配置正确文件配错误结论、把未知样本写成确认类别

这是教学设计，未生成、运行或测量该Harbor任务。科学任务还需单独判断方法和推断是否合理；可执行检查不自动证明生物学正确。

迁移一致性：统一格式之后仍要重放

Harbor Adapters强调adapter parity：统一执行入口后，初始状态、动作语义、超时、工具和grader应保留原benchmark合同。否则“同一模型的新分数”可能由迁移变化造成。论文分析harness、失败与成本；Harbor-Index v1筛出82个困难任务，来自54个benchmark的6,627个候选，最终涉及29个benchmark。它是困难前沿切片，不能替代通用能力量尺。[26] [34]

  • 先在原环境与adapter环境重放同一组已知行为，核对观察、动作、终态和reward；oracle与已知失败路径都要比较。
  • 对不可重放的随机用户 / 外部网页，冻结可控状态或使用重复试验，把随机性与adapter差异分开报告。
  • 记录环境重置、资源上限、工具错误和是否真正进入grader；超时与基础设施失败不静默归为策略失败。
  • 固定scaffold、工具权限、尝试次数和预算再比较模型；原论文外部baseline只作为参考，不充当严格受控消融。

Terminal-Bench 4.0是breaking major release：官方说明资源校准、移除8个任务，并在正文写19项修复；合作方页面写20 revised、66 tasks。保留19/20来源分歧，以逐项release清单再复核；旧版本分数不能直接搬进4.0表格。[37] [38]

榜单审计要检查什么

Silent Instrument Errors对HAL / τ系列归档报告了嵌套span双重计费、部分试验未进入grader、gold replay混入动作日志、evaluator版本重评分等问题。这些是该作者的审计报告，本地未重放确认；可据此建立检查项，不能泛称所有榜单无效。AgentProofBench则研究可重用verifier的reuse / rebuild与deployment-state panels，结论限于其任务族。[11] [12]

# 建议的审计记录字段；不是实际实验数据或框架配置
task_id, task_version, split, environment_digest
model_revision, harness_commit, verifier_commit, seed
attempt_id, parent_span_id, provider_request_id
input_tokens, output_tokens, cached_tokens, billed_cost
entered_grader, reward, artifact_digest
failure_class, latency, tool_calls, stop_reason

计费以provider request等实际请求标识去重，父span聚合与子span请求不能一起相加；缓存输入和未缓存输入分别统计。失败类至少区分policy、environment、tool、grader与预算耗尽；无法判断时保留unknown。

阶段固定条件与改变项验收产物
A · 任务验收固定环境与verifier；运行oracle、负对照、不同策略试解和重置重跑可构建率、oracle一致性、负对照误通过、失败归因、版本清单；阈值由任务风险预先定义

C · 合成路线固定base、训练器、目标token和生成预算；比较静态任务、空间内重分配、空间扩展有效新任务率、去重后覆盖、grader分歧、逐域留出成绩与单位成本
