RAG的输出应该是一组可追溯的证据

RAG把当前任务需要的外部信息放入模型上下文。检索器找候选，reranker缩小候选，生成器解释证据；Agentic RAG进一步让策略选择何时检索、改写哪个查询、何时结束。它不能自动解决来源错误、权限泄露或引用不支持结论的问题。

先修：上下文与memory、窗口和历史访问。本章维护检索原理；规划预算与安全分别见02、03。

知识库、会话摘要与长期memory保存不同对象

对象来源与作用正确性约束
检索知识库文档、代码、数据库；提供事实和方法版本、权限、原文位置、有效期与删除传播
会话摘要本次运行历史；恢复目标、已做动作和未决问题压缩会丢细节；关键artifact和失败证据需可重新读取
跨会话memory筛选后的偏好、经验、可复用流程是候选背景；不能覆盖当前指令或冒充独立科学证据
模型参数训练形成的分布与能力通常不能逐句给出处；更新不等于更新文档索引

把失败的科学结论写入memory，再当作RAG证据检索，会把一次误判变成持续污染。应把“当时认为”“官方原文”“后来修正”分开存储。memory实现由Codex案例维护。

索引之前：版本、权限与语义边界

文档记录至少包含document_id、source_url、revision、content_hash、访问时间、许可、ACL、页/节/span和解析器版本。网页更新时间不是论文版本；同论文的HTML、PDF与博客转述不是三份独立证据。代码要固定commit，科学数据要固定对象与处理层。

chunk太小会截断定义、否定、表头和适用条件；太大会稀释相关内容、增加重排及生成成本。本文建议按标题/段落/表格语义切分，以短chunk检索、父段落补上下文；overlap保留连续性，但应按源span去重。chunk长度、overlap和embedding模板是需在真实语料上消融的参数，不设通用最优数字。

权限需要在候选生成和最终引用时检查。只在回答前隐藏文档，可能已让reranker、日志、缓存或生成器看到敏感内容。按租户/权限域分索引或先使用可见ID集合，再做检索；权限更新需使旧缓存失效。语料删除也要传播到向量、原文、摘要和prefix缓存。

BM25、dense、融合与rerank分别解决什么

BM25(q,d) ∝ Σt IDF(t) · tf(t,d)(k₁+1) / [tf(t,d)+k₁(1−b+b·|d|/avgdl)] dense(q,d) = similarity(Eq(q), Ed(d)) RRF(d) = Σlist 1/(c + ranklist(d))

BM25利用词项匹配和长度归一化，对accession、函数名、错误代码等精确对象常有价值。dense学习语义匹配，但近邻不保证包含答案，embedding相似度也不是事实正确概率。cosine通常要求明确归一化；内积会受向量范数影响。不同模型的分数不能直接相加。

RRF按各候选表排名融合，避开不兼容的原始分数尺度；它不证明所有查询都应使用相同权重。cross-encoder reranker联合读query与chunk，通常比单向量更能辨认细节，但每个候选都要计算；先召回再重排，把昂贵计算放在较小候选集。还需按来源、版本和span去重，并保留少量相互矛盾的权威证据。

步骤优化对象容易遗漏的失败
BM25 / dense在可见语料中取得相关候选tokenization、版本错误、ANN漏召回、查询分布偏移
RRF / weighted fusion合并候选排序同文档重复、多路高度相关、未经校准的分数混合
rerank判别候选对问题的局部相关性把流畅转述排在官方原文前；长文截断丢失条件
context packing窗口内覆盖关键证据相关但不充分；相同事实重复占用预算；表头与单位丢失

Agentic RAG：检索是可学习的行动

单轮RAG执行一次固定query；多跳流程按预设步骤拆题；Agentic RAG根据观察决定是否改写、拆分、换来源或结束。查询、浏览、证据选择与最终回答都形成轨迹。工具返回文本是观察，策略生成的查询是动作，两者在SFT/RL中使用不同mask。

路线与固定来源改变的对象证据边界与本文分析
Self-RAG，2310.11511v1学习reflection tokens，控制检索与生成/批评不等于给任意模型加“再检查”提示；自评分仍需独立引用评测
Search-R1，2503.09516v5多轮查询、检索观察mask和结果奖励固定QA语料/检索器中的报告；搜索观察不是模型action token
Agentic-R，2601.11888v1局部query-passage相关性与全局答案正确性共同衡量utility，迭代更新retriever和agentretriever从静态相似度走向轨迹效用；需独立研究切分防止答案/检索器共适应
Search-R1++，2602.19526v1解耦prompt、reward、policy optimizer；分析answer avoidance与稳定性其REINFORCE/PPO/GRPO比较不是跨任务定律；先控制模板和奖励，再比较算法
PROGRESS，2608.00969v1冻结教师生成必要子查询，以覆盖奖励指导分解教师覆盖是代理目标；相似query不保证证据正确或科学合同通过

本文判断：检索训练有三种不同目标——找到相似文档、找到当前决策有用的证据、让完整任务通过。它们可能不一致。科学任务最有价值的检索有时是发现元数据矛盾并拒绝继续，而不是尽快产出答案。前沿原文[4–7]；本章不外推作者QA收益到RNA-seq。

while budget.remaining() and not evidence.sufficient(contract):
    query = policy.choose_query(unresolved_claims, evidence)
    hits = retrieve(query, allowed_documents, frozen_index_version)

“sufficient”需根据任务合同定义，不能直接由模型一句自信回答确定。若新增检索没有带来新证据、重复访问同页或预算耗尽，应停止并报告缺口。预算与失败恢复见下一章。

分别评估检索、生成和完整任务

Recall@k = |相关证据 ∩ top-k| / |标注相关证据| MRR = mean(1 / 第一条相关结果的排名) 引用支持率 = 有原文支持的已核对引用 / 已核对引用 成功成本 = 全部尝试成本 / 独立验收成功数

multi-hop需要多条证据联合，单文档recall不能完整描述充分性；nDCG需要相关性等级标注。引用正确性检查出处是否支持该句，引用完整性检查应被支持的重要结论是否缺引用。事实正确、引用支持和工具任务成功是不同指标；LLM judge要用人工/规则子集校准，不能作为自动真值。

待执行对照冻结变量能区分什么
BM25 / dense / hybrid语料、版本、ACL、query、候选预算候选覆盖与近似索引损失
无rerank / rerank / oracle证据候选与generator重排失误、证据组织与生成使用能力
单轮 / 多轮 / RL检索模型起点、总token/工具预算、测试研究策略价值与单纯增加计算的差异
冲突 / 无答案 / 权限负例证据快照、攻击位置、合法目标拒答是否恰当、引用欺骗与越权

索引只纳入允许的训练/公开文档，test答案、verifier参考输出和其他研究标签隔离。查询轨迹按研究切分；同研究不同chunk或改写不能分到train/test两侧。科学方案见合同与切分，后训练mask见SFT/RFT。

理解检查

向量相似度很高，为什么仍不能引用？

相似度只描述embedding关系；文档可能版本错误、没有支持结论、属于不可见权限域或把否定条件截断。引用要回到原文span。

增加检索轮数必然提高正确性吗？

更多轮也会引入冲突、冗余、注入和成本。需要同预算对照及可执行的停止规则；检索行动次数不是学习效果。
