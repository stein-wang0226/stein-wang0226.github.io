后训练是多个服务的循环，不只是一次 backward

训练节点更新权重，推理节点生成轨迹，环境执行动作，verifier 判结果，teacher / critic 提供额外信号。任务长度与服务速度不同，决定同步等待、异步缓存、并发配额和参数传输的成本。

并行维度主要解决什么Agent 后训练额外关心
DP / FSDP / ZeRO样本并行，分片参数、梯度和优化器状态变长样本、有效 token 数、分母和 global batch
TP / PP / CP切矩阵、层或上下文，承载大模型与长序列训练和推理布局转换、pipeline 等待、长工具输出
MoE EP专家分布与 dispatch / combinerouting 一致性、专家负载、通信和概率差异
Rollout 并发同时生成、执行多个任务KV 容量、环境等待、长短任务公平性
Teacher / grader 并发额外反馈吞吐prefix 重算、词表张量、rate limit、失败重试

Full fine-tuning 下 Adam 的状态、master weights、activations 与通信都需核算；不能只按模型权重决定 GPU 数。colocation / hybrid 复用 GPU 可减少闲置，但训练与 rollout 争内存；独立部署减少干扰，却增加权重同步和排队成本。

同步、解耦、完全异步：吞吐和新鲜度的取舍

同步模式一轮采完再更新，慢任务会拖住整批；解耦模式分配独立采样与训练资源，但仍可能在轮次同步；完全异步让 queue 中的轨迹持续进入训练，训练同时更新参数和采样器。

AReaL 的论文研究大规模异步推理 RL；Relax 则用服务隔离和 TransferQueue 组织多模态异步数据。故障隔离、数据队列和 backpressure 是系统机制，不能自动消除 off-policy 学习偏差。[45] [46]

verl 的 fully async recipe

文档包括 AgentLoop / inference server、MessageQueue 和 ParameterSynchronizer，以及 require_batches、trigger_parameter_sync_step、staleness_threshold 和 partial rollout。staleness_threshold 控制 backlog 配额比例，不是“最多落后几个 checkpoint”；大于 0 时可出现跨版本 partial 样本。[51]

该文档在 Qwen2.5-7B、128 GPU 的作者测量中给出约 2.35–2.67× 加速。模型、资源、同步基线和任务不同，不能拿这个数与另一框架 README 相除组成速度榜。终评还要看有效训练 token、任务质量与总 GPU 小时。

三类偏移：策略版本、数值实现、完成顺序

μ：实际rollout行为分布 πold：训练侧旧策略；πθ：训练侧当前策略 πθ/μ = (πθ/πold) · (πold/μ) 策略更新比 训练/采样分布校正

策略版本延迟使 rollout 用旧权重；同版本差异还来自精度、kernel、MoE routing、template、截断与采样温度。相同 checkpoint SHA 不能保证 log-prob 完全一致。verl 的三策略路线与 bypass 路线分别处理不同假设，需要按 recipe 解释。[52]

教学 token 的 μ=0.20、πold=0.22、πθ=0.24，更新比为 1.091、实现校正比为 1.10，总比为 1.20。若只看 πθ/πold，就漏掉采样与训练的差异；这个算例不代表真实框架误差大小。

重要性采样不能创造缺失支持。behavior log-prob 必须对应实际 token IDs、模板和采样分布。top-k / top-p 会截掉部分支持，temperature 改变分布；未采到或被彻底排除的动作，不能仅靠一个有限 ratio 恢复。

长 trajectory 的 ratio 乘积容易高方差；几何平均、clip、mask 或 residual filter 改变目标与样本利用。它们是稳定训练的近似，不应自动称“完全无偏校正”。

完成顺序偏移不属于 token ratio

短代码任务先返回，长科学任务还在跑；如果训练持续吃“先到的样本”，科学域占比会下降。即使所有 token 的 log-prob 完全准确，也不会自动补回缺失的域。V4.1 将完成顺序和数值对齐分开讨论；MiMo 用域预算、时长和接受率调节并发。[25] [27]

MiMo调度关系示意： 域资源预算 ∝ 目标batch量 Bᵢ × 平均耗时 tᵢ / 接受率ᵢ 长任务或高拒绝率域，需要更多并发才能维持目标准入占比。

同时统计 dispatch、完成、接受和实际训练四层域占比。dynamic sampling、lag filter 和基础设施重试都会改变接受率；拒绝和等待成本算入总预算。

Partial rollout 与上下文压缩：旧 KV 不能默认跨权重复用

长任务可以中断生成、等待工具、继续 rollout；期间模型参数可能更新。常见 continuation 需重新 prefill 当前历史来重建 KV。V4.1 披露专门的跨 checkpoint 状态处理，MiMo 讨论 re-prefill；这不是所有框架通用的“缓存一直有效”。[25] [27]

KV 来自旧权重的投影和历史层状态。换权重后复用可能造成模型函数混合，是否可接受取决于特定算法与实现。记录每段策略版本、历史、重算和缓存来源，才能判断概率计算对应哪个真实分布。

Agent Lightning v1：保存真实调用，而不是假定一条长 prompt

v1 的 Trainer、API Gateway 与 Rollout Controller 支持已有 harness；模型调用可能因 compaction 或子 Agent 产生非嵌套上下文。必须保存每次 exact prompt / response token IDs，文本看似前缀相同不保证 token 前缀相同。[47] [64]

只有精确 token-prefix 条件成立，调用才能合法合并。一次 episode 产生很多训练调用时，sample-mean 会使调用多的任务权重更大；episode-mean 与 token-mean 取舍应由目标决定，不能无条件推荐“拼成长序列”。2025 原 LightningRL 的分层路线属于历史来源，v1 的当前实现另行说明。[48]

固定源码实例：slime 怎样把教师信号加到 advantage

本次核对 commit 79aa41a884ab0bf65222c94418f6357d3c31192b 的 OPD 文档、rollout 入口和 Megatron loss。以下为 loss.py 715–719 行原始摘录，Apache-2.0。[55]

reverse_kls = []
for i, adv in enumerate(advantages):
    reverse_kl = student_log_probs[i] - teacher_log_probs[i]
    advantages[i] = adv - args.opd_kl_coef * reverse_kl
    reverse_kls.append(reverse_kl)

若学生对某 token 的概率高于教师，log pS−log pT 为正，教师项降低它的 advantage；相反则提高。这里是 sampled-token 蒸馏信号进入 policy-gradient，不是完整词表 KL 直接反传。

同文件 829–836 行在基础 advantage 后应用 OPD；839 行之后还可归一化 advantage。顺序会影响信号尺度：归一化一个混合项不等价于独立归一化任务和教师项。教师数组还需按 response 位置裁剪，与动作 mask、token IDs 对齐。

GPU 利用率高不等于训练更有效。并列报告总 rollout token、接受/拒绝 token、教师评分 token、训练有效 token、环境秒、重试、同步与队列等待，再给 GPU 小时和终评成功率。
