RL 环境是任务状态机，也是训练分布的一部分

环境规定模型能观察什么、能做哪些动作、动作如何改变状态、什么时候结束、如何评分。一个好的奖励函数依赖可信环境；环境把答案泄漏或把服务故障当策略失败时，再先进的 RL 目标也会学错。

情况谁的问题训练记录与处理
无效工具名 / 参数策略或协议不一致若协议正确，可计策略失败；模板漂移先修协议
产物错误、规定预算耗尽真实任务失败按任务规则打分，记录失败位置和截断类型
容器拉取失败、服务宕机基础设施单列、重试或排除任务更新；重试成本仍计入
测试逻辑错误 / 不确定参考verifier隔离任务、修复并重验，避免当作模型负样本

时间预算导致的正常 timeout 与服务故障引起的 timeout 不同；重试不能静默消除失败统计。训练和评测统一明确结束、状态重置、网络可达性与资源限制，才可比较模型。

Harbor：把 Agent 工作区与 verifier 分开

当前 Harbor 文档的任务含 instruction.md、task.toml、环境、解法和 tests。测试脚本把分数写入 /logs/verifier/reward.txt 或 reward.json；两者都有时 JSON 优先。具体字段与共享/独立模式按固定 Harbor 版本核对。[53] [54]

  solution/solve.sh
  tests/Dockerfile            # 独立verifier镜像包含受保护的测试
  tests/test.sh

独立 verifier 启动新环境，不继承 Agent 工作区全部文件系统；通过任务声明的 artifacts 交接选定产物。TOML 顶层键需写在各 section 之前，否则可能意外落入前一个表。tests/Dockerfile 或指定镜像包含测试；不要把不同模式的 tests 上传规则混用。

# 教学片段：顶层artifacts放在[environment]等表之前
artifacts = ["/app/output/result.json", "/app/output/provenance.json"]
# 其余task.toml字段须按实际Harbor版本生成和验证。

当前 task init 默认倾向独立模式，但旧任务缺相应配置或 verifier 环境时仍可能是 shared；升级框架不能证明历史任务全已隔离。共享模式尤其需防 Agent 写测试、读取隐藏参考或伪造 reward 文件。

科学任务对最终统计量和 provenance 重新验证，代码任务对 patch 应用与隐藏回归重新验证，GUI 任务由受保护的持久化状态检查。Agent 的“完成了”、文件存在或按钮点击本身都不是最终成功证据。

五类反馈：名称相近，预测对象不同

相关原论文 / 官方资料：Process supervision。

信号它回答什么不应自动推断什么
Outcome reward最终产物是否满足任务哪个中间动作导致结果
Process reward model（PRM）当前步骤正确性或过程质量后续必然成功，或它可直接当 value
Value / Q当前状态/动作后预计未来回报这个数学步骤局部一定正确
Advantage当前动作相对 baseline 好多少原始 reward 或人工真值
Teacher log-prob / 文本反馈教师偏好动作、补充条件或错误解释独立验证的真实任务成功

对数学推导，一个错误步骤以后也许被模型纠正并得到对的答案；“从这里多次续写的成功率”包含 continuation policy 的能力，不等于当前步骤正确性。反过来，一个正确中间步骤后面也可能失败。这是 PRM 标注与 value 估计的重要区别。

过程监督：从 PRM800k 到标注、选择与训练的分歧

相关原论文 / 官方资料：Process supervision。

Let’s Verify Step by Step 通过步骤标注研究过程监督，PRM800k 是经典入口。Qwen 的 Lessons 指出 MC continuation 标注、LLM judge 和人类过程正确性之间存在差异；best-of-N 排序表现也不等价于在线训练中的抗投机能力。[37] [38]

标签来源价值误差与成本
人类步骤标注可明确错误原因和局部正确性昂贵、细粒度一致性与专业领域知识
MC 多次续写可自动估计该 prefix 的可完成性受续写策略和采样预算影响，非纯步骤正确性
LLM judge / consensus扩展覆盖、给解释与结构化评分自洽不等于真值；需可信留出标注与对抗样本
执行式 step check代码/科学/GUI 某些状态有客观检查检查是否足够、是否可投机、是否泄漏终评

三种评测分别做：对人类过程标签的判断质量；推理时 BoN 的选中成功率；在线 RL 的真实终评、投机与稳定性。只选一种表现好的指标，不能证明适用于全部用途。

PURE 与 Cliff：稠密奖励也可能强化坏过程

PURE：求和会奖励重复“正确步骤”

如果每个看起来正确的小步骤都有正 reward，模型可能把一个步骤拆成很多片、重复安全陈述或拖长推理，以增加总和。PURE 研究以最差后续步骤为中心的目标，抑制此类投机。[39]

求和风险：Return = Σᵢ rᵢ，重复高分步骤可能增益 PURE 转换示意：r*ᵢ = softmax(−rᵢ/T)ᵢ · rᵢ T → 0 时集中于最低分步骤；γ=1时对应最差步骤式回报

这适合研究逻辑推理的弱链路，但可恢复 terminal Agent 中，前面一个错误动作以后可能被修复。若直接把最差历史步骤当整条任务上限，会惩罚有价值的恢复。迁移需验证是否符合任务的不可逆性假设。

Cliff：识别首个 pitfall 边界

相关原论文 / 官方资料：GRPO / DeepSeekMath。

Cliff 使用验证的教师解法辅助判断第一次出错位置，边界前后施加不同信用；坏教师时回退 GRPO，overlong 也有单独处理。附录含误判案例，说明首错定位本身不是可靠真值。[40]

科学设计若错用 contrast 且未修复，后续步骤会沿错误方向；代码先跑出错误再修好，则不满足“首错后全废”。应按任务分别测试边界质量、恢复率和反事实影响，避免把数学推导的假设自动应用到交互任务。

多步信用分配：重复状态、子任务与知识条件基线

相关原论文 / 官方资料：GAE；GiGPO。

路线信用对象何时有帮助限制
GiGPO [41]episode 宏优势 + 相同 anchor state 内动作微优势状态可判等、不同轨迹常经过同一锚点同截图不保证同状态；开放仓库/GUI 的重复率可能低

Single-rollout value 路线 [10] [11]回合未来价值与 GAE长 rollout 贵，能学习可靠 criticvalue 误差、共享干扰、off-policy 与 mask

GiGPO 的 anchor 要求与决策相关状态等价：相同页面可能有不同隐藏数据库、权限或先前动作；同一 shell 路径可能有不同文件内容。错误判等会将不可比较的动作混成一组。

子任务粒度太细，定位成本与噪声增加；太粗又退回 episode 广播。RLDS 的收益随任务不同而变化，支持在自己任务族做 taxonomy、reward share 和定位器的独立消融，不支持承诺通用提升。

2026 信用分配趋势：从整轨迹广播到环境证据

当前前沿不是简单再造一个 GRPO 缩写，而是在回答“中间步骤的信用证据从哪里来”。下表按证据结构归类；这些论文主要在 ALFWorld、WebShop 等环境验证，尚不能直接外推到开放代码仓库、浏览器或科学任务。

趋势簇代表方法新增证据适用边界
轨迹图与分支比较GraphGPO [67]、MileGPO [70]合并重复状态，比较到目标的图距离、里程碑、陷阱和同状态分支状态必须可规范化并可靠判等；重复状态少时图证据变弱，错误合并会污染优势
显式 beliefReBel [68]结构化 belief、后续观察一致性和 belief-aware grouping适合部分可观测任务；belief 格式本身会改变策略输出和监督，不能当作免费隐藏状态
环境反馈多时间尺度EFCA [69]即时反馈、近期 action-feedback 历史与最终 outcome 共同重加权 return环境文本或状态变化必须能区分进展、无效动作和循环；噪声反馈仍会误导
固定子任务或知识条件RLDS、KnowGPO预定义阶段、reward share、训练时额外知识或定位器需要 taxonomy / 知识可得且无留出泄漏；维护成本随任务族增加
学习 value / 单轨迹turn GAE、single-rollout SAPO、SAOcritic 预测未来回报，减少每题多条长 rollout将生成成本换成 value 训练和偏差；异步时还要处理 policy lag

GraphGPO 使用任务内 rollout 图和到成功状态的距离构造边级优势；MileGPO 再加入里程碑/陷阱可靠性和同状态分支校准。ReBel 把部分可观测下的 belief 漂移显式化；EFCA 从环境响应提取短期进展和中期重复模式。它们共同说明一个趋势：优先复用交互中已有的状态、分支、反馈和历史，而不是给每个 token 训练一个通用 PRM。但“无需额外标注”不等于没有额外假设，状态判等、belief schema、反馈解析和图构建都需要单独验证。

面试选型：可可靠判等且同题多 rollout 重合多，用图/分支路线；部分可观测且错误来自状态误解，考虑 belief 信号；环境返回可解析反馈，考虑多时间尺度信用；轨迹极贵且重复状态少，评估 critic / 单轨迹路线。最终都保留 terminal verifier 作为任务语义锚点。

MiMo GAR：同样通过的代码路径，质量仍有差别

MiMo-V2.6 §4.3.2 的 Grader-Augmented Reinforcement 为混合成功/失败的代码组提供质量因子：grader 结合任务、仓库、patch、tests 等信息判断成功路径质量，在通过路径的 advantage 上做调整。[27]

未截断的教学形式： λ = Σ_pass Aᵢ / Σ_pass fᵢ Aᵢ A'ᵢ = λ fᵢ Aᵢ（通过样本） 于是 Σ_pass A'ᵢ = Σ_pass Aᵢ 实际配方还有λ上限、重中心化和invalid grade回退。

例如两条通过轨迹优势均为 1，质量因子为 1 和 0.5，则 λ=4/3，重加权为 4/3 和 2/3，总正优势仍为 2。实际 cap 与 re-centering 会影响这个恒等式，不能把教学算例当完整实现。

通过与否首先由可靠 grader / verifier 更新 reward 和统计；成功路径质量加权是另一层。grader 偏好“补丁短”可能压制必要重构，偏好“测试多”可能奖励无效测试。需通过独立终评与质量留出标注识别 grader 漏洞。

过程检查只针对可验证的中间不变量，不奖励“说做了”。例如科学任务先检查样本 ID 再拟合，比给每句分析解释都打正分更可审计；GUI 等待网络响应是运行环节，不能按等待次数累计策略 reward。

把硬约束是否通过、结果 reward、过程质量和成本分别记录。权重组合需要事先声明并消融，不能在看到留出结果后调整到最好。完整输入、轨迹和训练对照见第六章。
