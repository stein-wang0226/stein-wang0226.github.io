OPD 为什么需要学生自己走一遍任务

静态蒸馏让学生模仿教师访问过的路径；OPD 让学生生成动作和历史，再由教师评估这些真实学生 prefix 的下一步分布。它补的是状态分布偏移，不只是把教师答案换成概率。

教学代码任务中，教师通常直接修空输入；学生却可能先改调用方，收到 test_empty_input FAILED。静态教师路径没有这个错误历史；OPD 的教师要在这个 prefix 上指出下一动作的分布。教师必须能理解学生的实际状态，不能悄悄换成一条理想历史。

L_OPD(θ) = E[h ~ d_barθ] D(πθ(·|h), πT(·|h)) d_barθ：生成本批数据的学生快照所访问的 prefix 分布

一批样本采完后可用固定快照更新；学生随后再采新批。这是一种 on-policy 数据循环，不表示每个 optimizer step 都即时重采所有状态。异步缓存会进一步引入行为策略与当前策略差异。

完整词表 reverse-KL：每个 prefix 的局部梯度

令固定 prefix 上的学生概率是 pᵥ、教师概率是 qᵥ，教师分支无梯度。reverse-KL 对学生具有概率的候选施加约束，forward-KL 则按教师概率加权。支持集、温度和词表对齐必须先定义。

D_reverse = KL(p || q) = Σᵥ pᵥ(log pᵥ − log qᵥ) D_forward = KL(q || p) = Σᵥ qᵥ(log qᵥ − log pᵥ) 若 p = softmax(z)：∂D_reverse/∂zᵥ = pᵥ[(log pᵥ − log qᵥ) − D_reverse]

最后一式既包含“这个候选相对教师是否过多”，也包含对学生分布求导产生的基线项。它解释了为什么把采样 token 的 log p−log q 直接当普通 loss 反传，不自动得到完整 reverse-KL 梯度。

# 固定学生 prefix 上的完整词表教学伪代码
student_logp = log_softmax(student(prefix_ids).logits, dim=-1)
with no_grad():
    teacher_logp = log_softmax(teacher(prefix_ids).logits, dim=-1)
student_p = student_logp.exp()
kl_by_position = (student_p * (student_logp - teacher_logp)).sum(-1)
loss = masked_mean(kl_by_position, assistant_prediction_mask)
loss.backward()

这段只表示 loss，不包括模型并行、温度缩放、数据传输和 off-policy 校正。词表大小 V、有效位置 T 使 logits 张量规模近似 O(TV)，教师额外前向、通信和 peak memory 都应计入预算。相同 architecture 不是必要条件，但 token-level 对齐也不能因 architecture 不同就跳过。

局部梯度等价不代表完整轨迹目标无偏

上式固定 prefix，验证的是局部分布梯度。若目标包含 dθ(h) 本身对 θ 的依赖，完整梯度还含状态访问变化；普通固定轨迹的局部 KL 反传不包含这一项。很多算法使用交替 rollout / update 的 surrogate，需要按实现描述。

SDPG 明确讨论 fixed-prefix 局部 identity，随后加入 gate、schedule 和参考正则。不能从局部恒等式推断任意多轮 trajectory、截断采样和异步更新都完全等价。[33]

采样 token 的蒸馏信号：数值估计和正确梯度是两件事

a ~ p： D_reverse = Eₐ[log p(a) − log q(a)] 局部最小化梯度 = Eₐ[(log p(a) − log q(a) − D_reverse) ∇ log p(a)] 对应上升优势：A_distill = stopgrad(log q(a) − log p(a) + b(h))

当 b 只依赖状态，baseline 不改变这个局部期望。采样 log-ratio 可以估计 KL 数值；更新则需要 score-function / policy-gradient 的处理。直接对冻结样本上的平均 log p−log q 反传，通常只剩 ∇log p，缺失应有的权重。

# 单prefix、on-policy采样的局部教学示意
sampled_token = sample(student_probability)
student_logp = student.log_probability(sampled_token, prefix)
teacher_logp = teacher.log_probability(sampled_token, prefix)  # no-grad
adv_distill = detach(teacher_logp - student_logp + state_baseline)
loss = -adv_distill * student_logp
# 若rollout来自旧行为策略，需要按真实实现定义ratio、mask与截断。

TML 的公开实现把教师与学生 log-prob 差作为即时 token 蒸馏反馈，使用 γ=0 的设计，避免把每个 token 的反馈简单累成整条序列的大回报；这不是所有 OPD 的统一折扣规则。其“难以 hack”的讨论是接近教师分布这一目标，不能替代独立任务正确性。[30]

教师路由可以按任务域选择数学、代码、GUI 专家，也可混合教师分布。简单概率混合 q=Σwⱼqⱼ 与平均多项 KL 并不相同：后者涉及平均 log-prob，前者是 log 的概率混合。报告需明确目标，而不是只写“多教师平均”。

“大教师更好”也依赖教师对学生访问状态的适应性。教师自己的 task score 很高，仍可能在学生损坏的 shell 状态上给低质量反馈；此时更强信号可能更稳定地推错。终评要看统一学生的目标能力、原有能力和同成本表现。

MOPD2：增加前缀覆盖，不把所有探索留给自主长 rollout

MiMo-V2.6 §5.6 的 Multi-Prefix Multi-Teacher OPD 包含三类采样：标准学生自主 rollout、teacher-prefix OPD、SFT-prefix OPD。对一条含 k 个 assistant 回合的示范，可形成 k 个完整历史 prefix；学生从每个 prefix 新生成一个回合，教师在相同历史上评分。[27]

代码任务中，prefix 可以停在“已经读完实现”“收到失败测试”“刚检查补丁”三处。小学生不必先自主完成长链路才能接触后半段；但示范 prefix 的状态可达性、截断和真实环境一致性要核验。学生部署时仍需自己走到这些状态。

多前缀扩大有效起点，也可能重复同一任务或让高回合数示范贡献更多样本。按任务、episode、prefix 或 token 归一化会改变权重；成本包括生成示范、环境重置、教师评分和丢弃的 continuation。

自蒸馏：同一模型也能通过更充分的信息当教师

“Self” 常指共享或相同模型参数，学生和教师看到的条件可以不同。教师分支得到验证解法、失败反馈或成功 sibling，因此信息更充分；没有外部大教师不等于没有外部监督。

Guided-OPD 与 TISD：主动改变学生访问的轨迹

Guided-OPD：按回合渐退教师接管

以 β 的概率由教师生成当前回合，课程使 β 逐渐降为 0。学生回合使用 reverse-KL，教师回合使用 forward-KL；早期混合策略让小学生接触更有价值状态，后期转到自主执行。论文在 ALFWorld、ScienceWorld、WebShop 上研究小 Qwen 学生与 Qwen3-30B-A3B 教师。[34]

教师接管能帮助完成前置步骤，但可能造成依赖。只有 β=0 的学生独立留出评测才能验收迁移；不能把混合 rollout 的成功率当最终学生成功率。

TISD：在失败轨迹中找到分支点，再让学生重新探索

TISD 用失败轨迹的学生/教师 KL 峰值定位干预候选，教师选择分支 token，学生重采后缀，再做轨迹蒸馏。它增加新的 successor prefix，区别于只在原错误路径上计算局部 loss。高 KL 表示分布分歧，不证明那个 token 必然是根因，也不保证一次干预就能成功。[35]

OPDArena：目标能力增加，仍需检查能力保留

OPDArena 比较五个 Qwen Base、OpenR1-50k 一轮训练，主要结果取两个 seed 平均。其 OPD 采用 student-weighted Top-16 approximation；完整词表用于部分分布测量，不能把这项实验说成 full-vocabulary OPD。[36]

研究发现教师类型会影响保留，RLVR teacher 在相关设置中优于 SFT teacher；更大或更多教师不保证更少遗忘。它与原 OPSD 在 prompt、模板、教师和更新实现上存在差别，不能用一个标签覆盖为“自蒸馏无效”。

分布外 JS 变化与遗忘呈关联，支持增加行为分布与能力回归监测，但不是单独的因果证明。终评至少并列目标域增量、分布外增量、工具协议稳定性和总成本，避免仅凭 teacher KL 越小越好。
