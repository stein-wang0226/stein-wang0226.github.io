从最终成败到动作梯度，中间隔着信用分配

Agent episode 包含策略动作和环境观察。模型只控制动作；最后 reward 要转成哪些动作应增加或减少概率的信号，再决定用怎样的概率比、裁剪和分母完成更新。

对教学代码任务，最终测试全通过为 1、真实任务失败为 0；删测试文件不能算成功。将整条成功路径都加概率是粗粒度信用：它可能连带强化一次多余读取、错误补丁和后续恢复。细化信用要额外信息，而不只是改优化器。reward 的内容见第四章。

环境输出不是策略选择，因此通常不进入 policy loss 的 response mask。环境失败是否算任务失败也需先定义；不能让基础设施宕机的 rollout 变成模型“动作不好”的标签。

Clipping 不是把区间外 token 的梯度全部设为零

优势为正，ratio 高于上界后目标停止鼓励继续增大；优势为负，ratio 低于下界后停止鼓励继续降低。另两个区间仍可能有梯度。因此 PPO 的 min-clipping 与“无论优势符号，区间外全部丢弃”的 strict IS mask 不同。

参考 KL 可以单独加正则或参与奖励；实现位置、估计器和系数改变梯度。不能由“用了 PPO”推断所有 KL 项都一致。

多轮 Agent 的 value 位置也要明确：是在动作前、生成 token 内还是回合后估值；tool observation 可以改变状态，但它的随机反馈不应被当成策略生成 token 逐个施加动作梯度。

RLOO 与 GRPO：用同题候选代替 learned baseline

RLOO：Aᵢ = Rᵢ − (1/(G−1)) Σⱼ≠ᵢ Rⱼ GRPO：Aᵢ = (Rᵢ − mean(R₁…R_G)) / (std(R₁…R_G) + ε)

RLOO 用其他候选的均值避免自己的 reward 进入 baseline；GRPO 用组内中心化和标准差。它们节省显式 critic，却需要同一任务多次采样；单条长 episode 很贵时，省下的 critic 不能直接等价为总成本降低。[3] [4]

异质数据：标准化不能保证每个任务都有学习机会

独立 Bernoulli 成功，单次成功率 p，组大小 G： P(组内同时有成功和失败) = 1 − p^G − (1−p)^G G=8：p=0.01 / 0.99 时约 7.7%；p=0.50 时约 99.2%

每题除以自己的标准差还会改变隐式权重：微小但不可靠的奖励差也可能被放大。中心化只处理数值，不会消除任务梯度冲突或 completion bias。需逐域监控全零/全一组、奖励方差、有效动作 token 和错误类型。

GSPO 在序列层裁剪长度归一化几何比率，缓解 token ratio 的不稳定和更新单位不一致。它不是完整轨迹 importance ratio 的乘积，也不保证对所有长程 off-policy 目标无偏。[7]

CISPO：J ≈ meanᵢₜ [stopgrad(clip(ρᵢₜ)) · Aᵢₜ · log πθ(aᵢₜ|hᵢₜ)] 裁剪的是 importance coefficient，并阻止其反传；实际范围见原配方。

MiniMax-M1 的 CISPO 在 clipped IS 系数上做 detach，再用 log-policy 梯度；不能把它描述为 PPO 的 min 两项裁剪。比率单位、权重边界和 token 聚合都需与报告一致。[8]

Soft Adaptive Policy Optimization 在远离 1 的 ratio 上平滑减弱梯度，而不是硬截断；正负优势可使用不同温度。原报告偏向对负优势采用更强抑制，但这是实验设置，不能宣称“soft”消除了所有偏差。缺失 A 或把 f 直接说成 log-prob loss 都会改变目标。[9]
