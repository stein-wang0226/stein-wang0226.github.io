把同一个任务的输入、动作、反馈与训练目标接起来

下面三个案例是教学设计，未执行 GPU 训练，也没有伪造真实轨迹和成绩。它们说明如何将前五章的目标落实为数据、环境、反馈和可复核交付。

案例 A：修复空输入崩溃，同时保留非空行为

输入是一个小仓库、issue 和工具协议：mean([]) 应抛出 ValueError，其他数字列表继续返回平均值；禁止改测试、依赖与无关函数。允许读取、patch、运行测试，输出提交补丁与说明。

# 教学初始实现
def mean(values):
    return sum(values) / len(values)

# 满足本任务的最小候选修复
def mean(values):
    if not values:
        raise ValueError("empty input")
    return sum(values) / len(values)
回合动作和观察训练价值
1 · 理解状态读函数与 issue，运行基线，观察 ZeroDivisionErrorSFT 学工具协议与定位；观察作为上下文
2 · 首次修复失败只在调用方捕获异常；函数直接测试仍失败学生失败 prefix，供恢复训练 / SDPO / OPD
3 · 根据反馈恢复在函数入口处理空列表；运行非空回归教师恢复 token 可作 SFT；局部教师分布可作 OPD
4 · 独立终评干净镜像应用 patch，隐藏测试与变更限制通过独立 outcome reward；不以最终回复为分数

同任务怎样进入不同训练方法

方法数据与目标会学不到什么
SFT / 恢复 SFT可靠示范；失败历史为 context，恢复动作监督没有覆盖的新错误状态
拒绝采样 RFT多次尝试，经独立 verifier 筛选后 CE被丢弃失败路径的相对好坏
DPO同题可靠补丁 chosen、吞异常捷径 rejected离线候选以外的探索
GRPO / RLOO同题多候选，最终通过形成 advantage全失败组只用二值结果时无法区分错误
OPD / SDPO学生失败 prefix，教师或反馈条件 self-teacher 的概率教师校准不足、无有效反馈或支持缺失时不能保证正确
GAR / step checks对通过路径质量重加权，验证不变量弱质量 grader 可被补丁风格和重复测试投机

独立终评应覆盖空、单元素、负数、重复值和规定数值类型，检查测试目录没有被改。真实仓库按项目、问题来源和解法簇隔离 train / heldout；同一个模板的不同文件名不应当作全新泛化任务。

该案例连接 ReTerm 的恢复思路、MiMo 的成功质量信号与 OPD 学生状态；它本身不是这些论文的原始实验。[16] [27] [30]

案例 B：Harbor 科学分析，验证设计和统计产物

任务输入为允许公开的 count matrix、样本 metadata 和预先定义的分析要求：在指定统计方法、协变量和 contrast 下，输出基因统计表及 provenance。这里没有假定任何真实生物结论，也不填虚构显著基因数。

过程具体不变量可能失败与反馈
样本对齐按 ID 显式 join，列与行集合一一对应不按 ID，只按行序；文本反馈指出错位样本
设计构建预定协变量、design 满秩、足够自由度条件与 batch 混淆；不能仅看模型“跑完”
contrast指定 treated−control 的方向与因子编码效应符号反向；独立参考与方向检查
统计与多重检验方法、过滤与调整范围固定，字段一致把 pvalue 当 padj、重复调整或选择性报告
最终产物schema、唯一基因 ID、覆盖、数值容差和 provenance表存在但内容错、NaN处理不符、输入哈希错

信号设计：结果、过程和特权信息各有边界

Outcome 由独立 verifier 在指定产物上验证。过程信号只奖励预定可检查不变量，例如 ID 对齐与 design 合法性；不奖励“显著基因更多”。数学误差容差按统计方法、数值精度和库版本制定，不能以宽容差掩盖 contrast 错误。

SFT 数据应来自实际可重放的分析过程；拒绝采样经独立参考筛选；RLDS 可按输入/设计/拟合/验收分子任务，但奖励份额与定位噪声要消融；SDPO 可用 runtime error 或 verifier 文本反馈；OPSD 的参考解法仅供训练教师 context，不能出现在留出任务学生输入。

受保护 verifier 使用新 sandbox 和选定 artifacts，避免读取全部 Agent 工作区；按 Harbor 固定版本测试任务模式。按研究、数据来源、分析模板和代码谱系切分，避免同一研究不同基因子集分别进入训练和评测。[53] [54]

科学失败需区分环境包安装、资源不足、模型方法错误、统计设计错误和生物解释未经证实。前四类可由可执行任务判定；解释的科学真实性还需专业审阅，不能仅由一个 LLM judge 当终评真值。

案例 C：GUI 修改指定草稿事件时间并保存

在可重置的本地测试应用中，将指定 draft 事件 event_id 改为给定时区下的开始时间，保持标题、参与者和结束时长等约束。使用合成测试数据，避免把生产日历或实际发送动作混入教学实验。

阶段模型观察 / 动作环境与独立验证
定位根据截图/DOM 找对应事件与权限状态检查真实 ID 与 draft 状态，不能只按相似标题
编辑选择日期、时间和正确时区，保留其他字段记录输入控件与页面状态，处理本地化/时区转换
保存与等待执行保存，等待响应，再读取确认网络响应等待不按次数累计 reward；区分服务失败
终评给出证据一致的完成回复受保护持久化状态验证目标 ID、时间、权限和其他字段

UI 显示更新可能只是未保存的客户端状态；点击按钮不等于数据库已变。过程检查可验证对象定位和持久化确认，但不能奖励反复打开、点击和等待。任务预算应包含动作数、截图/模型 token、环境时间和 reset 成本。

SFT 学观察到动作的映射，恢复数据覆盖保存失败和控件状态变化；多轮 RL 学结果驱动决策；Guided-OPD 的逐回合教师可以帮助早期状态覆盖，但部署终评必须全学生执行。GiGPO 若以截图作为 anchor，需额外核验隐藏状态等价。[34] [41]

训练按应用、任务模板、布局和语言等维度分层，泛化用未见布局/对象和独立状态 oracle。相同页面换颜色不应被包装成广泛 GUI 泛化；截图正确性、权限和任务结果分别统计。

E4 · 状态覆盖teacher、loss、任务来源与训练预算自主 OPD vs MOPD2前缀 vs Guided/TISD全学生终评，示范/接管/干预的额外成本
E5 · 信用分配固定 rollout、outcome、任务划分episode广播 vs step/子任务/anchor/value定位校准、恢复、过程投机和真实终评
E6 · 异步系统模型、算法、任务池与硬件lag、同版本对齐、完成配额分别消融dispatch/接受/训练域占比，有效token、总成本与成功

同生成 token 比较学习效率；同 GPU / 环境总预算比较可交付收益。至少多个 seed，报告重复运行/采样误差与失败分布。若算法同时改变算力、来源、teacher 和 verifier，只能称整套方案比较。

设计中没有填具体 GPU 数、学习率或预期提升，因为模型规模、环境速度和预算尚未固定。开始训练前按实际 framework recipe 锁定这些值，再生成可运行配置。

诊断和成本：平均 reward 之外必须看到什么

指标组记录什么用于判断
结果与泛化固定harness下逐域成功、错误类型、OOD能力、违规真实提升、遗忘、reward hacking
训练信号全同reward组、std、advantage、loss分母、entropy、ratio与clip有效学习机会和更新稳定性
教师与过程KL、反馈有效性、过程定位校准、teacher成本学生更像教师是否真的改善任务
系统与配额queue年龄、策略版本、domain四层占比、重试与拒绝异步对齐、completion bias、资源瓶颈
Cost_total = rollout + training + teacher/critic/grader + environment + retry/rejection + synchronization 成功成本 = 同一评测协议下总推理/环境成本 / 独立通过任务数 训练收益另报：留出成功增量 / 训练总GPU小时；基线与预算固定

成功数为零时成本比不可定义，不填 0；pass@k、单次成功、重复运行平均和 time budget 要分别报告。共享基础设施的计费分摊需说明，不能将算力百分比直接换成美元。
