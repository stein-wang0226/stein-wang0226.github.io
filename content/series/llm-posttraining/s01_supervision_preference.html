先分开四条轴：数据、反馈、目标与参数更新方式

“有好答案”不自动决定做哪种后训练。完整动作示范可以做 SFT；同题好坏候选可以做偏好优化；当前策略和 verifier 可以构成 RL；教师条件分布可以构成 OPD。LoRA、全参数和量化则回答更新哪些参数、如何存储，属于另一条轴。

SFT：目标 token、条件历史和样本权重

令 hᵢ 是预测第 i 个 token 时的历史，mᵢ 是目标 mask。对 Agent，通常学习 assistant 的动作、参数、解释和结束标记；system / user / tool 内容作为条件历史。具体角色边界由真实 chat template 决定。

L_token = − Σₙ Σᵢ mₙᵢ log πθ(aₙᵢ | hₙᵢ) / Σₙ Σᵢ mₙᵢ L_episode = − (1/N) Σₙ [Σᵢ mₙᵢ log πθ(aₙᵢ | hₙᵢ) / Σᵢ mₙᵢ]

两个分母并不等价。token-mean 使较长的目标轨迹拥有更多总权重；episode-mean 给每条 episode 相同权重，单 token 的权重随长度下降。长恢复链路与短成功路径混合时，要报告实际采用哪一种，不能只写“assistant-only SFT”。

离线训练使用示范前缀，即 teacher forcing；推理使用学生自己的动作历史。学生一个错误工具参数就可能进入示范没有覆盖的状态，随后持续偏离。这是补恢复数据、在线 RL 和 OPD 的共同动机，但三者提供的目标不同。

实现检查：模板、打包和截断

TRL 的 assistant_only_loss 需要模板提供可识别的 generation tags；开关本身不能纠正模板错误。Packing 还要检查不同样本 attention 的隔离语义，不能仅看 padding 节省。截断若切掉最后动作或结束标记，会把“未完成”训练成常见模式。[49]

# 教学检查，不是任意模型可直接运行的完整 recipe
decode(input_ids)                     # 看清真实模板与工具调用
decode(input_ids[labels != -100])      # 看清实际学习的目标
assert target_contains_stop_boundary
assert tool_observation_is_context
check_packing_attention_boundaries()
audit_truncation_by_role_and_task_family()

同时保存 tokenizer / template 版本、输入 token 和有效目标 token。train loss 降低只说明对这些目标拟合更好，不能替代未见任务、错误恢复和最终产物评测。

恢复训练：保留学生失败历史，监督可靠纠正

教学任务：函数 mean([]) 应抛出明确的 ValueError，非空列表保持原行为。学生第一次只在调用方捕获除零，工具回报单元测试仍失败；教师读真实错误后在函数入口处理空输入，再运行回归。训练要区分“失败状态的上下文价值”和“失败动作是否值得模仿”。

ReTerm §3.1 明确只对教师恢复 token 做 SFT，学生失败历史提供上下文；§3.2 的 ReTerm-GRPO 是另一个在线优化分支。GLM-5 也讨论成功轨迹内部的不良动作筛选。这些证据支持精细监督，不能推成“所有失败 token 永远都不应训练”。[16] [22]

教师恢复需要可重放和终评：修复后的公开测试通过，不代表没有修改测试或破坏其他输入。监督准入应结合独立测试、文件变更范围和恢复轨迹质量；错误观察覆盖按任务族统计，不按“轨迹最终成功”一刀切。

拒绝采样 RFT：把搜索成本与数据偏移算进去

若每题尝试 K 次、单次通过率为 pₓ： 至少一个可保留解法的概率 = 1 − (1 − pₓ)^K 若保留全部成功轨迹：期望条数 = K pₓ

同样的 K 会让容易题贡献更多训练条数，难题可能完全消失。只保留每题一条减少条数偏移，却不能救回零成功题；补教师、调整难度、增加预算或放弃任务需要分别记录。弱 verifier 还会筛进投机解法。

报告候选总 token、执行与判分时间、通过率、去重率和最终监督 token。同样大小的 SFT 数据可能消耗完全不同的搜索算力；与 RL 比较时，仅对齐保留下来的数据量会隐藏差异。

偏好优化：从 DPO 到无需成对标签的 KTO

设 y+ 与 y− 是同一任务的偏好轨迹。DPO 将相对于参考策略的对数概率差转成偏好分类，标准离线版本没有每步环境探索。[12]

L_DPO = − log σ(β [log πθ(y+|x)/πref(y+|x) − log πθ(y−|x)/πref(y−|x)])

教学 chosen 是函数入口检查空输入且回归通过；rejected 是直接把所有异常吞掉、返回 0。标签应反映任务约束，而非回复更礼貌。Agent 的 log π(y|x) 只累计策略生成动作的概率，工具输出作为条件；不能把环境观察也当作模型选择。

方法反馈与关键机制参考模型使用时的边界
DPO [12]成对偏好，参考相对 log-prob 差需要离线覆盖和标签质量；β 与长度、概率和数据共同作用
SimPO [13]平均 token log-prob 作为隐式 reward，加入偏好 margin不需要长度归一化改变目标，不是简单删掉 DPO 的 reference
ORPO [14]chosen 的 SFT，加 odds-ratio 偏好惩罚不需要同时提升示范拟合和偏好差；其 odds 语义不同于直接 log-ratio
KTO [15]非成对 desirable / undesirable 标签，参考 KL baseline需要好坏样本比例和权重需要校准，不等于任意二值任务 reward 的在线 RL
rθ(x,y) = β / |y| · log πθ(y|x) L_SimPO = − log σ(rθ(x,y+) − rθ(x,y−) − γ)

新策略遇到静态偏好对没有出现的环境状态时，仍可能无法恢复。在线收集偏好可更新数据覆盖，但属于额外过程；不能由此认为离线 DPO 已完成 PPO / GRPO 的探索功能。偏好、执行正确性和成本最好分别报告。

强化 RFT：grader 必须对应任务意义

OpenAI Cookbook 用生命科学描述生成短答案，讨论 exact、fuzzy 和 model graders。这个案例说明 grader 的可用形态，不证明字符串相似就能判断科学正确；模型 grader 需要留出标注校准，不能只在训练答案上验收。[17]

教学代码任务更适合执行测试与变更限制：先判环境是否正常，再判补丁是否正确；错误类型、超时与基础设施故障分别记录。强化 RFT 是反馈循环的称呼，具体采用何种 actor/critic、ratio 或 baseline，要由实现文档说明，不从 API 命名推断。

RLHF、RLVR 主要区分反馈来源；PPO、GRPO 主要区分优化目标；异步训练描述执行系统。把它们分开，才能判断失败应该改标签、补数据、换算法，还是修运行环境。

进入 RL 或 OPD 前应交付什么

交付 checkpoint、tokenizer、template、工具 schema、训练谱系、数据来源族和独立评测。先确认策略能执行动作、正确使用工具观察、按证据结束；否则大量全失败组可能只反映协议尚未学会。
