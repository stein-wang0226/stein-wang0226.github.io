后训练方法按反馈来源区分

SFT 告诉模型“在这个条件下应当生成什么”；偏好优化告诉它“哪条回答相对更好”；RL 让当前策略尝试任务，再用结果更新；蒸馏则把教师信号转给学生。这几类方法可以循环组合。

SFT：把能力变成稳定行为

在 CSV 例子中，Base 可能知道如何过滤空行，却需要学习工具 schema、调用顺序、检查产物与停止条件。训练样本应来自可执行且可信的操作轨迹，覆盖常规完成、有效错误恢复、长任务与边界情况。

Mask=0 不会切断条件信息

模型不直接拟合工具结果的 token，但后续动作预测仍依赖这些观察，梯度会通过模型计算影响参数。对工具返回应用 detach、移除观察或更改 attention，是其他操作，不能等同于简单屏蔽预测目标。

成功轨迹也可能含错误动作

一条最终成功轨迹可能先调用错误命令，再根据观察修复。可以保留真实失败观察作为恢复上下文，同时决定是否监督错误动作本身。GLM-5 公开了对不希望模仿的动作回合做目标筛选的做法；不能简单地把整条最终成功轨迹的所有 assistant 回合都当作正例。[3]

另一方面，过度筛掉所有失败观察会让策略只见到理想流程。筛选应明确“保留哪些上下文、监督哪些动作、为什么”，并用未见错误恢复任务验收。整条未验证失败轨迹可以供奖励、偏好或分析使用，不宜无条件混入模仿正例。

数据质量、覆盖与训练预算

对 Agent SFT，最终 reward 只是筛选维度之一。还需检查工具可执行性、环境状态、产物正确性、动作是否绕过规则、重复度、教师特征和训练 / 评测同源泄漏。Qwen3-Coder-Next 的验证轨迹与跨框架实验说明，质量与 scaffold 覆盖要同时管理。[2]

Full fine-tuning、LoRA 或其他参数高效方法是更新参数的方式，与 SFT / RL 目标不是同一维度。小预算可用 PEFT 做探索，但不能默认它与全参数工业训练具有相同容量和遗忘特性。最终比较仍需固定起点、有效目标、训练量和部署配置。

拒绝采样 RFT：先搜索，再把可靠路径变成示范

CSV 任务可以采样多条路径，用最终文件的表头、行数、内容和路径验证，留下可靠示范。自然语言声称“写好了”不是 verifier；只检查文件存在也不足以区分全删、漏删或内容错。

拒绝采样改变训练分布：容易成功的任务可能被大量保留，难题完全消失；某种错误捷径可能恰好通过弱 grader。记录每任务尝试数、通过率、筛选原因和覆盖；必要时配额采样或补充可信示范。筛选后的 loss 看不到被丢弃路径的相对好坏，这与在线策略梯度不同。

与“对成功 rollout 做 SFT”的关系

对成功 rollout 做监督训练是一种拒绝采样式流程，但命名不重要，协议重要。报告采样模型、温度、每题候选数、过滤标准、去重、总生成 token 和 SFT 预算，才能与直接 SFT 或 RL 比较。

R1 的后训练不是一条 SFT→RL 直线：cold-start SFT → 推理 RL → 拒绝采样与其他数据 SFT → 后续 RL；R1-Zero 则展示从 Base 直接 RL 的不同分支。两条路径不能混成同一个实验。

偏好阶段的输入与产物

输入是同prompt的可靠chosen/rejected，产物是相对参考策略更符合偏好的checkpoint。CSV清洗例子必须按文件结果形成标签；DPO、SimPO、ORPO与KTO的目标差别见偏好主讲章。

DPO：固定偏好对上的优化

对同一 prompt，数据提供 chosen 与 rejected。DPO 用参考策略消除一个显式 reward model 的中间求解，将偏好转化成直接策略目标；标准离线 DPO 不必在每步运行工具环境。[17]

L_DPO = − log σ(β [log πθ(y+|x)/πref(y+|x) − log πθ(y−|x)/πref(y−|x)]) y+：chosen；y−：rejected；β 控制相对参考策略的尺度。

CSV 的 chosen 可以是通过产物验证的有效轨迹，rejected 是同任务下会误删合法行或未完成写入的轨迹。偏好标签应来自可靠检查，不能只根据回复口吻。多轮 Agent 轨迹的概率与动作 mask、工具观察和序列化要定义清楚；整段字符串概率不能不加区分地包含环境生成的观察。

DPO 适合有稳定偏好对的任务，但离线数据可能覆盖不到当前策略的新错误。在线收集偏好可以缓解分布漂移，那是额外的数据更新过程。它仍不能被自动视为 PPO / GRPO 的同义词。Llama 3 的 SFT / DPO 链路是公开偏好后训练参考。[16]

强化 RFT：转到结果反馈循环

Reinforcement fine-tuning 使用自定义 grader 给当前模型输出打分，并以强化学习方法更新策略。官方文档中的 RFT 用的是这个含义。本系列把它归入下一章的 rollout → reward → policy update，不与拒绝采样后的交叉熵混用。[25]

当任务有独立、可信的结果验证，RL 能利用“成功或更接近成功”的信号；当 grader 无法可靠区分正确与投机，训练可能持续强化错误。即使奖励是二值，任务难度、采样次数、长度与探索预算仍然影响学习信号。

InstructGPT 的经典 RLHF 路线是 SFT→人类偏好 reward model→PPO；RLVR 使用可验证答案或执行测试作为奖励来源。RLHF / RLVR 描述反馈来源，PPO / GRPO 描述优化算法。 两条轴不能混为一张单线阶段列表。[19] [20]

教师信号的阶段交接

静态教师轨迹交给SFT，学生状态上的教师信号交给OPD。保存教师支持范围、可用logits或采样接口、专家路由和学生独立验收；V4与Ultra对信号粒度的分歧及多教师细节见OPD主讲章。

蒸馏：静态教师答案与 OPD 的条件分布不同

离线蒸馏可让教师预生成高质量解法，再用学生 SFT。它省去每步教师评分，却让学生主要学习教师访问过的路径。OPD 则让学生自己采样，教师在学生实际遇到的 prefix 或状态上给出信号，减少只学理想教师路径的偏移。

L_OPD = E[s ~ student rollout] KL(πstudent(·|s) || πteacher(·|s)) 这是 reverse-KL 的概念形式；实现还需处理采样梯度、支持范围与正则。

完整词表计算要获得 teacher 的 logits / log-prob 分布，并处理词表兼容、温度和代价；采样 token 的近似节省分布传输，却引入估计与优化差异。只把已采样 token 上的两个 log-prob 相减，不能无条件当成可直接反传的完整目标。

轨迹准入与教师接口：成功不是唯一条件

SFT科学轨迹需同时满足artifact验收、公共任务与许可、版本 / 模板一致、真实工具输出和准确token spans。不能仅按最终成功给整条历史所有assistant动作监督；可保留可验证的修复路径，但误删输入或无依据猜测应单独审查。科学轨迹schema将动作状态、观察和artifact关联起来。

OPD还需教师在学生实际prefix上提供兼容概率或评分：完整词表KL要求词表 / token化及条件支持可对应；API只给最终答案或少数top logprobs不能直接实现完整词表reverse KL。教师对“从学生错误状态继续”的覆盖和成本另评估，不能把离线教师答案SFT称为OPD。已有V4 / Ultra的不同报告保留在蒸馏节。

全参数与LoRA / QLoRA是更新选择，不改变SFT / RL反馈来源的定义。其状态和合并限制见训练05；同预算科学对照见sci-posttrain方案。
