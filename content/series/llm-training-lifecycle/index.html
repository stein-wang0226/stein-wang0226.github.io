Research notes · 2026-11-14

先看链路：能力、行为与反馈如何接起来

预训练获得通用知识和生成先验；CPT／Midtraining 调整领域、结构与交互分布；SFT 让模型模仿可靠行为；RL 通过实际结果改进决策。每一步都要说明起始权重、输入数据、优化目标、输出 checkpoint 和验收条件。

最关键的术语修正：CPT 描述“从已有权重继续训练”，Midtraining 描述训练链路中的准备阶段，SFT 描述监督训练方法。Midtraining 内可以对 trace 使用 assistant-only loss；看到相同 loss，不能推断它们是同一阶段。RFT 则必须写全名：拒绝采样微调与强化微调是两种方法。

沿途究竟交付什么

环节输入与优化对象核心产物下一步如何检查
Pretraining文档 / 代码 token；预测后续 token，部分配方含 FIM通用 Base、tokenizer、数据与训练状态留出损失、通用能力、代码 / 数学、多语言和长上下文
CPT / Midtraining已有 Base；领域与通用回放，结构上下文、QA、masked trace领域或 Agent Base；配比、角色目标与回归报告固定下游 SFT 的最终增量；并行监测原有能力
SFT / 拒绝采样 RFT可靠示范、采样后通过验证的路径；目标动作交叉熵能遵循协议的策略；模板、工具 schema 与监督来源工具调用合法性、独立任务成功率、错误恢复与泛化
DPO / RL偏好对或策略 rollout；相对偏好 / reward偏好策略或结果驱动策略；参考模型、奖励和采样状态独立 verifier、多维能力、成本与失败分布
OPD / 最终交付学生状态上的教师信号；可汇总多个专家统一学生模型及推理 / 环境配置检查专家能力保留、教师支持范围、同预算终评

权重文件不能单独定义一个可复现的 Agent。Chat template、工具名称与参数、停止标记、最大上下文、环境镜像、verifier 版本和生成预算，都可能改变同一 checkpoint 的结果。

4 个学习环节

用同一个 CSV 清洗任务贯穿文档、代码变更、轨迹、监督目标、reward 与最终产物验证。

工业链路正在扩展训练上下文的结构。 仓库、issue–PR、CI 日志、函数依赖和工具工作流提供了不同信号；它们不能统一简化成“多收集一些长轨迹”。Nemotron 的混合配方有直接受控证据，Qwen 与 GLM 提供工业规模参考，MidTool 和函数级 FIM 提供更小规模的设计实验。[1] [2] [3] [5] [8]

固定后训练只能解释初始化贡献。 相同 SFT 下模型变好，说明这段训练改善了后续起点；要判断它是否比把同样预算投入 SFT 更值得，必须另外对齐总算力。输入 token、有效目标 token、FLOPs 和 GPU 小时是不同口径。[1]

平均能力保留不等于没有遗忘。 PRISM 的部分配置综合平均略增，但 HellaSwag 或长上下文分项明显下降。需要逐项验收和通用回放，配比通过消融选择。[6]

后训练已经常见循环、专家化与蒸馏。 推理 RL 可以产生新的 SFT 数据；专家策略可以在学生状态上提供 OPD 信号。但 V4 与 Ultra 对完整词表 / 采样 token 的结果不同，不能从一个实验选出通用默认方案。[10] [11] [13]

以下数字均为作者报告，本地没有复现模型训练。公开技术报告与预印本不代表独立第三方验证。CSV 示例、mask 伪代码和 Harbor A–E 方案属于教学与待执行建议。

对原 Midtraining 调研的修订

需要澄清的内容复核后口径
Olmo 3 长上下文预算7B 是 50B 训练 token，32B 是 100B；不能统一写成 50B。
MidTool 的 91% 数据Web / PDF / Code 桶均含原始内容及合成增强；9% 是另列的原生 Agent 轨迹，不能把剩余部分称为纯自然数据。
Function-Aware FIMGemini 3 Flash 生成 rationale 和候选函数体，ground truth 用于 judge 过滤；部分实验从 Instruct 权重起步。
工具返回 mask 的提升27.5 → 37.8 来自 100B midtraining 接早期 SFT 配方；不能拼到 Lightning-LC 的 full SFT 行。
“单次”评测与成本Nemotron SWE 每题 3 次 rollout 平均、TB 每题 8 次平均；单次训练比较不等于每题只尝试一次，也没有证明等总算力更优。
