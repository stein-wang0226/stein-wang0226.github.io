先选择更新对象，再分配集群

Pretraining、CPT、SFT、RL 描述训练链路；全参数、LoRA、优化器和并行策略决定同一阶段怎样更新。一个工业后训练方案要同时回答：哪些参数可训练、哪些状态常驻、哪些数据被采样、哪些环境实际执行，以及谁负责验证。

先修：FFN / MoE、残差与稳定性及RL 循环。本章建立方法和资源账本，最新 Muon / FP4 型号证据见研究地图07。

LoRA 与 QLoRA：冻结底座，仍需要反向传播

W₀ ∈ R^(dout × din)，A ∈ R^(r × din)，B ∈ R^(dout × r) y = W₀x + (α/r)BAx；可训练参数 = r(din + dout) 完整矩阵参数 = din × dout；底座 W₀ 冻结

低秩限制施加在增量 ΔW，底座可以是满秩。LoRA 省去冻结参数的梯度和优化器状态；上游 adapter 要获得梯度，仍可能需要穿过后续冻结层反传和保存 / 重算激活。因此“只训练少量参数”不能直接换算为相同比例的训练计算下降。[1]

例如一个8192×8192矩阵，本文选 r=64，可训练量为1,048,576，约为原矩阵的1.56%；这是单矩阵规格推导，不代表全模型比例。若扩展到 Q/K/V/O、SwiGLU 三矩阵、router 或专家，必须分别统计真实形状与是否共享。GQA 的 K/V 矩阵通常更小。

方法改变什么主要收益对象不可省略的条件
全参数更新全部或明确选择的底座参数适应空间大权重、梯度、master、optimizer；遗忘与恢复
LoRA低秩增量；底座冻结可训练状态、多任务 adapter 交付目标矩阵、r/α/dropout、保存激活、服务端 adapter 支持
QLoRA冻结底座用4-bit存储；adapter训练底座存储和 optimizer 内存峰值NF4、double quantization、计算 dtype、paged optimizer；NF4 不是通用 FP4 训练
专家 / router 更新明确选择的 MoE 子模块领域适应与状态减少专家覆盖、冷专家梯度、路由偏移；不是自动具有 LoRA 性质

QLoRA 的原论文包含65B在48GB单卡微调的报告，这是其模型、序列和训练条件下的结果，不能据此保证任意70B长程 Agent RL可装入同样显存。NF4编码存储与BF16计算要分开；合并时 ΔW 加到反量化底座，再量化会引入新的误差。[2]

scaling = lora_alpha / r
result = base_layer(x)
result = result + lora_B(lora_A(dropout(x))) * scaling
# merge: orig_weight += delta_weight.to(orig_dtype)

scaling、merge、forward。量化 Linear、DoRA、专家参数和服务动态切换有各自分支，不由这段摘录覆盖。

AdamW、Muon 与精度：更新规则不等于权重约束

AdamW：W ← (1−ηλ)W − η m̂/(sqrt(v̂)+ε) Muon（概念）：M ← momentum(G)；U ≈ polar(M)；W ← W − η·scale(U) 梯度裁剪：G ← G·min(1, c/(||G||₂+ε))

AdamW 把 weight decay 从自适应梯度分母中解耦，不能简单等同于给 Adam loss 加 L2。Muon 近似正交化的是二维更新矩阵，不要求更新后 W 正交；embedding、输出头和一维参数的分工，以及矩形缩放、动量 / Nesterov、Newton–Schulz实现都影响结果。[3] 前沿配方与原论文。

矩阵被 TP/FSDP 切片后，独立对每块做 polar 一般不等于整矩阵更新再切片。研究方案应冻结 optimizer 的逻辑矩阵、通信、参数分组和精度，再比较 AdamW / Muon；否则“优化器收益”混入了重计算、并行和更新预算差异。

对象建议记录典型错误
模型权重 / master常驻 dtype、master 是否存在、量化尺度从FP4 GEMM推断 optimizer state 全是4-bit
梯度 / 通信累积、归约精度；裁剪前是否得到全局范数每 rank 裁剪局部梯度冒充同一个全局裁剪
Norm / router / softmax高精度保留项和 kernel 实际 dtype选择 BF16 就假定所有算子同精度
激活 / 长上下文重计算粒度、序列长度、有效目标与 packing把激活 OOM 归因于 optimizer，然后盲目减学习率

本文分析：新架构的稳定性应分解为残差传播、QK尺度、路由负载、数值范围和参数更新五个对象。loss下降只能说明当前目标被优化；通用能力回放与 held-out 任务必须独立评测。

训练诊断与恢复：保存能解释异常的状态

每步至少按任务桶保存目标 token 数、loss、梯度范数、裁剪比例、学习率、溢出 / 跳步、序列长度、专家负载、零方差组比例及policy lag。一次尖峰要能对应到数据版本和样本，避免把数据污染、非法工具输出、FP溢出或路由失衡统称为“训练不稳定”。

现象先区分的解释本文建议的待执行对照
某一批 loss / gradient spike异常文本、长序列、数值溢出、更新过大冻结样本与起点，比较精度 / 裁剪 / step；保留失败 checkpoint
训练指标升、通用能力跌分布偏移、目标重加权、遗忘、污染同预算比较 replay 比率与数据切分，不用训练集验收
MoE 一部分专家过载router漂移、token异质性、容量和dispatch分任务 / 专家看token、drop、梯度和通信；不能只看均值
恢复后行为不同遗漏 optimizer、RNG、sampler、rollout版本checkpoint同时保存数据游标、随机态、scheduler、adapter与环境镜像

恢复范围分两层：模型训练状态能够续训；长程工具环境是否能够恢复要另外定义。只恢复权重并重新采样，不等于恢复一条中断中的科学分析轨迹。对应Harness状态管理。

并行维度先分清逻辑对象

维度主要切分代价与约束
TP矩阵 / head / FFN 通道层内collective；head及矩阵可分性、KV复制
PP层与阶段microbatch、pipeline bubble、层 / 专家负载不均
CP同一长序列的上下文Attention历史交换；不是多条独立样本
DP + optimizer sharding样本；冗余训练状态梯度归约 / 状态聚合；有效batch按独立样本维度算
EP / ETP专家分配 / 单专家矩阵dispatch/combine；专家DP与普通层DP可不同
FSDP / ZeRO参数、梯度、optimizer状态的冗余all-gather / reduce-scatter；不是新增的模型层轴

ZeRO-1/2/3分别进一步分片optimizer、gradient、parameter；具体常驻buffer与临时聚合取决于实现。CP减少序列激活 / Attention工作量，不应假定它独立缩小每rank权重。[4]；原通信说明见分布式指南。

整合前异步rollout概览 · 2026-11-14

异步 rollout：提升重叠，控制数据过期

同步方案等待一批中最慢轨迹，再更新actor；异步方案让环境 / 生成继续运行，trainer有足量数据就更新。其代价是行为策略与当前策略不同。必须保留采样时的logprob和策略版本，区分概率校正、裁剪、过滤及有限lag。重新用新权重计算“旧logprob”不能还原行为策略。

固定 verl v0.6.0 的one-step-off-policy recipe提供生成 / 训练资源隔离与权重同步的实现路线；AReaL v5描述完全异步、staleness控制与PPO改动。两者不是相同算法，论文数学 / coding结果也不是本科学任务的收益证明。[6]

本文建议的接入顺序与配置边界

先以同步、相同精度 / 模板 / 动作mask建立概率一致性，再比较one-step overlap；完全异步单独消融。记录样本完成、权重同步、排队与更新时刻，区分更新次数lag和实际时间lag。长工具调用期间是否换策略须明确，最好将整条轨迹绑定同一版本或逐动作保存版本。

所选 verl 配置文件engine/megatron.yaml确有TP、PP、CP、EP、ETP与distributed optimizer字段。本文下载文件是独立方案schema，不是该框架启动YAML；容器依赖、MCore adapter和全部组合未实测，不混写两个版本的启动参数。

理解检查与下一步

LoRA参数少，为什么长上下文仍会OOM？

冻结底座仍参与前向；adapter梯度可能穿过冻结层反传，激活、Attention中间状态、logits和临时buffer不随可训练参数同比减少。

512卡、CP2、EP8时，为什么专家DP不是4？

本版本普通层DP=32，但专家视角cp=1，重组DP×CP域；ETP=TP时专家DP=32×2/8=8。世界规模始终512。

异步吞吐更高，就证明训练更好吗？

还需同资源质量曲线、同推理预算终评、过期样本比例、训练 / 环境成本和失败记录。更多过期或不可验证轨迹可能增加token吞吐却降低有效更新。

沿科学合同 → SFT / RL对照继续；服务状态和容量归推理部署系列。三条路线见统一阅读入口。
