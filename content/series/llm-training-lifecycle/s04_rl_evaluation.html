RL 的核心是采样、执行、评分、更新

训练策略不只复述示范，而是根据真实任务结果调整行动概率。Agent 中一次 rollout 包含多次“动作 → 工具观察”，最终产物由 verifier 检查。语言流畅、调用格式合法和任务完成是三个不同指标。

maximize E[reward(trajectory)] optional regularization: − β KL(πθ || πref) trajectory = actions + environment observations + final artifacts

参考策略 πref 用于控制漂移；行为 / old 策略 πold 用于采样与概率比；当前策略 πθ 是正在更新的模型。它们可能起初相同，训练后承担不同角色。把 old log-prob 换成 reference log-prob 会改变算法。

# 教学 verifier，不是 Harbor 的现成 API
def verify(task_spec, artifacts):
    output = read_csv(artifacts["out.csv"])
    checks = {
        "path": artifacts.has_expected_path,
        "header": output.header == task_spec.header,
        "rows": output.rows == task_spec.expected_rows,
        "input_unchanged": artifacts.input_hash == task_spec.input_hash,
    }
    return {
        "reward": int(all(checks.values())),
        "checks": checks,
        "verifier_version": "csv-output-v1",
    }

期望输出属于 evaluator，不能给策略作为答案。Verifier 可采用精确断言、单元测试或领域计算，也可包含人工 / 模型 grader；验证器本身必须与任务目标一致。检查文件存在太弱，重复使用训练中公开的测试又可能教会策略只满足少数已知断言。

奖励来源适用信号需要检查
RLVR答案、程序测试、文件 / 环境状态的可验证正确性测试覆盖、容差、超时、权限与污染
RLHF / learned reward人类偏好、帮助性与交互质量偏好一致性、分布外误判和 reward hacking
Model grader部分难以精确判定的任务质量提示、模型版本、长度 / 风格偏差和独立校验
成本 / 过程约束工具次数、时间、token、非法动作不要把少动作奖励变成提前停止或漏验证

最终 reward 与过程日志分开保留。成功率是主目标时，可以将成本作为独立约束或明确的组合项；不要在看到实验结果后临时修改 reward 再与旧组比较。

PPO 与 GRPO：谁提供 advantage

PPO 用概率比和 clipping 限制更新幅度，常见 RLHF 实现训练一个 value / critic 来估计回报与 advantage。GRPO 对同一任务采样一组回答，用组内相对 reward 构造 advantage，省去独立 critic，但仍需 reward、采样与策略训练。[18] [19] [20]

rᵢ,t = πθ(aᵢ,t | sᵢ,t) / πold(aᵢ,t | sᵢ,t) J_clip = E[min(rᵢ,t Aᵢ,t, clip(rᵢ,t, 1−ε, 1+ε) Aᵢ,t)] 这是策略项的简化形式；实际实现另有价值项、KL 或其他正则。
给同一任务采样 G 条轨迹，奖励 R₁ … R_G Aᵢ ≈ (Rᵢ − mean(R)) / (std(R) + ε) 把序列反馈赋给该轨迹的策略 token；具体归一化按算法版本。

若组内 reward 是 [0,0,1,1]，成功路径获得正相对 advantage，失败路径负相对 advantage。若全0或全1，组内标准化没有可区分的结果信号；此时增大训练步数不会凭空产生正确样本。需检查任务难度、采样预算、协议、奖励或示范起点。

序列 reward 广播到动作 token 是粗粒度 credit assignment：成功轨迹里也可能有无效动作。若加入过程 reward，需要验证它是否真的与最终质量一致，而不是只奖励某些表面步骤。

DAPO、Dr. GRPO、GSPO：修改的是哪一部分

方法主要变动希望解决的问题实现与比较边界
PPO [18]policy ratio + clip；常配 learned value稳定策略更新与 advantage 估计value、reference KL、采样批与更新轮数均影响结果
原 GRPO [20]同任务组相对 advantage；不训练独立 critic降低 critic 成本，利用组内相对反馈组大小、reward方差、长度和难度归一化仍重要
DAPO [21]非对称 clipping、动态采样、token-level loss、超长样本处理探索、有效训练信号和长回答的优化多项改动共同作用；不能把完整方案收益归于单一 clip参数
Dr. GRPO [22]分析并移除特定响应长度 / reward标准差归一化带来的偏差长度偏好与任务难度权重失真改变的是目标与归一化；base先验和reward仍可主导表现
GSPO [23]序列平均 log-ratio 后取exp，序列层面 clipping序列反馈与优化单位一致性，报告关注训练稳定性使用长度归一化概率比，不是原始整序列概率比的原样估计
sᵢ = exp[(1 / |yᵢ|) Σₜ log(πθ(yᵢ,t|prefix) / πold(yᵢ,t|prefix))] 序列平均 log-ratio → exp → 序列层面 clipping。 扩展到 Agent 多轮时，应明确 |yᵢ| 只计哪些策略生成 token。

“用了 GRPO”不足以复现：是按序列还是 token 平均？是否除 reward标准差？KL如何实现？组内全同 reward怎样处理？超长截断怎样打分？这些改变了实际目标。算法名之外应保存配置、代码版本和关键张量统计。

对新业务，先建立能稳定采样和可靠验证的基线，再对优化变体做控制实验。某个数学 benchmark 上有效的长度处理，不应无验证地搬到带长 stdout 的多轮 Agent。

Agent 训练系统：把长轨迹变成正确的更新批次

与单轮文本不同，Agent rollout 的耗时受工具、环境初始化、错误恢复和长度影响。把所有 GPU 等在最慢任务上会降低吞吐，异步采样能缓解，但会使行为策略落后当前策略。GLM-5 公开了异步 RL 的系统组织；细节可结合既有Agent Harness 指南。[3]

系统项必须保存 / 控制错误会造成什么
行为策略版本rollout model ID、old log-prob、采样参数概率比与实际采样分布不一致
动作 / 观察 mask精确 token span、工具与模板、结束标记把环境 stdout 当成策略动作更新
多轮上下文历史、截断 / 压缩规则与位置设置训练计算的prefix与采样时不同
环境隔离镜像版本、任务初始化、随机种子、资源限制状态泄漏、并发干扰或不可复现错误
奖励与失败原始 verifier 输出、超时、环境失败、任务失败失败被静默删除，成功率分母改变
Policy lag采样与更新的版本差、延迟、样本年龄过旧样本让近似on-policy更新失真
推理 / 训练一致性精度、模板、采样器、工具协议、log-prob口径奖励变化与优化错误无法区分

Importance ratio 与 clipping 不能无限修复任意大的 policy lag。应记录滞后分布，定义可接受窗口及过旧样本处置，监控 ratio、KL、clip fraction、有效目标和 reward分布。异步带来的吞吐收益要与策略效果及丢弃采样成本一起报告。

Harbor A–E：分别检验初始化与预算价值

本方案延续原调研，尚未执行。目标是验证 Midtraining 是否让固定后训练更有效，以及额外预算应放在哪里。使用同一可恢复 Base、冻结 Trace SFT 池与独立 Harbor 任务族留出集。

组训练路径回答的问题
ABase → 固定 Trace SFT最小可用基线
B通用 CPT → 同一固定 SFT额外继续训练本身的增量
C领域文档 / repo / PR / 日志 + 通用回放 CPT → 同 SFTC−B：相同输入预算下的领域配方增量
D从C置换部分输入 token 为 assistant-only trace → 同 SFTD−C：将轨迹提前混入的增量
EBase → 更充分的 SFT；额外预算按实测成本尽量匹配与A–D共同检验预算投向，不能仅按token声称等算力

第一层：冻结下游条件

A / B / C / D 使用相同 SFT 数据、更新配置与评测协议；C与D的工程来源相同，D用等量输入 trace替换部分C数据。B / C / D匹配输入token、长度分布、有效batch与计划步数，报告实际FLOPs、GPU小时、目标token与辅助loss。Mask影响目标密度，因此还应检查归一化与每桶目标权重。

第二层：控制总预算

固定SFT只回答初始化贡献。E将可用的额外训练资源投入SFT，并按硬件、长度、有效目标和吞吐实测匹配；教师生成、预处理、rollout与环境执行成本另列，说明是否计入总预算。若无法精确匹配，报告预算差，不用“等算力”概括。

第三层：拆出 mask 与后续 RL 因素

如D优于C，可在相同 trace与输入上做观察mask开 / 关对照，固定模板和截断并记录目标数量，区分数据加入和目标改变。再将选定checkpoint接同一RL方案，检查长RL后初始化收益是否持续；不能用公开Nemotron的短RL实验代替这一步。

预算不足时的顺序：先做A与D了解业务增量；已有稳定领域CPT时优先C与D；决定扩大投入前补E和分项回归。把成功率最低增量、能力容许回退与成本上限提前写入实验方案。

若每题采样 n 次，有 c 次成功，平均单次成功率与“至少一次成功”不同。在可交换采样等前提下，常见 pass@k 估计为 1 − C(n−c,k) / C(n,k)；多轮工具环境与不独立采样时必须说明假设和协议。

Nemotron报告的SWE每题3次、TB每题8次平均pass@1，不能称为pass@3 / pass@8。评测3个采样种子也不能称为训练3个种子；Function-Aware FIM的数字需要同样区分。

异质任务与工业系统：算法之外的四份记录

按任务族分别记录有效reward组、归一化 / clipping / token聚合、policy lag / 行为logprob、环境与verifier故障。对二元独立采样，组内奖励有差异的概率为1−p^G−(1−p)^G；极难或极易题均可能没有相对学习信号。组内标准化不自动平衡难度和梯度，长程工具执行也不由token均值充分描述。

DAPO动态采样、Dr.GRPO的归一化分析与GSPO序列比率改变不同环节，须保留本章方法区分；前沿信用方案连接研究地图02。训练 / 采样的精度、mask与routing差异也会影响logprob；重新算新策略概率不能替代保存原行为概率。
