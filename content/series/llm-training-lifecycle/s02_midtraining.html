阶段名称与训练目标要分开看

CPT（Continued Pretraining）强调从已有模型继续训练；Midtraining 强调通用训练与任务后训练之间的能力准备。工业报告里的 late pretraining、annealing、领域 CPT 与 Midtraining 有交叠，不能仅根据阶段名猜测数据和 loss。

把两条轴分别记录：位置轴是在哪个 checkpoint 后、给谁做初始化；目标轴是文档 LM、FIM、QA、masked trace 或其他损失。Nemotron 在 Midtraining 就采用 assistant-only 轨迹目标，随后仍接独立 SFT；Qwen 的同阶段混入自然工程语料、合成 QA、轨迹与少量指令。[1] [2]

名称描述的维度建议补齐的字段
领域 CPT继续训练过程与数据领域起点、领域 / 回放比例、目标、预算与回归
Midtraining能力准备阶段及下游用途checkpoint 的定位、固定后训练及数据组成
Trace SFT监督数据形态和训练方法示范来源、验证、角色 mask、模板与动作协议
Long-context adaptation窗口与长依赖适配长度课程、长样本、位置设置与真实长任务

桥接分布的研究通过受控实验分析引入时机与混合比例，支持“让预训练和后训练分布更接近”这一设计方向。它没有证明所有模型都必须增加同名阶段，也没有给出普适混合比例。[9]

工业配方：Nemotron 的混合 CPT → 固定 SFT

2026-10-15 的 Priming Base Models for Agentic Post-Training 给出 Nemotron 3.5 的具体数据桶，并比较起始 Base 与经过 Midtraining 的 Base 接受相同 SFT 后的结果。这类实验能解释初始化贡献，同时要承认 Midtraining 组多使用了训练算力。[1]

论文表1，各桶和为100%。39.4B 是唯一轨迹 token；约500B 运行读入约50.3B 轨迹 token。数据池大小、实际输入和有效监督目标分别统计。

附录B 的训练设置是 256K packed sequence、global batch size 64、文档间隔离 attention、Adam 与 BF16。Lightning / Super 学习率分别为 5e−5 / 1e−5，短 warmup 后恒定；保留 multi-token prediction 辅助目标，权重分别 0.1 / 0.3。这是该模型的实测配方，不能直接搬成小模型的默认超参数。

轨迹只监督 assistant 回合，包括工具调用；工具观察留在上下文里。PR、日志与重复内容另有目标筛选规则。整个阶段因此是按数据类型定义条件与目标的混合 LM 训练，不是所有输入一律全 token 监督。

Mask 对照支持：在这套轨迹和配方下，读取观察、只学下一步行动，比同时学习工具输出更有效。工具输出可能很长、难预测，目标分布与权重也随 mask 改变；究竟是目标噪声、assistant 权重还是优化动态带来收益，需要额外对照区分。

证据边界：相同 SFT 下的提升没有证明等总算力最优。TB2.0 的1点变化应结合重复训练与不确定性；公开 RL 延伸仅有 Lightning-8K 的短、单种子实验，不足以推断长 RL 后仍保持同样排序。

作者发现 LoCoDiff、仓库 / trace 预测损失等代理指标对最终排名不够稳定。实践上同时保留代理损失和固定下游验收；不能由此断言所有模型的 perplexity 都无价值。

为什么函数级任务与技能包可能有用

随机文件切片可能缺少实际补全所需的依赖。函数级样本有机会选择签名、调用者、相关定义和测试；技能包则把主说明引用的脚本或规范插到可读位置，减少引用落空。模型从中学习上下文关系，而不是仅学习一个长文档的局部续写。

收益可能来自结构、数据质量、教师解释或后训练配合。Function-Aware FIM 的教师合成与 Instruct 起点意味着不能把结果解释为“纯自然自监督让 Base 获得 agent 能力”。SPT 的固定预算数据置换也需要与相同预算的其他来源比较。

# 教学伪代码：具体模板、打包和并行实现按模型适配
IGNORE = -100

def encode(record, tokenizer):
    if record.kind == "trace":
        ids, target_mask = render_chat_and_tokenize(record, tokenizer)
        return ids, target_mask   # mask 基于角色和实际 token 边界
    return tokenize_document_and_mark_targets(record, tokenizer)

def update(model, records):
    samples = [encode(r, model.tokenizer) for r in records]
    batch = pack_with_document_boundaries(samples)
    targets = batch.target_mask & batch.valid & ~batch.document_start
    labels = where(targets, batch.ids, IGNORE)
    logits = model(batch.ids, attention_mask=batch.block_causal_mask)
    loss_sum, target_count = shifted_cross_entropy_sum(logits, labels)
    loss = normalize_by_global_target_count(loss_sum, target_count)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

cpt_stream = mix_by_input_tokens(

save_checkpoint(base, "agent-base")

先在未 shift 的 token 位置构建目标，再按 causal 预测对齐。新文档首 token 被屏蔽，attention 隔离独立样本。无目标样本应拒绝或跳过；分布式归一化要匹配框架的梯度求和 / 平均约定，不能简单地平均各卡不同长度样本的平均 loss。

本伪代码未展开辅助头、activation checkpointing、梯度累积或特定 kernel。若模型实现内部已有 shift，外层不要再做；若模板不能返回 assistant mask，应核对实际 token 边界，不能按原始字符串长度猜位置。

配比、回放和目标权重是三个独立选择

按样本数混合容易被超长 stdout 改变输入预算。按输入 token 设配比更便于记账，但目标 token 与梯度权重仍需单独计量。一条 10,000-token trace 若只有500 assistant目标，其输入占用与监督贡献不同。

输入配比：wₖ = bucket_input_tokens / total_input_tokens 目标配比：qₖ = bucket_target_tokens / total_target_tokens 加权目标：L = Σₖ αₖ Lₖ；αₖ 是否显式设定必须记录。

如果所有目标直接汇总做全局 token 平均，目标密度高的数据桶贡献较多。若先按每桶均值再加权，效果又不同。比较观察 mask 时，应固定相同轨迹与输入长度，同时报告有效目标、归一化方式和 assistant 梯度权重，避免误把目标重加权解释为单一语义因素。

回放用于缓解遗忘，但比例取决于模型、目标、预算与接受的回归。PRISM 的分项下降说明不能只看综合平均。建议先冻结通用、领域、长上下文与指令基线，定期评估；再比较配比、训练时长和数据质量，保留可回退 checkpoint。[6]

继续训练前的决策清单
  • 当前缺口是知识、依赖结构、工具协议还是决策质量？能否先用较小 SFT 验证？
  • 起点究竟是 Base 还是 Instruct？是否需要保留既有对话行为？
  • 数据是自然来源、合成增强还是原生执行轨迹？是否保留来源族和验证记录？
  • 比较的是同 SFT 初始化增量，还是严格预算投资？教师、预处理和 rollout 成本是否纳入？
  • 下游 SFT、harness、模板、停止条件与评测集是否冻结？

Harbor：把“值得继续训练吗”变成可检验问题

从同一 Base 建立 A=直接固定 Trace SFT；B=通用 CPT→同SFT；C=领域+回放 CPT→同SFT；D=从C置换部分输入 token 为 assistant-only trace→同SFT。B / C / D 匹配输入预算和长度分布，再实际核算 FLOPs / GPU 小时。

A–D 检查初始化增量；C−B 检查领域配方；D−C 检查轨迹提前混入。再加 E，把额外计算用于更充分的 SFT，才更接近业务预算选择。固定输入 token 不能自动证明总算力相等，mask 改变也必须报告有效目标。

完整的任务切分、verifier、记录 schema、统计与成本控制见第四章 Harbor A–E 方案。原调研的建议在这里保留，并修正“对齐 token 就等算力”的表述。
