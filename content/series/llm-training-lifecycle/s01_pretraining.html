预训练要得到什么样的起点

通用 Base 学习文本与代码中的知识、结构和条件分布。它可能已经能续写推理、解释错误或生成工具调用的文本，但尚未保证稳定遵循对话协议，也没有直接以真实任务成功率为优化目标。

贯穿四章的例子是：“读取 sample.csv，删除 value 为空的行，写入 out.csv。”完成它需要 CSV 知识、代码能力、工具协议和执行验证。预训练主要提供前两类先验；Midtraining 加强工程上下文，SFT 教可靠操作，RL 用环境结果改进策略。这个分工帮助定位问题，但能力会跨阶段重叠。

数据治理先定义分布，再定义训练量

“训练了多少 token”只描述读入量。质量、重复次数、知识覆盖、样本之间的关系和评测污染，会改变同样预算的效果。Llama 3 与 Olmo 3 报告都把数据治理和配方作为核心训练工程。[16] [4]

步骤实际处理应保留的证据
来源登记记录抓取 / 发布版本、语言、许可、仓库和提交；按来源分类source ID、内容 hash、来源时间、许可与允许用途
解析与质量过滤剔除模板噪声、损坏编码、无意义重复；保留对目标有用的公式、代码与结构过滤规则版本、每桶保留率、抽样人工检查
去重与污染隔离文档级、片段级近重复；检查评测题、解法、同源 PR 与衍生样本去重簇、split ID、污染检测范围和例外记录
样本组织文档边界、文件路径和结构；避免误把互不相关内容视为连续故事序列化格式、边界标记、截断策略
混合采样按 token / 样本 / source 的明确口径设置权重与重复次数唯一 token、实际见到的 token、各桶有效目标数
训练 / 验证划分尽量按来源族或仓库隔离，防止同一内容的改写分别落入两侧冻结留出集、近重复检查结果、版本清单

例如 20B 唯一数据被反复采样到 100B 输入，不能称为 100B 独立知识。若把训练完成的补丁、测试答案或 verifier 输出放进评测提示，就改变了任务条件。数据污染既可能发生在预训练，也可能由后续合成与拒绝采样传播。

数据混合：配比、重复次数与有效监督分别记账

先按来源冻结留出集，再比较候选配比。混合并非“高质量桶越多越好”：小桶被反复读取可能过拟合，代码比例提高也可能挤压多语言覆盖。建议先在固定小模型、token预算和学习率调度上比较，再把候选带入规模阶梯；这是实验设计建议。

设桶 \(j\) 有 \(U_j\) 个可用唯一token，总预算为 \(D\) 个输入token，按token口径分配比例 \(p_j\)，且 \(\sum_jp_j=1\)。\(D_j\) 是该桶的计划读取量，\(r_j\) 是平均重复倍数；\(f_j\) 是读入token中参与直接loss的比例，\(\tilde p_j\) 是全局目标token平均下的目标数量占比。

\[ D_j=p_jD,\qquad r_j=\frac{p_jD}{U_j},\qquad \tilde p_j=\frac{p_jf_j}{\sum_kp_kf_k}. \]

算例：代码桶 \(U=10\mathrm B\)、总预算 \(D=100\mathrm B\)、代码占比20%，对应读取20B、平均重复2次。若其直接目标比例为0.5，其他80%输入全部算loss，则代码只占 \(0.2\times0.5/(0.2\times0.5+0.8)=11.1\%\) 的目标数。B表示十亿token；这里没有假定每个目标梯度大小相同。

按样本采样时还要乘平均长度；按桶分别求平均再加权时，上面的 \(\tilde p_j\) 也不再是目标系数。预训练常有 \(f_j\approx1\)，角色mask在Midtraining/SFT更关键。终评同时保留每桶loss、重复量、下游分项与训练总成本，避免平均loss掩盖小桶退化。

Causal LM：每个 token 的条件预测

\(x_{1:n}\) 是长度 \(n\) 的 token 序列，\(x_{\lt i}\) 是第 \(i\) 位之前的前缀，\(\theta\) 是模型参数；\(\prod\) 将各位置条件概率相乘，log 为自然对数，\(L_{\rm LM}\) 为有效目标位置的平均负 log-prob。预算节的 \(N\) 是参与矩阵计算的参数元素数，\(T\) 是实际处理 token 数，\(C\) 单位为 FLOPs，区别于数据序列长度 \(n\)。

decoder用前文预测下一token，训练可同时计算已知历史下的多个位置。条件概率因子分解、softmax梯度与shift已在架构页展开；这里关注数据进入目标时的边界与分母。

\[ p_\theta(x_{1:n})=\prod_{i=1}^np_\theta(x_i\mid x_{<i}),\qquad L_{\rm LM}=-\frac{\sum_i m_i\log p_\theta(x_i\mid x_{<i})}{\sum_i m_i}. \]

\(m_i\in\{0,1\}\)表示目标是否有效；padding和需隔离的文档起点按配方处理。两文档例：将[甲,乙]和[丙,丁]打包时，乙→丙这条跨文档预测应依约屏蔽，丙→丁仍有效；attention也需阻断第二文档读取第一文档。loss mask本身不能完成注意力隔离。

普通文档的多数 token 都是目标。对拼接的独立文档，可以隔离 attention 并屏蔽新文档首 token 的 loss，防止前一文档末尾被用来预测后一文档起点。不同配方可能采用不同边界规则，必须在数据与模型实现中保持一致。

# 概念上的 shift；不是特定框架 API
input_ids   = [BOS, "CSV", "rows", "exclude", "header", EOS]
target_mask = [  0,     1,      1,         1,        1,   1]

# logits 在当前位置预测下一位置
loss = cross_entropy(logits[:, :-1], labels[:, 1:])

# labels 对应当前 token 的身份；target_mask 先在未 shift 的位置构建。
# 模型 API 若内部已 shift，不能在外部再 shift 一遍。

优化器更新的是模型权重。训练目标不会直接证明“CSV 已被正确清洗”：模型可以对说明文本损失很低，却调用错工具、误删合法的 0，或在文件没写好时声称完成。后续阶段需要引入行动分布与结果验证。

FIM：把补全与编辑条件编码进因果序列

Fill-in-the-Middle 将原文切成 prefix、middle、suffix，再序列化为“已知前缀 + 已知后缀 → 中间缺失内容”。仍用自回归交叉熵；模型是在重排后的序列上预测 token。原始 FIM 研究表明，这样可以让 decoder 学习中间补全，并研究与正常续写的混合。[15]

# 原文件
def clean(rows):
    return [r for r in rows if r["value"]]

# 示意序列；实际 special token 由模型 tokenizer 定义
<fim_prefix>def clean(rows):
<fim_suffix>
# callers / tests may follow here
<fim_middle>    return [r for r in rows if r["value"]]

重排顺序、截取位置和目标范围都影响任务。FIM 不自动保证 prefix / suffix 完全不算 loss，也不自动建立多文件依赖。函数感知 FIM 会额外选择调用者、相关定义或测试等上下文；第二章讨论其合成教师与实验边界。[8]

从目标理解能力：文档 LM 学“这里通常接什么”，FIM 学“在已知前后文下缺什么”，trace 监督学“给定历史和观察下一步做什么”。三者都能落到 token 交叉熵，但条件分布不同。

算力预算：参数、token 与实际吞吐

相关原论文 / 官方资料：Chinchilla。

Chinchilla 讨论的是固定训练算力下，如何同时选择模型规模与数据量。它不能被简化成对所有部署目标都有效的固定 token / parameter 比例。模型长期推理成本、数据质量、MoE 激活规模和继续训练价值会改变取舍。[14]

\(6NT\)从哪里来，何时不够用

对稠密矩阵 \(y=xW\)，一次乘加按2 FLOPs计；每token的矩阵前向约 \(2N\)。反向既计算输入梯度又计算权重梯度，两次相似矩阵乘法合计约 \(4N\)，前后向约 \(6N\)，再乘实际处理token数 \(T\)。

\[ C_{\rm forward}\approx2NT,\quad C_{\rm backward}\approx4NT,\qquad C_{\rm train}\approx6NT. \]

教学例：\(N=10^6,T=10^3\)，这部分约 \(6\times10^9\) FLOPs。它是矩阵计算粗估，未含长上下文QK/AV、重计算、辅助头、MoE路由、通信与故障恢复；不能直接称为整个训练实测成本。

MoE 的总参数量决定权重存储的一部分成本，激活参数量更接近单 token 前馈计算量；不能仅把总参数代入来横比训练效率。GPU 小时还取决于并行、通信、padding、重计算、精度与故障恢复。Mask 掉某些目标通常仍需要它们的前向和上下文计算，因此“少算 loss”不等于同比节省输入算力。

统计量含义常见误读
唯一 token去重后的语料容量，明确 tokenizer把重复采样量当成新增数据
输入训练 token模型实际读取量；明确是否计 padding不同长度 / packing 的计算成本被当成相同
有效目标 token产生监督损失的位置数按输入 10% 的 trace 被当成 10% 梯度权重
FLOPs / GPU 小时计算量与硬件占用的实测口径相同 token 被称为严格等总算力
端到端预算预处理、训练、教师、rollout 与验证成本只比较策略更新 GPU，却忽略合成和环境执行

DeepSeek-V4 公开 32T+ 训练量及长上下文阶段，官方模型卡也给出同一大规模链路；Nemotron 3 Ultra 报告 20T 预训练。它们展示工业投入规模，无法由总 token 独立解释最终质量。[10] [26] [11]

Scaling Law：固定算力，怎样分配模型与数据

先分清三个问题：Scaling Law 拟合规模与损失的经验关系；compute-optimal allocation 在预算内选参数量和训练量；scaling ladder 则用逐级实验检验能否外推。预训练 loss 的规律不能直接当作 Agent 成功率规律。

基础来源：Kaplan 等，2020；Chinchilla，2022，§2–3。前者强调幂律与提前停止，后者联合改变模型和训练时长，得到更均衡的规模分配。下列优化推导采用 Chinchilla 的可分离损失模型；它是经验拟合假设下的数学结论。

\(N\) 为稠密模型参数数，\(D\) 为处理的训练 token 数（即上一节的 \(T\)，不保证独立）；\(L\) 为同一验证分布、同一 tokenizer 下的平均交叉熵，单位 nats/token。\(E\) 为拟合的损失下限，\(A,B>0\) 为尺度系数，\(\alpha,\beta>0\) 为拟合指数；系数取决于 \(N,D\) 的计数单位。\(C\) 为训练 FLOPs，\(\kappa\) 为每参数每 token 的计算系数，稠密主矩阵粗估取6。

\[ L(N,D)=E+A N^{-\alpha}+B D^{-\beta},\qquad C\approx\kappa ND. \]

代入预算，再令边际收益平衡

固定 \(C\) 后，增大 \(N\) 就必须减小 \(D=C/(\kappa N)\)。因此只需最小化一个变量；对 \(\log N\) 求导可以直接比较两项收益。

\[ \begin{aligned} L(N\mid C)&=E+A N^{-\alpha}+B(\kappa N/C)^\beta,\\ \frac{\partial L}{\partial\log N} &=-\alpha A N^{-\alpha}\\ &\quad+\beta B(\kappa N/C)^\beta=0,\\ N_*&=\left(\frac{\alpha A}{\beta B}\right)^{1/(\alpha+\beta)} (C/\kappa)^{\beta/(\alpha+\beta)},\\ D_*&=\frac{C}{\kappa N_*}\ \propto\ C^{\alpha/(\alpha+\beta)}. \end{aligned} \]

\(*\) 表示这个拟合模型内的最优点；\(\propto\) 表示忽略固定比例系数。对 \(\log N\) 的二阶导为 \(\alpha^2 A N^{-\alpha}+\beta^2 B(\kappa N/C)^\beta>0\)，故驻点为最小值。最优条件是加权边际收益相等，不要求两个损失项本身相等。

当 \(\alpha\approx\beta\) 时，参数和 token 都近似按 \(\sqrt C\) 增长。这解释了“预算扩大，两者一起扩”的方向，但没有推出普适的 \(D=20N\)：比例还依赖系数、数据分布和训练配置。

原论文口径可以记住的结论适用边界
Kaplan；Chinchilla §2 对前序结果的比较算力增加10倍，前序配方约把模型扩大5.5倍、数据扩大1.8倍实验规模、训练时长与学习率衰减的处理不同，不能只比较年份
Chinchilla §3 的三种估计方法模型与训练 token 近似等比例扩展；用曲线包络、IsoFLOP 和参数拟合交叉判断各方法指数不完全一致；不是任何规模都精确平方根
Chinchilla Table 170B 参数、1.4T token，即该模型约20 token/参数这是一个训练配置及其研究背景，不是所有模型的统一配方

Scaling ladder：从小实验走到大规模训练

实验阶梯是验证流程，不是把同一个模型一路续训变大。不同规模通常需要独立训练；固定模型改变训练时长，与同时改变深宽/专家数，是不同实验轴。下面为工程组织建议，未执行本地训练。

实验层固定什么 / 改变什么产物与放大条件
算法与超参数阶梯固定模型、数据、目标和预算；改变 optimizer / LR / batch 等单轴，必要时检查交互稳定区间、loss 曲线、梯度与更新尺度；保留调参总成本
规模阶梯明确宽度、深度与头数的构造规则；各规模改变 D，分别完成相应 schedule每点保存 N、D、FLOPs、最终验证 loss；更大一级留作外推检验
系统阶梯同一逻辑目标，扩大卡数或改变 TP/PP/CP/EP、精度与分片有效 tokens/s、通信、峰值显存、恢复一致性；吞吐提升不等于 loss 改善
下游确认固定评测与后训练协议，比同等 loss 的候选及其成本领域/长文本/代码等分项；预训练平均 loss 不能代替任务验收

IsoFLOP 怎么做：给定一个 \(C\)，对多个 \(N\) 分配 \(D=C/(\kappa N)\)，比较训练终点损失，得到该预算下的最佳规模；在多个预算重复。长 cosine 训练的早期 checkpoint 尚未完成衰减，不能直接充当短预算训练的最优终点。Chinchilla §2 特别讨论了这一偏差。

超参数如何迁移：学习率、初始化与参数化要一起定义；不能把小模型的最优 LR 原样套给任意大模型。跨规模先验证更新与激活尺度；更换 AdamW/Muon、dense/MoE 或数据混合后，应重新检查拟合。详细更新规则见优化器参数，batch 的统计分母见全局 batch 账本。

μP / μTransfer：迁移的是参数化后的配方

Tensor Programs V研究在最大更新参数化（μP）下，把小模型调出的超参数迁移到更宽模型。初始化时独立随机项的和常按 \(\sqrt n\) 增长，训练后相关更新的贡献却可能按 \(n\) 增长；只让初始化方差稳定，并不保证更新后的激活稳定。

因此要同时定义哪些轴随宽度变化、初始化尺度、输出层缩放和逐参数组学习率。例如官方 mup实现对具有两个宽度轴的隐藏矩阵，在Adam下使用下式；它不是所有参数共享的缩放规则。

\[ m=\frac{\mathrm{fan\_in}}{\mathrm{base\_fan\_in}}, \qquad \eta_{\rm hidden}=\frac{\eta_{\rm base}}m. \]

\(m\) 是相对基准模型的输入宽度倍数，\(\eta_{\rm base}\) 是搜索的基础学习率，\(\eta_{\rm hidden}\) 是这一类隐藏矩阵实际使用的学习率；embedding、readout及固定维度参数须按完整参数化另行处理。宽度扩大4倍、基础LR为0.004时，该隐藏矩阵使用0.001；这只是规则算例，不是推荐训练值。

  1. 定义base / delta shapes：标明随规模变化的轴；官方基础用法保持深度不变。
  2. 做coordinate check：在几个宽度、几个更新步上检查每层激活坐标的平均绝对值，排查随宽度爆炸或消失。
  3. 小宽度搜索，留出大宽度确认：保持分组LR相对比例，检查最终loss；激活检查通过不等于迁移收益已经验证。

边界：μP不是Muon，前者是参数化方法，后者是更新规则。换深度、专家结构、优化器、tokenizer或数据分布，不能直接沿用这一个式子。完整Tensor Programs证明在原论文；本节提供关键机制、实现接口与可检查条件。

WSD：让训练时长的实验复用稳定阶段

MiniCPM与官方模型沙盒报告 §2.4采用Warmup–Stable–Decay：先升温，维持稳定学习率，再从指定checkpoint分支退火。较长预算的主干继续稳定训练，较短预算的分支完成自己的衰减，避免把未退火中途点与已退火终点混比。

\(t\) 为optimizer更新步，\(W\) 为warmup结束步，\(S\) 为稳定阶段结束步，\(H\) 为衰减持续步数；\(0<W<S\)，\(\eta_{\max}\) 为峰值LR，\(f:[0,1]\to[0,1]\) 为选定的非增衰减函数且 \(f(0)=1\)。记无单位的学习率倍率为 \(u(t)\)，实际学习率为 \(\eta(t)=\eta_{\max}u(t)\)：

\[ u(t)= \begin{cases} t/W,&0\le t<W,\\ 1,&W\le t<S,\\ f((t-S)/H),&S\le t\le S+H \end{cases} \]

MiniCPM沙盒在0.036B模型的相关实验中比较约2.5%和10%的退火长度，前者不足、后者达到或超过其cosine对照；10%是该实验观察，不是通用最优值。分支退火也消耗训练量，共享主干只能减少重复实验，不能把所有分支当作零成本checkpoint。若退火时同时引入高质量数据，须分别消融schedule和数据变化。

三个面试追问：token翻倍、20倍规则、部署成本
  • 固定 N，D 翻倍，loss 减半吗？不。只有拟合的数据项变成 \(2^{-\beta}BD^{-\beta}\)，模型项和下限不变。
  • 为什么工业小模型可能训练远超20N？需要考虑长期推理负载、内存与延迟约束；训练算力最优不等于生命周期成本最优。
  • MoE、长上下文、RL 能直接套这个式子吗？不能。总参数、激活参数、attention、路由和 rollout 成本需分开建账，再验证适用的经验关系。

长上下文与 late pretraining：课程和数据一起变

把上下文窗口调大只改变可容纳长度；要学会检索、跨文件依赖和多轮状态，仍需要相应数据。更长序列也改变 attention 成本、有效 batch 和位置分布。Qwen3 的三段预训练、GLM-5 的长度课程与 Olmo 的 Longmino 都展示了逐阶段组织。[12] [3] [4]

公开方案可核对做法不能据此假定
Qwen3通用预训练 → 强化知识与推理的数据阶段 → 长上下文阶段所有团队都在同一位置设置一个独立的 Midtraining checkpoint
GLM-532K / 128K / 200K，分别训练 1T / 500B / 50B token160B issue–PR 唯一数据池就是该阶段的全部训练量
Olmo 3Dolmino 能力准备；Longmino 的 7B 用 50B、32B 用 100B 训练 token50B 是所有模型的统一长上下文预算
DeepSeek-V4公开上下文从 4K 扩展到 1M 的训练安排仅修改推理 max length 就等价于该训练过程
  • 长数据不足：名义窗口扩大，真实长依赖仍可能失败。
  • 长样本过多：可能挤压短任务与原能力；改变有效batch与计算量。
  • 验收：短/长分桶、位置敏感检索、跨文件执行与能力回归同时看。

训练系统保证可继续、可比较

相关原论文 / 官方资料：ZeRO；FSDP；Megatron parallelism；PyTorch FSDP API；DeepSpeed official docs。

数据并行扩大 batch，张量 / 流水线并行拆分模型，序列或上下文并行分担长序列；ZeRO / FSDP 管理参数、梯度和优化器状态。如何组合取决于模型、序列和通信瓶颈，现有分布式指南提供实现入口。

可恢复训练需要权重之外的优化器状态、学习率调度、随机数、数据分片游标及 global step。若改变 tokenizer，token ID、embedding 与已学分布的兼容问题必须处理；常见 CPT 使用原 tokenizer，而不是在继续训练时随意重新分词。

  tokenizer/                 # vocab, special tokens, normalization

恢复用 checkpoint 与对外推理权重可以分开保存，但必须能追溯到同一训练状态。构建模型卡时应明确 checkpoint 的阶段和是否经过后训练，避免把 Instruct 权重的结果当成 Base 的自然先验。

什么时候进入 CPT 或后训练

  • 知识、结构或长依赖不足：评估领域CPT与相应数据。
  • 已有知识但工具协议不稳：先做可执行示范SFT。
  • 协议稳定但决策、探索或恢复不足：评估RL及反馈质量。

阶段可以分支；是否增加投入由同下游和同预算对照决定。
