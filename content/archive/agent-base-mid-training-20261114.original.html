Agent Base Model 的 Mid-training

公开工业配方、受控实验与 Harbor 验证方案

公开的 coding-agent 配方支持“混合 CPT → Trace SFT”。 更准确地说，mid-training 本身就可以包含 trace，并在这些样本上使用与 SFT 相同的 assistant-only loss。阶段之间真正变化的是数据配方、训练预算，以及要得到的 checkpoint。

工业配方实验证据前沿路线数据与伪代码Harbor 实验文献

一条可对照的工业配方

NVIDIA 在 2026 年 10 月公布的 Nemotron 3.5 研究给出了数据配比，并让带与不带 mid-training 的 checkpoint 接受相同 SFT。相对只披露成品分数的报告，这种对照能回答“加一段 mid-training，输出模型改善多少”。它仍然多用了一段训练算力。[1]

两种模型均使用 256K packed sequence，样本之间隔离注意力。Lightning 和 Super 的峰值学习率分别为 5e−5 和 1e−5，短 warmup 后保持恒定。论文也保留了各自的 multi-token prediction 辅助头。对轨迹只监督 assistant 回合，包括工具调用。PR 和日志也有各自的去噪或目标筛选规则，因此整段训练可以理解为按数据类型定义目标的混合语言模型训练。[1]

哪些选择有受控证据

最直接的结论来自同一轨迹配方的 mask 对照。模型仍然读取工具观察，并用它来预测后续动作，观察本身无需成为生成目标。这个改动在该设置下改善了结果。长日志占用的目标 token、观察的不可预测性以及目标权重如何变化，仍需用额外对照区分。

用相同 SFT 测 base checkpoint 能直接评估这一阶段对最终模型的贡献。NVIDIA 观察到 LoCoDiff、仓库或轨迹的预测损失等代理指标对最终排序的预测不够稳定。论文的主要比较每个设置仅报告一次训练，且未与等总算力的更长预训练或 SFT 比较。Terminal-Bench 的 1 点变化尤其需要重复验证。[1]

Qwen3-Coder-Next [2]Qwen3-Next base 继续在自然代码、仓库、PR、合成 QA、多框架轨迹及少量指令上训练。万亿级输入，其中仓库约 600B。上下文 262,144，使用 next-token 预测、FIM、best-fit packing 和重复片段遮蔽。随后做验证轨迹 SFT。展示成熟工业链路。公开报告未给完整数据配比或逐角色 loss 规则。同一 scaffold 内的数据量收益与跨 scaffold 的有限迁移有直接实验。
GLM-5 [3]32K、128K、200K 三阶段分别 1T、500B、50B token。过滤后的 issue–PR 池约 160B 唯一 token。展示自然软件工程数据和上下文课程可以同时进入 late pretraining。数据池规模与训练 token 量口径不同。
Olmo 3 [4]Dolmino 从约 2.2T pool 采样 100B 训练 token，包含数学、科学、代码、指令及推理。Longmino 另用约 50B 训练 token，后训练用 Dolci。通用 base 路线，适合参考公开语料、checkpoint 和训练阶段的组织方式。
MidTool [5]20.3B token，网页、代码、PDF 桶含基于原文的合成样本，另有 9% 原生 agent 轨迹。4B 和 8B base 接相同 SFT，有可选 RL 对照。4B 的 BFCLv3 39.73 → 50.25，τ²-Bench pass@1 8.54 → 12.23。单独加入原生轨迹的消融有时退化，支持比较数据组合与任务迁移。
PRISM [6]跨多种 3B–24B 模型，主要在约 27B token、8K 上比较数学、代码、科学和通用数据组合。Granite-3.3-8B 的综合通用分数大致保持，HellaSwag 单项下降约 5 点。保留能力需要分项报告。
SPT 与 Function-Aware FIM [7] [8]SPT 在多文件技能包上继续做 causal LM，保留说明与引用文件的关系。Function-Aware FIM 从仓库中抽取函数级补全任务。可以用结构化文档和代码构造更贴近实际依赖的训练信号。两者的公开结果对应特定数据和后训练设置。

这些工作有三条共同的设计线索。把工程语料组织为跨文件、跨提交或跨回合的上下文。用少量与实际工作流接近的数据补齐工具协议和行动分布。用固定的下游训练检查增量。通用模型还要并行控制知识、数学和代码回归。这里比较的是截至报告日期、公开资料中与问题直接相关的配方，成品榜单无法反推某团队的 mid-training 目标或配比。

Harbor 如何验证这笔训练预算

以未见任务的真实 verifier 成功率为主指标。先固定一份 Trace SFT，并从同一个 base 建立下面四组。B、C、D 对齐 CPT 输入 token、上下文长度分布、训练步数和算力，C 与 D 使用同一套自然工程数据来源。构建 D 时，从 C 中移出一部分工程数据，用等量的轨迹 token 补足。

实验组训练回答的问题
A直接做固定 Trace SFT最小业务基线
B通用 CPT → 固定 Trace SFT额外继续训练本身带来多少变化
C通用回放 + 领域文档、仓库、变更与日志 CPT → 同 SFTC−B 衡量领域数据配方相对通用数据的增量
DC 的配方中置换部分 token 为 assistant-only 轨迹 → 同 SFTD−C 衡量将轨迹提前混入的增量

A 与 D 是固定 SFT 的增量对比。如果要作预算决策，再加一组把额外算力用在更充分的 SFT，并报告 GPU 小时。记录每组训练的 checkpoint、数据哈希、模板、种子及截断率。优先使用按任务族、仓库与环境划分的留出集，隔离同源任务、解法和近重复轨迹。训练轨迹可含真实失败观察与后续有效修复，整条失败且无验证结果的轨迹不作为模仿正例。

所有组固定评测脚手架、模型生成预算与环境镜像，并用配对任务的置信区间报告差值。另报跨脚手架、长任务、错误恢复、基础代码与指令跟随、推理 token 和墙钟时间。每次 rollout 保留任务 ID、模型和环境版本、原始 reward、verifier 输出与产物索引。环境失败单列并记录分母，按相同规则重跑缺失项。

评审决策。 算力只够验证一个增量时，若要判断 mid-training 是否值得投入，先比较直接 SFT 与混合 CPT 后的同一 SFT。若已有稳定的领域 CPT，优先比较 C 与 D。扩大训练的门槛由评审提前约定，包括最小成功率提升、通用能力容许回退和 GPU 小时上限。

本节是待验证的实验设计。本文没有运行 Harbor 训练或评测，公开论文结果不能直接换算成 Harbor 的预期收益。
