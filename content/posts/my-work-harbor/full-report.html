核心方法
  • 角色接力：把 GEO/SRA 研究转成题面、环境、参考路径、判分器和校准证据。
  • 分开治理：题面保留科学选择空间；冻结校准约束合法路径和错误路径。
  • 分开验收：生产入库、判分正确、独立难度与科学质量分别举证。历史规模和费用集中见后文。

1. 研究问题：怎样规模化构造科学任务

科学任务构造需要同时完成数据核验、问题定义、参考计算和独立判分。规模化的难点是使每道题都有这些证据，同时保留方法选择空间。

术语约定：GEO（Gene Expression Omnibus）是 NCBI 的公开组学数据仓库，每条研究以 GSE 编号标识；docker/podman 是当前本地隔离执行 solver / verifier 的沙箱口径；Terminal-Bench 3（简称 TB3）是 Harbor 框架的标准化评测任务格式；Codex CLI 是以非交互模式调用 LLM 的命令行工具。
  • 题面过细：直接给出归一化、检验和阈值，主要考实现指定配方。
  • 判分过窄：隐藏唯一答案会误拒其他合法分析。
  • 判分过松：字段可拼凑、固定答案可通过时，测到的可能是投机能力。

2. 核心机制：信息隔离与工件交接

每个角色只接收完成当前判断所需的材料，把结论写成下一角色能核验的工件。信息隔离依赖实际工作区和权限：solver 看公开数据与题面，隐藏 tests、solution 和 authoring；在 prompt 中要求“不看答案”不足以完成隔离。

explorer 发现候选，auditor 核查数据与科学问题，author 构造任务，gates 检查包契约，solver 留下盲测轨迹，judger 根据轨迹与判分证据裁决。角色名称只是接口；可复放工件和可验证隔离才是机制。

3. 方法与判分：先冻结，再盲测

方法总览

GEO-Harbor-Bench 将 NCBI GEO 公开研究转化为 Terminal-Bench 3 风格任务。核心原则只有三条：角色隔离、静态门禁前置、跨模型评审。

图 1. GEO-Harbor-Bench 生产链路：候选筛选 → 深度审计 → 造题/门禁/盲测/评审 → Harbor package 自包含验收 → done 入库。

评审 rubric 体系：每个站位的判分维度

质量控制采用分层裁决：越靠近昂贵盲测，判据越严格；每个站位只回答一个可被证据支撑的问题。

题面早评：盲测之前的质量前闸

早评是盲测前的低成本质量前闸：只判断题面是否值得进入昂贵沙箱，不看 solution/tests。

  • 只评三维：difficult、well_specified、outcome_verified；没有盲测轨迹的维度不强判。
  • 硬阻塞：well_specified 不达标直接打回，因为这通常意味着“题面开放空间大于校准覆盖”。
  • 防泄题：评审工作区白名单构建，solution/ 与 tests/ 不进入；反馈也不能写具体方法、参数、阈值。
  • 价值：把规格不清、配方泄漏、难度造假挡在盲测前，不烧沙箱、不消耗盲测预算。

盲测失败的八类归因路由

盲测失败后不直接“重写一遍”，而是先进入 trial_analysis 路由。八类归因对应不同修复动作：

  • task_specification：题面不清或目标不闭合 → 修题并重新冻结。
  • oracle_discoverability：公开证据不足或入口难找 → 补证据/改任务，不强行放行。
  • verifier_correctness：判分器误拒合法解 → 修 verifier 与校准包络。
  • reward_hacking：存在投机路径 → 加固反作弊与输出契约。
  • difficulty_crux：失败来自真实科学难点 → 可作为有效难度保留。
  • near_miss：接近正确但落在边界 → 扩展多路径校准或收紧容差说明。
  • low_timeout：资源/时间预算不足 → 调整预算，不当作科学失败。
  • refusals：题面触发拒答或误解 → 改写题面表达。

实证：247 个 proposal 评审记录显示，difficult 的 uncertain 可弱接受；well_specified 的 uncertain 是硬阻塞（0/8 通过），通常意味着题面自由度超过校准覆盖。

关键设计决策

为什么拆成多个角色？ 为了物理隔离信息：solver 看不到 tests/solution，评审员也不能从 oracle 反推答案。

为什么需要双代码路径？ 这一步不是 NOP，也不是把 solution 当作盲测结果；solver 只提交输出，verifier 在 docker/podman 中对照冻结 oracle / accepted paths 复算，solution 只用于参考路径自检，避免同源 bug 造成“永远满分”的假题。

为什么前置门禁重要？ 零 token 门禁在沙箱前拦截结构错误、配方泄漏和依赖缺失，避免无效盲测。

开放方法为何仍能确定性判分

把合法解法登记成完整输出路径，并对每条路径的排名、方向、统计量与元数据做联合检查。令第 k 条路径的接受集合为 \(\mathcal A_k\)，最终接受集合是这些集合的并：

\[ \begin{aligned} \mathcal A&=\bigcup_{k=1}^{K}\mathcal A_k,\\ V(y)&=\mathbf 1\{y\in\mathcal A\}. \end{aligned} \]

教学例：路径 A 允许输出 (1,10)，路径 B 允许 (2,20)。逐字段“取任一路径都可”会误收 (1,20)；完整路径校验要求两个字段来自同一合法计算。实际科学任务还需校准数值容差、并列、缺失和排序边界。

  • 正控制：合法路径真实执行并通过，覆盖题面允许的选择。
  • 负控制：known-wrong、固定答案和混拼输出执行后必须被拒绝。
  • 冻结：题面、fixture、verifier、校准结果绑定同一包指纹；修改后重新校准。

这是一套可检验的准入条件。有限校准无法证明已经覆盖所有合法解或所有投机路径。

交付产物：task package 目录结构

最终交付的是自包含 Harbor task package。核心原则很简单：考生只看题面和公开数据；答案、判分器和出题证据随包保存，但在盲测时物理隔离。

Harbor package 根目录：tasks/<slug>/author/task_package/

tasks/<slug>/author/task_package/
├── instruction.md                 # solver 可见：题面与输出要求
├── task.toml                      # 机器可读契约、资源预算、artifact 声明
├── environment/
│   └── data/                      # solver 可见：公开 fixture 与 checksum
├── solution/                      # 盲测物理排除：oracle 参考解
├── tests/                         # 盲测物理排除：verifier、test.sh、独立数据副本
└── authoring/
    ├── calibration-summary.json   # 合法路径 / known-wrong / 校准边界
    └── provenance/                # GEO 来源、深审结论、数据转换记录

导出时丢弃逐轮草稿、盲测留档和临时探针；保留题面、运行环境、判分器、参考解法与 authoring 证据链。这样上游既能直接运行任务，也能复核“这道题为什么成立”。

4. CRISPR-MHC-II-Screen：从计数矩阵到任务包

这个 case 主要展示流水线最终合成出的 Harbor 任务长什么样：它不是论文复述，也不是固定代码配方，而是把真实 GEO 研究转化为可盲测、可判分、可复核的任务包。

合成后的题面核心

任务背景：
GSE304150 是一个围绕 MHC-II 表达调控的 CRISPR 全基因组筛选实验。
输入数据为 sgRNA read count matrix，覆盖 A375 与 WM115+IFNγ 两个细胞设置，
并区分 MHC-II high / low 细胞群体。

输入：
- raw count matrix：77,441 guides × 10 samples
- sgRNA-to-gene annotation
- sample metadata：cell line、MHC-II 分选状态、replicate

目标：
从原始计数出发，识别促进或抑制 MHC-II 表达的候选调控基因。
solver 可以自行选择合理的归一化、效应量估计和统计检验方法，
但必须输出可复算的 gene-level 结果。

输出：
- gene-level ranking
- effect direction / effect size
- significance or support evidence
- short interpretation of top hits

判分重点：
结果是否能稳定恢复 MHC-II 通路核心信号，并满足输出 schema 与复算约束。

为什么这个任务成立

  • 真实科学问题：从 CRISPR screen 中识别 MHC-II 表达调控因子，问题本身具有清晰生物学意义。
  • 输入可复算：任务基于 sgRNA 级原始计数矩阵，而不是只给最终 hit list。
  • 开放但可判：不指定唯一统计配方，保留 solver 的方法选择空间；同时用 gene-level ranking、效应方向和显著性证据约束输出。
  • 生物学 sanity check：HLA-DRA、RFXAP、RFXANK、RFX5、CIITA、CD74 等 MHC-II 相关信号应在结果中得到合理支持。

合成过程只保留关键转折

候选审计确认原始计数矩阵可得；早版题面因方法写得过细被门禁拦截；修订版只保留科学目标、输入输出契约和判分边界，并登记多条合法解法路径。最终任务通过盲测、verifier 复算与评审闭环，形成自包含 Harbor package。

7. 单位成功成本：真实账本与假设估算

真实单位成功成本以全部尝试资源除以最终成功数，包含重试、失败、校准和 adjudication。若每次尝试成本固定为 c、成功概率为 p，且每次独立同分布，则尝试次数的期望为 1/p：

\[ \begin{aligned} C_{\rm measured}&=\frac{\sum_i c_i}{N_{\rm done}},\\ \mathbb E[C_{\rm geometric}]&=\frac{c}{p}. \end{aligned} \]

教学例：每次 100 tokens，p 从 0.1 变为 0.7，则单位成功期望从 1000 降到 142.86 tokens，下降约 85.7%。这只说明固定成本假设下的算术关系；实际每次成本和任务难度可能一起变化。

8. 面试复述与追问

  • 怎样做到开放且可判？冻结多条完整合法路径，联合校验输出，执行正负控制；追问：容差为何合理？
  • 为什么多角色？明确工件职责和可见材料；追问：怎样证明 solver 实际无法读 tests？
  • 失败后先做什么？按八类归因路由，区分规格、verifier、科学难点和资源故障；追问：修包后哪些证据失效？
  • 如何报告规模与效率？库存、匹配批次任务率和尝试率分别统计；追问：pending 和 retry 是否进入分母？
  • Refinement 已证明有效吗？当前冻结记录的难度 drop=0、accepted child=0；需要规格与独立难度门共同通过，不能用产线库存代替。
