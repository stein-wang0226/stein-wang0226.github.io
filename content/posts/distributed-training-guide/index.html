选框架前，先确认要切分什么

本页用于实现与排查。状态容量、ZeRO推导、batch与普通/专家进程组在训练主题主讲；这里保留 API、配置和故障定位。源码/API片段是参考，未在本机执行 GPU 集群训练。

候选适合的现有工作流要核对的约束
DeepSpeedHF/自定义训练，需要ZeRO或offloadJSON和Trainer参数、引擎初始化、保存与恢复
FSDPPyTorch/Accelerate，层级分片版本、wrap/shard粒度、optimizer构造、state dict
Megatron Core/LM模型已适配多维并行、MoE/长序列逻辑矩阵、拓扑、数据格式、权重转换与kernel
  • 不按参数规模划硬界：长度、训练状态、激活、互联和更新范围共同决定容量。
  • 没有通用最快排名：原稿未附条件的tokens/s、GB和“FP8固定提升50%”从当前教学稿移除，原件仍可查。
  • 分片和卸载不同：前者减少副本，后者把状态移到CPU/NVMe并引入传输。

DeepSpeed：配置、引擎与 Trainer 保持一致

stage1分片optimizer，stage2再分梯度，stage3再分参数。容量节省取决于分片数、dtype、master与临时buffer，不是固定33%/50%。“auto”是集成层解析约定，自定义原生启动需要提供具体参数或对应处理。

FSDP1 原生包裹片段：先设置设备，再构造 optimizer 
import os
from functools import partial
import torch
import torch.distributed as dist
from torch.distributed.fsdp import (
    FullyShardedDataParallel as FSDP, MixedPrecision, ShardingStrategy)
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
from transformers.models.llama.modeling_llama import LlamaDecoderLayer

local_rank = int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local_rank)
dist.init_process_group("nccl")
# model须已构造；本例为Llama层。不同模型改匹配层类。
policy = partial(transformer_auto_wrap_policy,
                 transformer_layer_cls={LlamaDecoderLayer})
model = FSDP(
    model, device_id=local_rank, auto_wrap_policy=policy,
    sharding_strategy=ShardingStrategy.FULL_SHARD,
    mixed_precision=MixedPrecision(param_dtype=torch.bfloat16,
                                  reduce_dtype=torch.bfloat16),
    use_orig_params=True, limit_all_gathers=True)
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)

这是API片段，数据/模型/恢复入口由实际程序提供。PEFT混合冻结参数与可训练参数须检查wrap约束；use_orig_params和编译兼容性按版本核对。

FSDP2不是“任何PyTorch2.4+都具有完全相同公共API”。model.layers、mesh、保存/恢复与compile应按实际版本和模型核对。Accelerator.prepare负责包裹时，不再重复手工FSDP包裹同一模块。

Megatron：逻辑模型、进程组与配置一起核对

  • TP：层内矩阵/head切分，需要频繁collective；优先高速互联域，跨节点并非数学上禁止。
  • PP：层分段与microbatch调度；气泡、激活传输和阶段负载要一起看。
  • SP/CP：SP在TP域减少部分逐token激活副本；CP切同一长序列，需要历史交换，不能简单当DP。
  • EP/ETP：专家分配/单专家切分，普通层和专家层的DP可不同。
  • distributed optimizer：减少更新状态冗余；不能笼统当作FSDP FULL_SHARD。

转换与高级 kernel：核对模型支持而不是只改路径
  • HF↔Megatron：转换器loader/saver、QKV布局、GQA、RoPE与head共享需匹配；转换后检查单步logits或可比输出，不能默认任意模型都兼容。
  • 低精度：Transformer Engine的FP8格式、scale与硬件支持按版本固定；GEMM dtype不代表optimizer state也为FP8。
  • 调度：interleaved PP、grouped GEMM与通信重叠需对应kernel及拓扑；看整步时间，不重复相加重叠阶段。
  • 组合：已有适配的MCore/FSDP/DeepSpeed组合需按实现验证；不要让两个引擎各管理同一参数的更新状态。

诊断顺序：看内存对象和关键路径

症状先确认调整与验证
optimizer初始化/更新OOMm/v、master、foreach临时buffer状态分片/压缩/offload；比持久容量与峰值

每rank利用率不均PP阶段/专家负载、数据等待分段/路由/loader；检查空闲与collective时间
通信阻塞设备映射、网卡、rendezvous、collective次序NCCL日志与各rank堆栈；分辨网络和程序不同步
NaN/跳步样本、mask分母、Norm/QK、归约/状态精度冻结起点重放异常批；BF16不保证免NaN
恢复后曲线改变optimizer/scheduler/RNG/sampler/global step保存完整状态，检查数据位置和world size兼容

诊断命令可使用 NCCL_DEBUG=INFO；NCCL_SOCKET_IFNAME 必须是当前主机实际互联接口。降低学习率、增warmup或开offload都有对应对象与代价，不能不看证据套固定值。

按需完整示例：HF + LoRA + DeepSpeed

单个 train_lora.py：教学数据、标签mask、加载与保存

需要可访问的模型、Transformers、PEFT、datasets、DeepSpeed和BF16 GPU，使用上面的ds_config.json。版本依赖需固定后小规模验证；本机未执行该GPU示例。教学数据很小，不代表有效能力训练。

import torch
from datasets import Dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, Trainer, TrainingArguments
from peft import LoraConfig, get_peft_model

name = "meta-llama/Llama-2-7b-hf"
tokenizer = AutoTokenizer.from_pretrained(name)
tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "right"
args = TrainingArguments(
    output_dir="./lora_output", per_device_train_batch_size=1,
    gradient_accumulation_steps=4, max_steps=4, learning_rate=2e-4,
    bf16=True, deepspeed="ds_config.json",
    gradient_checkpointing=True,
    gradient_checkpointing_kwargs={"use_reentrant": False},
    save_strategy="no", report_to="none")
# TrainingArguments先构造，便于HF接入ZeRO配置；此例使用stage2。
model = AutoModelForCausalLM.from_pretrained(
    name, torch_dtype=torch.bfloat16, use_cache=False)
model = get_peft_model(model, LoraConfig(
    task_type="CAUSAL_LM", r=16, lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05, bias="none"))
model.print_trainable_parameters()  # 不预设全模型固定比例

texts = ["A CSV keeps rows with nonempty values.",
         "The string zero is a valid value."] * 8
def encode(batch):
    return tokenizer(batch["text"], truncation=True,
                     padding="max_length", max_length=64)
data = Dataset.from_dict({"text": texts}).map(encode, batched=True,
                                            remove_columns=["text"])
def collate(rows):
    ids = torch.tensor([r["input_ids"] for r in rows])
    mask = torch.tensor([r["attention_mask"] for r in rows])
    labels = ids.clone()
    labels[mask == 0] = -100  # 按attention mask，保留真实EOS监督
    return {"input_ids": ids, "attention_mask": mask, "labels": labels}

trainer = Trainer(model=model, args=args, train_dataset=data,
                  data_collator=collate)
trainer.train()
trainer.save_model("./lora_checkpoint")
if trainer.is_world_process_zero():
    tokenizer.save_pretrained("./lora_checkpoint")

此例监督全部非padding token；真实assistant-only SFT须用模板生成准确目标mask。adapter保存仍需关联底座与tokenizer版本；只存adapter不等于保存完整续训checkpoint。

为什么“按相同batch比较最快框架”仍不够？输入/目标token、长度、重算、精度、并行、optimizer和通信都影响关键路径，且必须比较质量与恢复。

分片能把峰值精确除以D吗？只能对被分片的逻辑状态按理想均匀推算；聚合、激活和未分片对象不一定缩小。
