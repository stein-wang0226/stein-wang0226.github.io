02 / SYSTEM问题形式化与系统结构

x/q 为蛋白输入/问题，t 为动作步，aₜ/oₜ 为动作/真实观察，hₜ 为动作前历史；πθ 为参数 θ 定义的策略，∼ 表示按分布采样，点号表示所有候选动作。

输入是蛋白序列 x 与问题 q。策略根据历史输出工具调用或最终答案；真实环境返回 observation，加入历史后继续决策：

\[ \begin{aligned} h_t&=(x,q,a_1,o_1,\ldots,a_{t-1},o_{t-1})\\ a_t&\sim\pi_\theta(\cdot\mid h_t) \end{aligned} \]
原训练与评测图保留。真实工具观察是环境资产；冻结评测使用独立 scorer。
  • 动作：有效调用或终止答案；需记录参数、实际执行与失败。
  • 观察：数据库/预测器返回；程序、权重、数据库与接口版本共同固定。
  • 边界：训练 split 隔离不保证工具数据库没有测试序列或同源项。

来源：论文 §3；项目框架说明。

04 / SUPERVISED LEARNINGSFT：动作监督与 label 对齐

u 索引输出 token，yᵤ 是示范目标，c 为任务条件，y<u 为示范前缀，mᵤ∈{0,1} 为监督 mask；L_SFT 是有效位置 NLL 之和，若实现平均则另指定分母。

单步动作、观察到答案与完整多轮轨迹分别训练接口、证据转化和连续决策。系统、用户与工具观察作上下文；assistant 动作和最终答案进入监督。设 m 是监督 mask，c 是工具执行后已知的条件：

\[ L_{\rm SFT}=-\sum_u m_u\log\pi_\theta(y_u\mid c,y_{\lt u}) \]

mask 不等于梯度隔离。 工具 token 的目标 loss 为零，但其上下文表示仍可通过注意力影响 assistant loss。next-token shift 使位置 u 的 logits 预测 u+1 的 label；mask 应与 shifted label 对齐，不能按输入角色边界错位一格。

05 / REINFORCEMENT LEARNING从期望回报到逐步策略梯度

τ 是完整轨迹，pθ(τ) 为其概率，R(τ) 为终评回报，J 为其期望；∇ 对 θ 求梯度，E 按策略轨迹平均。Gₜ,ₖ/rₜ,ₖ 为候选 k 在步 t 的未来回报/即时奖励，H 为总动作步数，γ 为折扣。actor 式的 u 为动作内 token，m 为策略 mask，A 为固定优势，Z 为聚合分母，β 为 reference KL 系数。

每个问题由当前模型采样 K=4 条轨迹，真实工具执行产生观察和局部 reward。环境转移不依赖 θ 时，轨迹密度对 θ 的导数只来自策略输出；对期望回报用对数导数展开：

\[ \begin{aligned} J(\theta)&=\sum_\tau p_\theta(\tau)R(\tau)\\ \nabla J&=\mathbb E[R(\tau)\nabla\log p_\theta(\tau)]\\ \nabla\log p_\theta(\tau) &=\sum_t\nabla\log\pi_\theta(a_t\mid h_t) \end{aligned} \]

动作前已经发生的奖励不会受当前动作改变，条件期望下可以从该动作的信用项删去。剩下当前位置及未来的 return；主配方 γ=λ=1，无学习 critic：

\[ \begin{aligned} G_{t,k}&=r_{t,k}+\gamma G_{t+1,k}\\ G_{H+1,k}&=0\\ G_{t,k}&=\sum_{s=t}^H r_{s,k} \quad(\gamma=1) \end{aligned} \]
γ=1 示意，数值例与四臂结果见本页第 12 节。机制图不单独证明因果效果。

动作可能有多个 token，其 log probability 是策略 token 的 log probability 之和。return 经配置变换后得到 token advantage A，mask m 排除工具/用户/padding，Z 是配置分母：

\[ \begin{aligned} L_{\rm pg}&=-\frac1Z\sum_{t,u}m_{t,u}A_{t,u} \log\pi_\theta(y_{t,u}\mid h_{t,u})\\ L_{\rm actor}&=L_{\rm pg} +\beta D_{\rm KL}(\pi_\theta\Vert\pi_{\rm ref}) \end{aligned} \]
  • Identity：return 层保留原值，后续仍 masked whitening 与优势 clip。
  • Step GRPO：本项目对 prompt 组逐步 return 作组相对变换，仍用 vanilla PG；不凭名称套用另一框架的 episode GRPO。
  • 两种 clip：优势 ±0.2 与 PPO 概率比 clip 控制不同对象；数值例里的 raw return 不是最终 advantage。

组合奖励：附着位置与无工具 guard

本段 A/B/Q/V/J 是奖励计算的中间分数，区别于上一段策略优势 A、目标 J 和状态价值 V；y/y* 为回答/参考答案，z 为完整 answer 标签指示，m 为完成工具数，|y| 为回答字符数。C_tool、R、E、P、F、J 的具体职责见下方定义与事件表；ℓ(y) 是长度门控。最终评测的 zᵢ 另表示答案匹配是否超过阈值。

z 表示完整 answer 标签，m 表示完成工具数，R/E/P 是有界推理标记、效率及结构兼容，J 是字符 Jaccard，F 是可选同轨迹 fidelity。先分项，再合成终止 reward：

\[ \begin{aligned} A&=\min(1,R_{\rm tok}(y,y^*)+0.15z)\\ B&=2A+C_{\rm tool}+0.5R+0.3E+0.5P\\ \ell(y)&=\min(1,|y|/200)\\ Q&=B-0.45\mathbf1\{m=0\}+F\\ V&=0.3\mathbf1\{|y|\ge50,\ m\ge1\}\\ r_{\rm answer}&=\ell(y)Q+0.5J+V \end{aligned} \]

0.45=2×0.15+0.5×0.30 抵消纯 schema 增量；它不保证无工具时总 reward 为零。训练覆盖项含格式 bonus；最终评价在提取答案后用 recall 严格大于 0.5，不能直接比较两者。

06 / TRAINING & INFERENCE代码、训练与工具框架

训练与推理

ProtAgent 负责蛋白任务、reward、工具、评测与配置；分布式训练由 ROLL 执行。论文 SFT 使用 Megatron；RL actor 使用 FSDP2，轨迹生成使用 vLLM。更新后需要将 actor 权重同步到推理侧，reference policy 提供 KL 约束。

环境与工具

registry 定义工具与后端，executor 处理输入和调用，native preflight 检查依赖。训练和论文评测需真实执行程序与数据库；启发式结果不能冒充论文 actual-tool 输出。

11 / INTERPRETATION理论解释与后续决策

episode return 把同一轨迹分数赋给所有动作；一条轨迹可能同时含有有用调用和重复调用。step return 保留位置与局部奖惩，使后发生的动作不继承之前的局部奖励，同时保留未来结果对先前动作的回传。这改善信号分辨率的解释与实验方向一致，但不是所有多轮任务都会提升的定理。

  • 注释 token overlap 不直接衡量生物学真值、工具证据蕴含或置信度校准。
  • 训练池同源审计不能保证 runtime 数据库对测试蛋白不可检索；SignalP 版本差异没有匹配验证。
  • grounded citation、结构化 ID 密度、工具路由与 fidelity 为行为诊断，不是完整错误类别标注。
  • 模型规模、数据分布与工具集合有限；更大范围结论需要跨 backbone、任务和数据源验证。
下一步决策：若目标是生物学可信度，应优先冻结预测，进行独立专家评审和证据蕴含标注；若目标是机制解释，应固定起点和预算，补充跨模型、跨工具及逐 reward 组件的匹配实验。两条路线回答不同问题。

12 / ALGORITHM DEEP DIVE算法选择：从假设、控制变量到代码路径

这一节把算法比较拆成两个正交问题：一条轨迹的奖励如何分配给不同步骤，以及同一 prompt 生成的多条轨迹如何变换数值尺度。论文采用已有的 Monte Carlo return 和 REINFORCE，其贡献是在蛋白工具环境中对这两个因素进行控制比较，而不是提出新的通用策略梯度估计器。

12.2a 用一条轨迹计算回报

下面是解释算法的人造算例，不是论文中的额外实验。假设三个步骤分别得到 +0.25、−0.30、+1.00，且 γ=1；逐步方法从末尾累加，episode 方法把总和赋给每个步骤。

步骤示例动作 / rₜStep return GₜEpisode return
1首次相关调用 / +0.250.25 − 0.30 + 1.00 = 0.950.95
2重复调用 / −0.30−0.30 + 1.00 = 0.700.95
3终止答案 / +1.001.000.95

例如第 2 步不会继承第 1 步已取得的局部奖励，但仍收到第 3 步后续结果。数值只是 return；进入梯度前还须经过配置指定的 normalization、mask、whitening 和 clipping，不能把表中的 0.70 直接称作最终 advantage。

12.3 为什么选 K=4、四步及分段重启

完整数值配方集中在第 10 节。K 控制同 prompt 采样数，H/响应长度控制交互预算，γ 控制跨步传播，β 约束 reference 偏移；三阶段继承权重但重置 optimizer 和 reference。论文选择值不等于逐项搜索出的最优值。

12.4 代码走读：轨迹 → return → response → token

compute_discounted_returns:
  group_by(traj_id) → 按 step 排序
  reversed: running = reward[t] + gamma * step_lambda * running
  step_rewards = running → 恢复原始样本顺序

step_reinforce:
  step_rewards → agentic_reward_norm(config) → response_level_rewards
  → token_level_rewards / response_mask → compute_reinforce_return
  → masked_whiten（配置启用时）→ advantage_clip

代码展品｜摘自补充包 agentic/utils.py 的处理顺序，展示结构而非完整调用栈。该函数同时支持 step_reinforce_lambda；论文主配方中的 step λ=1 才退化为普通折扣回报。

先按 traj_id 分组、按 step 排序，保证不会把不同轨迹的未来奖励串接；计算后恢复样本原序。step_reinforce 路由通过配置选择回报归一化，再进入 token 级 advantage、mask、whitening 和裁剪；因此同名参数必须连同调用位置阅读。该补充代码用于解释契约，并不单独证明某次远端 run 的每个配置值。
